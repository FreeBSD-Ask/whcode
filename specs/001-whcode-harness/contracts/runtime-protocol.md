# Contract: 可选运行时子进程协议

**Feature**: [spec.md](../spec.md) | **Date**: 2026-10-20

**来源**：任务书 §4.7、§4.7.1、§8.4、ADR-008、D-07/D-08/D-09。

## 1. 边界

- 运行时**不是**主进程依赖；以 provider 接口、能力清单、独立 payload 和子进程协议实现（§4.7）
- 所有脚本在受控子进程中执行；主进程不得直接嵌入不受信任脚本执行（ADR-008、§1.3）
- 未启用运行时不加载其动态库、不占端口、不注册可执行工具（FR-704）
- 关闭全部可选 runtime feature 时，主程序仍可运行（V-301）

## 2. Provider 接口语义（§8.4）

`name`、`capability`、`is_available`、`env_fingerprint`、`execute`、`terminate`；执行返回退出码、持续时间、资源观察值与输出引用。所有异步执行操作必须有取消语义；底层无法立即取消时必须说明取消请求何时生效。

## 3. 能力等级与命名边界（FR-702、§4.7.1）

| 能力 | 实现建议 | 必须声明的限制 |
|---|---|---|
| JavaScript | Boa 作为受限 ECMAScript 引擎后端 | 不得称为完整 Node.js；无 Node API / npm 兼容性时必须明确标注 |
| Node.js | 独立 Node.js 可执行文件或官方运行时 payload | 与主二进制分离；版本、平台、文件树、许可证信息可审计 |
| Python | 子进程 Worker，可对接经验证的 Python 解释器与 `libpython` | C 扩展兼容性取决于版本/ABI/平台/依赖包；不承诺普遍兼容 |
| 受限 Python | 可选 RustPython 等受限实现 | 明确不支持的标准库、扩展与系统调用；门禁不得当作完整 Python |
| Windows Git Bash | 独立 PortableGit payload | 安装体积随版本变化，不写死固定 MB 数；验证 Bash、coreutils、管道与重定向 |
| BSD Shell | 系统 `/bin/sh` 或用户指定 Shell provider | 与 Windows Git Bash 是不同能力，不得共用 `gitbash` 名称伪装等价 |

不得把"动态链接 `libpython`"等同于已交付完整 Python 环境；不得把 `deno_core` 等同于 Node.js 完整兼容层。运行时是否内置/默认携带/按需下载须在 P1 实现前形成独立 ADR（D-07）。

## 4. 执行协议与检查点（FR-705/706）

1. 执行前：校验参数与权限策略，提交执行意图与检查点
2. 启动：标记 `running`，记录环境指纹（runtime fingerprint）与工作目录策略
3. 运行中：受超时、输出上限、取消与可用的资源限制约束；默认继承最小化环境变量集合（§10.2）
4. 结束：记录输出摘要、退出码、持续时间、stdout/stderr 引用与副作用凭证
5. 结果登记：按脚本哈希、输入哈希、运行时指纹与工作目录策略记录；重复执行缓存仅用于纯函数或显式启用缓存的任务（FR-707）
6. 终止/超时/崩溃：记录终止原因、退出状态、stderr 尾部与执行状态（FR-409）；平台须按策略清理子进程树（Windows）或进程组（BSD）（§10.2）
7. 不确定性：无法判断是否完成时标记 `unknown`，要求核对、幂等重试或人工决策（FR-410）

## 5. payload 校验（FR-703）

独立分发时必须校验来源、版本、哈希与平台兼容性；错误、stderr、模型输出与工具返回均视为不可信数据。平台不具备可靠内存限制能力时必须报告"无法强制限制"，不得声称已实现（§10.2）。

## 6. 验证点

- V-301 默认构建：全部可选 feature 关闭时主程序可运行，差异按实际文件与 RSS 报告
- V-302—V-304：受限 JS / Python / Git Bash 各自固定测试集，超出能力返回结构化错误
- V-305：超时后子进程树清理，stderr 尾部保留，状态可恢复
- V-306：引用未启用运行时的任务在执行前被阻止
- V-307：在执行意图提交后、外部操作期间、结果登记后分别注入中断，不确定操作标记 `unknown`
