### User Story 1 - M0 平台可行性与基线冻结 (Priority: P1) 🎯 MVP

工程团队在 **Windows 11 amd64**（唯一验收目标，ADR-013）上，用锁定版本的工具链完成 Workspace 骨架、嵌入式单文件数据库（DuckDB，ADR-001）原生构建、TUI 最小闭环、事件写者原型与基线性能测量；产出 ADR-001—ADR-010 的批准记录，冻结平台矩阵与候选性能预算（或经 ADR 修订）。FreeBSD/NetBSD/OpenBSD/DragonFly BSD 全部**延后**（ADR-013），不进入本轮验收结论。

**Why this priority**: 任务书 §12.1 规定进入大规模实现前必须先完成 M0；DuckDB 原生依赖在硬目标失败时需要 Go/No-Go 决策，是全部后续工作的前提（ADR-010、R-01）。平台范围已收敛为单一目标，避免因无环境平台长期无法收口（ADR-013）。

**Independent Test**: 在 Windows 11 amd64 执行构建、数据库冒烟（创建/事务写读/关闭重启/迁移）、TUI 启动-输入-resize-退出-异常恢复、写者原型幂等与批次测试，并运行固定数据集基准脚本产出基线报告；全部留有证据记录。

**Acceptance Scenarios**:

1. **Given** 锁定工具链版本与 Workspace 骨架，**When** 在 Windows 11 amd64 执行构建与依赖记录脚本，**Then** 产出一份含 Rust/DuckDB/编译器/OS 四类版本的依赖记录（已取得：`artifacts/deps-windows.txt`）（V-001）
2. **Given** 空数据库路径，**When** 依次执行创建数据库、事务写读、关闭重启、迁移冒烟，**Then** Windows 11 amd64 通过并留存日志（V-002）
3. **Given** 最小 TUI 原型，**When** 执行启动、键盘输入、终端 resize、退出与异常恢复测试，**Then** Windows 11 amd64 通过并留存证据（V-003；启动项已自动取证，交互四项待人工）
4. **Given** 事件写者原型与固定数据集，**When** 注入重复幂等键、批次提交与写入错误，**Then** 幂等键去重、关键事件确认与错误传播行为符合协议；基线性能报告按统一测量纪律产出，候选指标被冻结或经 ADR 修订（V-005、V-006）

**覆盖需求**：§9 平台矩阵（按 ADR-013 收敛）、NFR-201—222（冻结对象）、ADR-001—014、ADR-013、V-001—V-007、D-01/D-02/D-03/D-04/D-06/D-12/D-14

### User Story 2 - M1 存储与事件基座 (Priority: P1)

系统提供版本化 schema 与可重复迁移、单写者服务（有界队列、幂等键、批量提交、写入确认）、稳定游标分页查询、备份/归档/清理/压缩工具与数据库监控。任何前端尚未存在，能力经 CUI 之外的存储测试与原型命令验证。

**Why this priority**: 会话、事件、检查点、SDD 产物全部依赖持久化与事件游标基座（ADR-001/002）；任务书 M1 是 M2—M4 的硬前置。

**Independent Test**: 对已迁移数据库执行断连补拉、崩溃重启一致性、幂等重复提交、清理/压缩与活跃会话保护测试（V-103—V-108 中存储相关项），全部可在无 UI 的测试夹具上运行。

**Acceptance Scenarios**:

1. **Given** 客户端断连后依据持久化游标重连，**When** 补拉事件，**Then** 关键事件完整无缺失，任何内容采样或脱敏均有可查询标记（V-103）
2. **Given** 已确认提交的事务，**When** 终止进程并重启，**Then** 状态与关键事件保持一致（V-104）
3. **Given** 同一幂等键重复提交，**When** 写者服务接收，**Then** 返回既有结果或确定的冲突，不重复创建状态转换（V-106）
4. **Given** 清理或 compact 操作，**When** 执行，**Then** 预览、确认、审计与活跃会话保护生效；compact 副本校验成功后方能切换文件，报告记录数据库/WAL/已用与可用块统计（V-107、FR-509、FR-510）

**覆盖需求**：FR-501—FR-510、§7.3 事务与写入队列、§7.4 备份导出迁移、D-05/D-10

### User Story 3 - M2 会话与任务应用服务 (Priority: P1)

统一应用服务（whcode-app 层）提供会话与任务命令（创建/恢复/重命名/归档/删除/列出、任务列表/详情/重试/中止）、权限检查、状态快照与统一错误语义；任务状态常量在代码、数据库与 CUI JSON Schema 中使用同一套枚举。

**Why this priority**: 三端共享业务能力的前提（ADR-003、G-06）；没有应用服务层，后续 LLM、SDD 与界面都无挂载点。

**Independent Test**: 以测试夹具直接调用应用命令（不经 UI）：10 万事件会话切换仅返回元数据与有界尾部且游标稳定；任务概览返回阶段分布/完成度/阻塞/活跃任务；错误码与权限拒绝语义一致（V-101、V-102 相关项）。

**Acceptance Scenarios**:

1. **Given** 10 万事件的会话，**When** 切换会话，**Then** 仅加载元数据、概览、上下文指针和有限活跃尾部，分页游标无重复无遗漏（V-101、FR-102、FR-106）
2. **Given** 会话命令集合，**When** 执行创建/恢复/重命名/归档/删除/列出，**Then** 权限检查、阶段门禁与错误语义统一，结果为版本化状态快照（FR-101、FR-103、FR-104）
3. **Given** 1 万任务与固定阶段分布的数据集，**When** 查询任务概览，**Then** 报告 p50/p95/p99 且满足 M0 冻结后的性能预算（V-102）

**覆盖需求**：FR-101—FR-106、§3.1 状态常量、§8.2 状态快照

### User Story 4 - M3 LLM 调用与上下文管理 (Priority: P1)

LLM Provider 抽象提供流式响应、请求取消、重试、模型计量与供应商错误归一化；统一事件类型与四级追踪（off/metadata/redacted/full）；上下文按预算注入并返回游标与截断原因。

**Why this priority**: Harness 的核心职责（G-03、G-04）；事件链路与追踪级别是三端可观察性与安全默认值的共同基础（FR-201—FR-208、D-05）。

**Independent Test**: 用桩 Provider 固定响应速率与 chunk 大小：断连重连按游标补拉；redacted 级别下疑似秘密字段脱敏；上下文注入返回 items+next_cursor+consumed_budget+truncated_reason；流式积压时关键状态转换不丢失（V-101、V-103、V-104 相关项）。

**Acceptance Scenarios**:

1. **Given** 追踪级别 redacted，**When** 记录一次流式调用，**Then** 疑似秘密字段脱敏、链路按 request_id/session_id/task_id/tool_call_id 串联、token/延迟/成本入账且估算值带估算标记（FR-203、FR-204、FR-207）
2. **Given** 上下文预算，**When** 注入历史，**Then** 有界读取并返回截断原因，用户可查看预算、装入来源与截断原因（FR-105、FR-108）
3. **Given** 流式事件积压，**When** 系统合并 UI 更新或降低展示频率，**Then** 关键状态转换不静默丢失且留下可查询标记（FR-206、FR-208）

**覆盖需求**：FR-107、FR-201—FR-208、FR-616、§4.2 事件可靠性分级

### User Story 5 - M4 SDD 门禁状态机 (Priority: P1)

可配置、可版本化的 SDD 工作流（Constitution → Specify → Plan → Tasks → Implement → Converge）作为应用层状态机运行：产物解析为版本化结构、Clarify/Analyze 门禁、双向追溯、Converge 验收核对、解析纠偏重试、人工强制放行审计；每次模型调用显式注入当前阶段角色。

**Why this priority**: G-05 要求门禁由程序实施（门禁失败时应用服务拒绝阶段转换，而非仅追加提示词）；这是产品区别于普通聊天 Harness 的核心能力。

**Independent Test**: 构造违规产物夹具：未解决高优先级澄清阻止 Plan；Analyze 检出遗漏需求、孤儿任务、无效引用、循环依赖与覆盖不足；连续两次纠偏失败进入 blocked；force-advance 留完整审计；三端显示同一阶段状态（V-201—V-207）。

**Acceptance Scenarios**:

1. **Given** 含未解决高优先级澄清项的 spec，**When** 请求进入 Plan 阶段，**Then** 转换被应用服务拒绝（FR-307、V-202）
2. **Given** spec/plan/tasks 三类产物，**When** 执行 Analyze，**Then** 检出遗漏需求、孤儿任务、无效引用、循环依赖和未覆盖验收项，未通过阻止 Implement（FR-306、V-203）
3. **Given** 模型产物解析连续两次纠偏失败，**When** 第三次仍失败，**Then** 任务标记 blocked 并保留错误与原始产物（FR-309、V-204）
4. **Given** 人工 `force-advance --reason`，**When** 越过门禁，**Then** 审计记录含 actor、reason、跳过的门禁、相关产物版本与时间戳（FR-312、V-206）
5. **Given** Converge 对任务验收条件核对，**When** 存在 fail/not_tested 项，**Then** 生成差异报告，任务不得静默变为完成（FR-310、FR-311、V-205）

**覆盖需求**：FR-301—FR-314、§4.3.3 产物规范

### User Story 6 - M5 TUI 与 CUI (Priority: P2)

TUI（会话树、任务、上下文、事件、Spec 状态、diff 预览）与 CUI（稳定命令树、明确退出码、版本化 JSON 输出）接入同一应用服务；三端命令校验、权限、门禁与业务结果一致；共享功能能力矩阵。

**Why this priority**: 本地主交互形态（G-06、ADR-003/009）；在应用服务就绪后交付，风险已被 M0 原型缓解（V-003）。

**Independent Test**: 同一组业务命令分别在 TUI 与 CUI 执行，最终状态、权限与错误码一致（V-109 部分）；CUI JSON 输出带 schema_version，错误对象含 code/message/retryable/details；CUI 为脚本提供非交互路径。

**Acceptance Scenarios**:

1. **Given** 同一工作区，**When** TUI 与 CUI 执行同一命令，**Then** 最终状态、权限判定与错误码一致（FR-604、V-109）
2. **Given** CUI 任意命令加 `--json`，**When** 执行，**Then** 输出含 schema_version，错误对象含 code/message/retryable/details（FR-602、§8.1）
3. **Given** 任一端产生更改，**When** 另一端在线，**Then** 更改可见；断线端可从持久化游标补齐（FR-605）
4. **Given** 登记表把某命令在某端登记为预留或排除，**When** 该端调用该命令，**Then** 返回结构化 `not_supported`（CUI 退出码 55）而非 404 或静默成功，且未登记的命令被对等门禁拦截（预留编号 620／621；V-112）

**覆盖需求**：FR-601、FR-602、FR-604、FR-605、FR-610、FR-612、FR-613、FR-614、FR-615；前端对等增补（预留编号 619—625，正式登记由收口任务统一更新）与 V-112

### User Story 7 - M6 Web UI (Priority: P2)

独立原生 Web UI（非 TUI 的 PTY 镜像）经 HTTP API / WebSocket 访问同一应用服务；前端状态由同一事件流驱动；默认仅监听 127.0.0.1，对外监听必须显式启用身份验证、Origin 检查与安全配置。

**Why this priority**: 第三交互端，复用 M5 已建立的命令契约与事件流（ADR-004、FR-603、FR-609）；安全默认值是发布硬门槛（V-110）。

**Independent Test**: 浏览器完成会话/任务/历史/追踪/SDD/清理/运行时业务操作；断线重连补拉事件；默认绑定仅回环地址；未启用认证的对外监听被拒绝启动（V-109、V-110）。

**Acceptance Scenarios**:

1. **Given** 默认配置，**When** 启动 Web 服务，**Then** 仅监听 `127.0.0.1`；改为对外监听且未显式启用认证/Origin 检查时启动失败（FR-606、V-110）
2. **Given** 浏览器会话，**When** 执行与 TUI/CUI 相同的业务命令，**Then** 权限、门禁与最终状态一致，且无需 PTY 模拟（FR-609、ADR-004、V-109）
3. **Given** WebSocket 连接，**When** 校验连接，**Then** 通过来源校验、身份认证、授权检查与消息大小限制，token 不经 URL query 传递（§10.2）
4. **Given** Web 请求一条登记为预留的路径（如未接线的 SDD 门禁命令），**When** 处理请求，**Then** 返回 HTTP 501 与同码 JSON 信封而非 404；上下文与 diff 读取与 TUI／GUI 同源且有界（预留编号 620／622；V-112）

**覆盖需求**：FR-603、FR-605、FR-606、FR-609、FR-610；前端对等增补（预留编号 619—625，正式登记由收口任务统一更新）与 V-112

### User Story 8 - M7 BSD SSH 接入 (Priority: P2)

SSH 服务端作为独立传输入口在 FreeBSD、NetBSD 上提供公钥认证、会话隔离、终端尺寸变化与安全退出；OpenBSD 与 DragonFly BSD 不再作为原生安装目标，改由 WHCode 内置 SSH 客户端控制（FR-611、ADR-011）。默认仅开放受限的 WHCode 交互入口，不授予任意系统 Shell。

**Why this priority**: BSD 平台的核心接入形态（G-01、ADR-005）；M0 仅取得客户端侧原型，V-004 服务端证据尚未取得，此处交付完整能力。

**Independent Test**: 在 FreeBSD/NetBSD 目标设备上分别执行服务端公钥认证、resize、断连重连、会话隔离与权限边界测试；在 Windows 与四类 BSD 上执行内置 SSH 客户端连通性、受限命令、超时与输出上限测试；任一平台无法完成时记录明确阻塞原因（不以单一平台代替，R-02）。

**Acceptance Scenarios**:

1. **Given** FreeBSD/NetBSD 上的 SSH 服务端，**When** 使用公钥认证连接，**Then** 认证成功、会话隔离、终端尺寸变化与安全退出均正常（FR-607、V-004）
2. **Given** SSH 默认配置，**When** 用户请求系统 Shell，**Then** 默认拒绝；任意 Shell 仅作为显式独立权限授予（FR-608、§10.2）
3. **Given** SSH 会话执行业务命令，**When** 与其他端对比，**Then** 复用同一应用服务，不存在每会话各自打开数据库写入（ADR-005）
4. **Given** OpenBSD 或 DragonFly BSD 目标，**When** 通过内置 SSH 客户端连接并执行受限命令，**Then** 仅公钥认证生效、命令白名单或受限子系统拦截越权命令、超时与输出上限触发并留记录、外部操作按 ADR-007 登记（FR-611、ADR-011）

**覆盖需求**：FR-607、FR-608、FR-611、ADR-005、ADR-011、R-02

### User Story 9 - M8 可选执行运行时 (Priority: P3)

Runtime Provider 接口（探测、能力声明、版本指纹、执行、取消、结果归一化）与子进程 worker；能力等级 Full/Restricted/ShellOnly；JavaScript（受限引擎或独立 Node payload）、Python（子进程 worker）、Shell 与 Windows Git Bash payload 按独立 payload 交付；未启用运行时不影响核心启动。

**Why this priority**: 运行时全部为 P1 能力且不得阻塞首个可用版本（D-12、FR-704、G-07）；Boa/RustPython 不得被表述为完整 Node.js/Python（R-08、D-08、D-09）。

**Independent Test**: 关闭全部可选运行时 feature 后主程序仍可运行（V-301）；各运行时通过固定兼容性测试集并声明具体限制；能力不足时返回结构化错误；超时清理子进程树并保留 stderr 尾部；引用未启用运行时的任务在执行前被阻止（V-301—V-306）。

**Acceptance Scenarios**:

1. **Given** 所有可选 runtime feature 关闭的默认构建，**When** 启动主程序，**Then** 核心功能可用，差异按实际文件与 RSS 报告（FR-704、V-301）
2. **Given** 任务引用未启用的运行时，**When** Analyze 或执行前检查，**Then** 阻止执行并说明原因与替代建议（FR-710、V-306）
3. **Given** 脚本执行超时，**When** 终止，**Then** 子进程及子进程树按平台策略清理，stderr 尾部保留且状态可恢复（FR-705、V-305）
4. **Given** 在执行意图提交后、外部操作期间与结果登记后分别注入中断，**When** 恢复，**Then** 不确定操作标记为 unknown 并要求核对、幂等重试或人工决策（FR-407、FR-410、V-307）

**覆盖需求**：FR-701—FR-710、§4.7.1 兼容边界、D-07/D-08/D-09

### User Story 10 - M9 优化与发布 (Priority: P3)

按 M0 冻结的性能预算做优化（候选指标达标或经 ADR 修订）、5.5 小时稳定性测试（ADR-033）、数据库压缩与恢复验证、跨平台发布包、部署与安全文档、ADR/风险台账/兼容矩阵/已知限制交付。

**Why this priority**: 优化与发布收尾依赖全部功能里程碑；任务书禁止以未验证的未来能力声称已完成（R-12）。

**Independent Test**: 运行 5.5 小时压力测试（ADR-033）并记录 RSS/CPU/线程/WAL/队列深度/提交与查询延迟等时间序列；包含慢客户端、请求失败、断网、磁盘不足、写入失败、重启、终止子进程、迁移中断情形；所有强制验收通过，剩余偏差形成公开限制说明（§11.5、§12.2）。

**Acceptance Scenarios**:

1. **Given** 常规功能测试已通过，**When** 运行至少 5.5 小时稳定性测试（ADR-033），**Then** 产出规定指标的时间序列报告，并区分产品缺陷、环境限制与测试工具偏差（§11.5）
2. **Given** M0 冻结的性能预算，**When** 发布前测量，**Then** 达标或形成修订预算的 ADR；测量纪律记录 OS/硬件/编译类型/工具链/数据库版本/数据规模/采样窗口（NFR-201—210、V-006）
3. **Given** 发布清单，**When** 交付，**Then** 包含源码仓库与各 crate、锁定工具链与五平台构建脚本和 CI 配置、schema 与灾难恢复说明、CUI/TUI/Web 文档、事件 schema 与脱敏规则、SDD 夹具、运行时能力清单与许可证清单、基准脚本与稳定性报告、ADR 与已知限制（§12.2）

**覆盖需求**：NFR-101—107、NFR-201—222、§11.5、§12.2、D-11

### Edge Cases

- 外部工具在崩溃前已执行副作用但结果尚未登记：恢复时不得宣称操作从未发生，必须标记 `unknown` 并要求核对、幂等重试或人工决策（FR-407、FR-410、ADR-007、R-07）
- 事件队列饱和：关键事件必须背压、失败返回或触发安全停止，不得静默丢弃；展示快照可合并丢弃（ADR-006、§4.2 分级）
- 大段 prompt/response/工具输出：有界 payload、引用化、分块写入；超预算截断并记录标记，不得静默删除（R-05）
- 慢客户端：单个慢 WebSocket/SSH 客户端不得阻塞其他会话的状态广播（§6.3）
- 重复幂等键：返回既有结果或确定冲突，不重复创建状态转换（§7.3）
- 子进程终止：Windows 处理子进程树，BSD 处理进程组、信号与残留（§10.2、FR-409）
- 运行时缺失/不兼容：返回结构化错误，不静默跳过任务（FR-708）
- 模型产物解析失败：报告无法解析段落、重复 ID、未识别字段，保留原文，禁止静默丢弃（FR-309、R-06）
- 清理后物理空间未缩小：输出数据库/WAL/已用块/可用块统计并解释 `VACUUM` 语义限制，不承诺释放文件空间（FR-510、R-10）
- 迁移中断：迁移失败时数据库不得被误标记为新版本（§7.4）
- LLM 请求失败/断网/磁盘不足/写入失败：纳入 5.5 小时稳定性测试情形（§11.5）

### Functional Requirements

- **FR-103**: 系统必须随时生成工作区与当前会话的任务总览（阶段分布、完成度、阻塞任务、活跃任务）（P0）
- **FR-104**: 系统必须按需返回当前任务详情、依赖、步骤、产物引用、最近事件和失败原因（P0）
- **FR-105**: LLM 上下文注入必须按预算读取历史，禁止将整个历史集合一次性载入内存（P0）

**LLM 调用透明性（§4.2）**

- **FR-201**: 统一事件类型：请求开始、流式增量、请求完成/失败、上下文状态、进度变化、工具调用开始/结束、运行时终止与持久化异常（P0）
- **FR-202**: 实时事件可广播；断线重连后可依据持久化游标补拉事件（P0）
- **FR-203**: 提供追踪级别 off/metadata/redacted/full；默认不把秘密凭据写入日志（P0）
- **FR-204**: 通过 request_id、session_id、task_id、tool_call_id 串联一次调用的完整链路（P0）
- **FR-205**: CUI 支持 JSON/JSONL 事件查询与导出，并在导出中注明脱敏策略（P0）
- **FR-206**: 流式事件积压时可合并 UI 更新或降低展示 chunk 频率；不得静默丢失关键状态转换（P0）
- **FR-207**: 记录 token 数、模型参数、延迟和成本；估算值标记为估算，供应商计量值另行保存（P1）
- **FR-208**: 追踪记录提供完整性标记（缺失 chunk、脱敏、降采样、持久化失败）（P1）

**Spec Kit / SDD 工作流（§4.3）**

- **FR-304**: 每条需求有稳定 ID；每条任务有稳定 ID、验收条件、依赖和需求引用（P0）
- **FR-305**: Plan 关键决策可追溯至需求；任务可追溯至需求和计划决策（P0）
- **FR-306**: Analyze 检出遗漏需求、孤儿任务、无效引用、循环依赖和覆盖不足（P0）
- **FR-307**: 高优先级未解决澄清项阻止 Plan；引用或覆盖检查失败阻止 Implement（P0）

- **FR-309**: 解析失败可自动纠偏重试，默认最多 2 次；仍失败标记 blocked 并保留错误与原始产物（P0）
- **FR-310**: Converge 对每条验收条件记录 pass/fail/not_tested/not_applicable 并附证据引用（P0）
- **FR-311**: 失败或未测试的验收条件不得使任务静默变为完成；必须产生差异报告或阻塞原因（P0）
- **FR-312**: 人工强制放行必须记录 actor、reason、跳过的门禁、相关产物版本和时间戳（P0）
- **FR-313**: 每次模型调用显式注入当前阶段角色和允许操作；角色由状态机提供（P0）
- **FR-314**: TUI、CUI、Web 显示同一份阶段状态、门禁结果和产物版本（P0）

**长程任务、检查点与恢复（§4.4）**

- **FR-401**: 任务步骤支持持久化进度、依赖关系、重试计数和恢复状态（P0）
- **FR-402**: 检查点以增量状态差分和引用为主，避免每步复制完整历史（P0）
- **FR-403**: 任务状态变化、关键事件和检查点引用必须在同一数据库事务内提交（P0）
- **FR-404**: 恢复时加载检查点引用的元数据、产物与上下文游标；完整历史按需读取（P0）
- **FR-405**: 定时、按步骤和危险操作前可触发检查点；间隔与保留数量可配置（P0）
- **FR-406**: 子任务支持依赖图；并行调度为 P1，须在状态和写入一致性测试通过后实现（P1）
- **FR-407**: 提供轮询兜底；轮询只读快照，不独占或阻塞写者服务（P0）
- **FR-408**: 单个可重试任务失败不得使整个会话丢失；不可恢复错误向上传播（P0）
- **FR-409**: 子进程被终止/超时/主进程崩溃时，记录终止原因、退出状态、stderr 尾部和执行状态（P0）
- **FR-410**: 恢复协议必须处理外部副作用不确定的情况；不能判断时标记 unknown 并要求核对、幂等重试或人工决策（P0）

**数据库与清理（§4.5）**

- **FR-501**: 提供版本化 schema 与可重复执行的迁移机制（P0）
- **FR-502**: 提供有界写入队列、幂等键、批量提交与写入结果确认（P0）
- **FR-503**: 批量提交按行数上限或时间上限先到者触发；初始基线 500 行或 50 ms，须由 M0/M1 基准校准（P0）
- **FR-504**: 历史查询使用稳定排序键和游标分页，不以大 OFFSET 作为默认长历史分页路径（P0）

- **FR-506**: 高频概览使用显式维护的预聚合表；更新延迟和一致性语义必须可测（P0）
- **FR-507**: 提供数据库统计、查询计划分析、WAL 状态和写者队列监控（P0）
- **FR-508**: 提供会话归档、按时间清理、TTL 和导出/导入能力（P0）
- **FR-509**: 清理操作必须有预览、确认、审计和活跃会话保护机制（P0）
- **FR-510**: 数据库维护记录清理前后文件大小、WAL、已用块与可用块；不承诺 VACUUM 一定释放文件空间（P0）

**TUI、CUI、Web 与 SSH（§4.6）**

- **FR-601**: TUI 包含会话、任务、上下文、事件、Spec 状态和 diff 预览（P0）
- **FR-602**: CUI 提供稳定命令、明确退出码和版本化 JSON 输出（P0）
- **FR-603**: Web 通过 HTTP API / WebSocket 访问同一应用服务，前端状态由同一事件流驱动（P0）
- **FR-604**: 三端命令校验、权限、阶段门禁和业务结果必须一致（P0）
- **FR-605**: 任一端产生的更改须在其他在线端可见；断线端可从持久化游标补齐事件（P0）
- **FR-606**: Web 默认监听 127.0.0.1；对外监听必须显式启用身份验证、Origin 检查和安全配置（P0）。自本变更起 `serve --web` 默认使用内置 TLS 证书；关闭 TLS 必须显式 `--tls off` 或入站档位 `off`；TLS 不替代认证（2026-10-25 修订：见 FR-626／FR-627 与 ADR-040）
- **FR-607**: SSH 服务端在 FreeBSD/NetBSD 上提供公钥认证、会话隔离、终端尺寸变化和安全退出；OpenBSD/DragonFly BSD 由内置 SSH 客户端控制（见 FR-611）（P0）
- **FR-608**: SSH 默认提供受限的 WHCode 交互入口，不默认授予任意系统 Shell（P0）
- **FR-609**: Web UI 提供会话、任务、历史、追踪、SDD、清理与运行时的业务操作；不经 PTY 模拟 TUI（P0）
- **FR-610**: 三端共用功能能力矩阵；新能力的 API、CLI 行为、权限与测试必须同 PR 定义（P0）
- **FR-611**: 系统必须提供内置 SSH 客户端，连接 OpenBSD 与 DragonFly BSD 目标、执行受限命令并取回输出；单次执行必须有超时与输出上限，并按 ADR-007 的“意图—执行—登记”流程登记外部操作（P1；理由：它服务于 ADR-011 的平台承诺修订，不阻塞首个可用版本）
  - 安全边界：仅公钥认证；受限入口（命令白名单或受限子系统）；不继承本地敏感环境；输出有界并在超限时标记截断；超时即终止并记录原因；每次外部执行前登记意图、结束后登记结果；默认不提供任意 Shell

**显示适配与资源纪律（2026-10-21 新增需求，交付归属 M5/M6）**

- **FR-612**: TUI 必须提供三套渲染主题：A 屏（AMOLED/OLED）夜间模式使用**纯黑背景**（RGB 0,0,0——仅纯黑可完全关断 OLED 像素，深灰仍耗电）；墨水屏日间模式使用**纯白背景黑字**（白底黑字残影最小）；墨水屏夜间模式使用**纯黑背景白字**。主题经配置选择，禁止硬编码单一配色（P1）
  - 依据：OLED 纯黑像素功耗趋近 0、深灰（如 RGB 20,20,20）省电效果大减；e-ink 黑→白转换残影比白→黑更重，白底黑字最优
- **FR-613**: 渲染路径必须以降低内存与 CPU 占用为第一原则：TUI 只允许事件驱动与脏标记重绘，禁止周期性全量重绘；Web 前端（M6）必须尊重系统 `prefers-reduced-motion` 并提供动效总开关，能由 GPU 合成承担的效果（transform/opacity）交给 GPU，不能安全交给 GPU 的动效一律默认关闭（P1）
  - 终端应用的绘制由终端模拟器完成，WHCode 不直接调用 GPU；本条对 TUI 的约束是“减少无效重绘”，对 Web 的约束是“CSS 合成层友好 + 动效可关”
- **FR-614**: 资源占用不得随会话数量线性叠加固定开销：会话创建禁止预分配固定大缓冲；连接、读取缓冲与渲染状态按需创建并复用；空闲会话可被可配置的驻留策略卸载（仅保留元数据与游标，与 FR-102 一致）；卸载与唤醒行为必须可查询且不丢失已确认事件。安全前提：卸载策略不得绕过权限检查，缓冲复用不得跨会话泄漏内容（P1）
- **FR-615**: 面向用户的界面文本（CUI 输出、TUI 文案、错误消息、帮助）必须同时支持简体中文与英语，默认随系统区域自动选择，可用配置强制覆盖；必须为其他语言预留 **gettext PO 文件**翻译接口（`i18n/` 资源目录 + 运行时加载 + zh-CN→en 回退链）；文本渲染层不得假设从左到右书写，为阿拉伯语等 RTL 语言预留双向文本处理接口（P1；依据：GNU gettext 已原生支持 Rust 字符串提取与格式校验）
  - 交付边界：M2 起新增用户可见文本必须经文本层而非硬编码字面量；PO 接口在 M5 完整交付
- **FR-616**: 工作进度必须全链路可查询、不遮掩：现有事件体系（FR-201）扩展传输层进度事件——网络连接建立/断开、重连尝试、按连接的字节收发计数、请求往返时延、断连原因码——均作为可查询事件或指标暴露（CUI JSON 可导出）；任何“后台进行中”的状态不得只以完成度百分比呈现而隐藏阶段明细（P1；交付归属：M3 随 LLM Provider、M7 随 SSH）
- **FR-617**: GUI 在窗口最小化或不可见时不得执行任何 GUI 工作：暂停绘制、动画与前端轮询，恢复时先取状态快照再**单次全量重绘**（禁止逐帧追赶）；不可见判定以 Page Visibility API 为主、焦点事件为辅，恢复须去抖 ≥250 ms。图形稳定性要求：不假设 GPU 可用（先探测、失败降级）、动画只用 `transform`/`opacity`、`will-change` 按需且用后撤销、渲染上下文挂起时释放并在恢复时重建、`prefers-reduced-motion` 与动效总开关生效；TUI 侧需在窗口最小化时跳过绘制但继续记账关键事件（P1；交付归属 M5/M6；设计见 `docs/guides/gui-suspend.md`）
- **FR-618**: Web 前端必须为**无框架、无打包器**的极简实现（ADR-014）：服务端直出 HTML + 原生 ES modules，文本优先、无自动播放与装饰性媒体、无 WebGL/Canvas 动画；主题仅经 CSS 变量切换（纯黑/纯白）；硬性预算：首屏 JS ≤ 50 KB（gzip）、CSS ≤ 20 KB（gzip）、单页 DOM 目标 ≤ 2 000 节点、无第三方字体；无 JavaScript 时只读视图必须可用；预算与依赖审计进 CI，超预算即失败（P1；交付归属 M6，设计见 `docs/adr/ADR-014-minimal-frontend.md`）

**内置 TLS 证书库与 Web 证书设置（2026-10-25 新增需求，交付归属 M3/M6 与装配根 M10）**

- **FR-626**: 内置 TLS 证书库与出站、入站信任装配（P0；[安全]；交付归属 M3 出站信任、M6 入站与装配根）: 系统必须提供工作区级证书库 `<workspace>/.whcode/certs/`（`settings.json`、`ca-builtin.pem`、`ca-extra.pem`、`ca-builtin.json` 种子清单、`server-cert.pem`、`server-key.pem`），全部为公开格式的明文 PEM／JSON，同目录临时文件加原子替换写入，份数与字节有上限。出站信任档位为 `builtin`（默认，可编辑的内置 Mozilla 根证书副本；首次使用由 `assets/certs/ca-bundle.pem` 种入；未修改时随程序版本保真刷新并记录新旧 SHA-256，被修改时保留并标记“已修改、内置版本较新”）或 `system`（操作系统证书库）；`ca-extra.pem` 在两种档位下都追加生效；系统库读取成功但证书数为 0 时必须返回可操作错误，不得静默回落内置库；任何档位都不得关闭证书链与主机名校验，不存在 `disable_verification` 或等价“跳过校验”开关，Dangerous 配置无法经设置页写入。入站 `serve --web` 档位为 `builtin`（默认，首次运行按工作区生成 ECDSA P-256 自签证书，SAN 含 `localhost`、`127.0.0.1`、`::1`、本机名与绑定 IP 字面量，有效期 397 天）／`external`（用户提供的 PEM 证书链与未加密私钥）／`off`（明文 HTTP，ADR-023 现状）；优先级为命令行 `--tls` > 工作区设置 > 默认 `builtin`；默认档位证书无法生成或加载时必须拒绝启动并给出可操作错误（列出 `--tls off` 与文件路径），不得静默降级明文；入站变更在重启 `serve --web` 后生效。TLS 不得放宽 ADR-023 的地址边界、token 认证与 Origin 检查；启用 TLS 时 Origin 允许集使用 `https` scheme
  - 判据：Given 新建工作区首次构造出站信任，Then 自动创建 `settings.json` 与 `ca-builtin.pem`，档位为 `builtin`，状态报告给出内置证书份数、SHA-256 与来源版本；Given 向 `ca-extra.pem` 写入企业代理 CA 并分别以 `builtin`、`system` 档位连接本地 TLS 测试服务，Then 两次握手均成功且生效根证书总数为对应基线与追加份数之和；Given 系统库可读但证书数为 0，Then 出站信任构造返回可操作错误且不使用内置库；Given 提交超限、含私钥块、空内容或不可解析的 PEM，Then 返回具体原因且原文件字节不变；Given 修改 `ca-builtin.pem` 后执行重置，Then 恢复为内置资产内容、SHA-256 与种子清单一致并清除“已修改”标记；Given 空工作区执行 `serve --web`，Then 首次生成自签证书并输出 `https://` 地址与证书 SHA-256；Given 两个独立工作区各自首次启动，Then 证书与私钥不同且不存在随包分发的固定私钥；Given 传入 `--tls off` 或把入站档位设为 `off`，Then 以明文 HTTP 启动、输出 `http://` 且该选择不被静默改回；Given 上传证书与私钥不匹配、私钥带口令、证书链不可解析或超限，Then 保存被拒绝且原配置与运行中的 TLS 状态不变；Given 绑定 RFC1918 地址且未提供 `--token-file`，Then 与引入 TLS 前一样拒绝启动；Given 内置证书距到期不足 30 天或已过期，Then 状态与启动输出给出警告，已过期时自动重新生成并记录新旧指纹，外部证书不自动替换；Given 客户端分片发送 ClientHello 或长时间不完成握手，Then 握手在既有 5 秒空闲上限内被终止，每连接缓冲有上限且不新增常驻线程
  - 证据：`crates/whcode-domain/src/tls.rs`；`crates/whcode-app/src/cert.rs`；`crates/whcode-llm/src/http/tls.rs`（`http` feature）；`crates/whcode-web/src/tls.rs`；`crates/whcode-bin/src/serve.rs`；`assets/certs/ca-bundle.pem` 与 `assets/certs/SOURCES.md`
  - 依据：ADR-040（新增）、ADR-023 修订记录、ADR-031 修订记录、ADR-022（Origin scheme）、FR-606 修订；NFR-218／NFR-219（安全措施须有威胁模型、证据、代价与失效条件）
- **FR-627**: Web 证书设置页与受控证书 API（P1；[架构]／[安全]；交付归属 M6）: Web 端必须提供 `/settings/certs` 设置页（服务端直出 + 原生 ESM，纳入 FR-618 预算与简体中文／英语词条）与 `/api/certs/*` JSON API（状态、档位、CA 读取／写入／重置、服务端证书上传／重新生成／下载、连通性校验）。所有读写经既有认证、Origin 与能力判定（能力为 `settings.cert.read`／`settings.cert.write`）；成功变更写一条 `tls_config_change` 审计（含目标、动作、档位、证书份数与 SHA-256，不含 PEM 正文与私钥），审计写入失败时文件回滚并返回错误；降档操作（入站档位设为 `off`、写入空的 `ca-builtin.pem`、上传外部服务端私钥）必须显式确认；私钥只进不出——任何响应、日志、事件与审计正文都不得包含私钥，下载接口只返回公开证书 PEM 与元数据；请求体在解析前按上限拒绝（CA 512 KiB、证书链 64 KiB、私钥 16 KiB、JSON 总长 640 KiB），连接不被无界占用；入站变更返回 `restart_required = true`；两项能力在四端登记表各有状态：Web 为实现，CUI／TUI 按理由码 `web_settings_only` 排除，GUI 按 `gui_read_only_v1`／`six_view_scope` 排除，被排除端调用返回 `not_supported`；连通性校验以当前出站信任在 2 秒上限内完成握手，不发送任何凭据

- **FR-712**: GUI 必须满足资源预算：1200×800、六视图、无动画的空闲态 **RSS ≤ 96 MB、私有内存 ≤ 80 MB、线程 ≤ 24、句柄 ≤ 256、CPU ≤ 0.2% 单核**；**默认不创建 GPU 上下文**（采用软件光栅，或在探测失败时降级而非崩溃）；CJK 字体必须按需或子集加载，不得整份常驻（P1）

- **FR-713**: GUI 必须实现主题精确色值：与 FR-612 相同的三套（`#000000`／`#E6E6E6`／`#FFFFFF`）外加 `terminal-green`（纯黑 `#000000` 底 + 荧光绿 `#00FF00` 字，2026-10-24 用户新增；黑色为 OLED 兼容纯黑，可完全关断像素），共四套，不得依赖系统深色模式；文字抗锯齿允许存在，但**无彩色中间灰**（R=G=B 且亮度 32—223）像素占比必须可量化并记录，目标 ≤ 5%（单色前景三套按亮度口径的历史记录与真灰口径数值一致；`terminal-green` 为彩色前景，以截图只出现精确两色与抗锯齿过渡为主判据，亮度口径仅记录不设达标线）；主题切换不得要求重启（P1）
- **FR-714**: GUI 在窗口最小化或不可见时必须停止绘制、动画与定时轮询；恢复时先取状态快照再**单次全量重绘**（禁止逐帧追赶），恢复去抖 ≥250 ms；不得使用周期定时器驱动重绘（P1）
  - 与 FR-617 同口径；本条是 FR-617 在原生 GUI 上的可判定化
- **FR-715**: GUI 必须提供**可复现的自动化证据入口**：窗口截图、按键注入、空闲/交互资源采样（RSS／CPU／线程／句柄）三件套，结果按 `artifacts/gui-*/` 落盘并可被门禁脚本重跑；不得以人工目视作为唯一证据（P1）
- **FR-716**: 界面字体必须**完全本地化**并可区分四类文本：英语比例、简体中文比例、英语等宽、简体中文等宽各用一份不同的开源字体（OFL 类可再分发许可）；完整字体文件与许可原文入库，GUI 运行时只加载子集，子集外字符由系统字体栈回退并标注覆盖范围；不得依赖网络下载或目标系统是否安装该字体（P1）
  - 依据：用户新增任务（2026-10-23）与 ADR-028；与 FR-712“CJK 不得整份常驻”一致
- **FR-717**: TUI 的字体必须可声明与可撤销：提供命令把内置字体安装到用户级字体目录并检测当前终端是否声明使用；安装/卸载必须显式、可逆、不静默改写用户终端配置；不得声称程序能强制终端更换字体（P1）
  - 依据：终端字形由终端模拟器控制；ADR-028 第 5 条

**横切约束（任务书 §4.2/§4.4/§4.5/§4.6，验收时与 FR 同级对待）**

- 事件可靠性三级：关键事件不得静默丢弃（饱和时背压/失败/安全停止）；内容事件按追踪级别控制并留可查询标记；展示快照可合并丢弃。“实时广播 + 数据库写入”不得被描述为自动原子双写
- 检查点时序：外部工具执行前先提交 prepared 意图与检查点；启动后标记 running；结束后记录输出摘要、退出码与副作用凭证，再于同一事务登记结果
- 空间回收：CHECKPOINT 同步 WAL 并可能部分回收；`db compact` 采用“复制—校验—切换—备份—回滚”流程
- 三端对等：相同业务能力、权限检查、状态迁移、错误语义和可审计性一致；不要求视觉/交互一致
- 上下文加载器契约：返回 items + next_cursor + consumed_budget + truncated_reason

### 非功能需求（任务书 §5，摘要）

- **NFR-101—107**（可移植性与可维护性）：无未经封装的平台专有假设（差异集中于平台层）；平台依赖以 feature 隔离；持久化结构有 schema 版本、迁移与降级/备份说明；崩溃恢复不静默丢失已确认关键事件；核心逻辑/数据库写入/UI 渲染/子进程运行时隔离；指标可经 CUI JSON 导出；所有不兼容行为与能力限制可查询
- **NFR-201—210**（内存与 CPU 候选预算，M0 后冻结或修订）：

| 编号 | 候选指标 | 初始目标 |
|---|---|---|
| NFR-201 | 主进程空载 RSS | ≤ 35 MB |
| NFR-202 | 单会话活跃 RSS | ≤ 80 MB |
| NFR-203 | 长历史会话切换后 RSS 增量（10 万事件，切换 20 次） | ≤ 10 MB |
| NFR-204 | 5.5 小时 RSS 斜率（ADR-033） | ≤ 0.5 MB/h |
| NFR-205 | TUI 空闲 CPU | ≤ 0.5% 单核 |
| NFR-206 | LLM 流式期间 CPU | ≤ 8% 单核 |
| NFR-207 | 会话切换响应（10 万事件） | ≤ 200 ms（p50/p95/p99） |
| NFR-208 | 任务概览查询（1 万任务） | p95 ≤ 50 ms |
| NFR-209 | 历史单页查询 | p95 ≤ 30 ms |
| NFR-210 | 事件写入吞吐（候选） | ≥ 2,000 条/秒 |

- 测量纪律：必须记录 OS、硬件、编译类型、工具链、数据库版本、数据规模、采样窗口与脚本；不同平台结果不混为一组平均值
- **NFR-211—215（2026-10-21 新增项目优先序；候选目标，M1 冻结数值）**：
  - NFR-211 资源占用：内存、GPU、线程、句柄四类占用必须可测量；新增任何固定占用（每会话、每前端、每连接）必须经 ADR 批准；空闲态不得随会话数线性增长
  - NFR-212 GPU 纪律：默认不创建 GPU 上下文；视觉效果仅在显式启用时使用，最小化/不可见期间不得持有 GPU 资源（与 FR-617 配套）
  - NFR-213 安全优先：默认回环监听、追踪 `redacted`、最小权限、凭据不落日志与事件；任何放宽必须经用户批准并写入 ADR
  - NFR-214 BSD 代码兼容与工具链：平台分支仅限 `whcode-platform`；非平台 crate 保持 BSD 交叉检查通过；不使用任何 GNU 工具链（D-01 修订）；不改变 ADR-013 的验收范围
  - NFR-215 内存安全与 Rust 实践：自有 crate 的普通 Rust 代码一律通过 workspace lints 设置 `unsafe_code = "forbid"` 并由契约测试校验继承；禁止 `mem::forget` 主动泄漏；队列、缓冲与缓存必须有界；文件、套接字、线程等句柄遵循 RAII 并有释放测试；汇编例外仅按 ADR-015 执行（独立 crate/模块、安全包装、跨平台回退与差分测试）；第三方依赖内部的 unsafe 不在自有代码承诺内，以版本锁定、依赖记录与最小特性控制风险；clippy 默认组（`all`）零告警
  - NFR-216 并发设计先行：线程、调度、锁、无锁结构、内存序、共享缓存与异步运行时必须先有并发设计档案并通过 G2；档案含不变量、线性化点、内存序、进展保证、数据所有权、失败模式、验证计划、回退方案与文献依据；禁止以原型先行代替设计；完成判据是可判定性，不以工时衡量
  - NFR-217 性能优化与汇编例外：内存/CPU 优化必须按“测量→定位→建模→设计→实现→复测→归档”执行，报告分位数与副作用；汇编仅在测量证明热点且安全 Rust 与算法优化不足时允许，须独立 ADR、代码隔离、安全包装、跨平台回退、差分测试与安全评审
  - NFR-218 自由与退出权：用户可随时导出全部数据、离线使用核心能力、撤销默认值；不得以私有格式、隐藏导出、强制账户或强制联网制造退出成本；退出路径必须与进入路径同样可用并进入验收
  - NFR-219 安全反教条：每项安全措施必须附威胁模型、攻击面、证据、代价（可用性/性能/隐私）与失效条件；不得以“最佳安全实践”“行业标准”或检查清单替代威胁分析与可复现验证；默认拒绝、最小权限、回环监听、`redacted`、凭据不落日志是当前和解，变更走 ADR
  - NFR-220 不伪造与未知显式：工具、模型与代理不得编造命令结果、文件内容、外部事实或史料；未知、失败、不可验证必须显式标 `unknown`/`[待验证]`；工具输出须保留原始来源与可复现命令；LLM 生成内容不得作为唯一证据
  - NFR-221 反进步叙事与测量程序：不得以主流采用、星数、下载量、社区共识或版本号作为正确性/进步证据；技术演进不得写成必然进步史；性能与安全结论须来自可复现程序（环境、参数、分位数、交叉验证），程序合法性高于工具
  - NFR-222 用户友好、反苦难与文档时效：错误信息必须可操作、不责怪用户；不得以 RTFM、苦难或加班作为设计或贡献证据；默认显示进度与可取消；文档与 ADR 必须标注假设、适用范围与复审日期；知识会过时，禁止“永恒真理”式表述

### Key Entities *(include if feature involves data)*

- **工作区（Workspace）**: 配置、数据库、任务产物和运行时状态的持久化边界；一个工作区默认对应一个数据库文件（ADR-001）
- **会话（Session）**: 一次可恢复的智能体交互上下文；元数据不含完整历史
- **任务（Task）**: 有标识、依赖、状态、验收条件、重试计数和阶段归属的工作单元；支持父子层级
- **产物（Artifact）**: 规范、计划、任务列表、分析报告、代码差异、测试报告或收敛报告；带解析器版本与校验标记
- **事件（Event）**: 不可变记录；工作区内 seq 唯一单调递增；带 request/session/task/tool_call 关联 ID 与持久化等级
- **消息（Message）**: 会话内按角色与游标组织的对话内容；超大正文可分块存储
- **上下文窗口（Context Window）**: 摘要与原文范围的关系记录（窗口起止 seq、token 总量、摘要引用）
- **检查点（Checkpoint）**: 增量状态差分、产物引用、消息游标和外部操作标记
- **工具执行（Tool Execution）**: 执行意图、状态（含 unknown）、输入哈希、输出与副作用凭证引用
- **审计（Audit）**: 强制放行、权限敏感操作和清理的强制记录；不随普通会话 TTL 自动清除
- **运行时（Runtime）**: 名称、能力等级、后端、版本、安装状态与 payload 路径；执行记录含指纹、退出码、时长与输出引用
- **Schema 迁移（Migration）**: 版本、应用时间与校验和；可审计且不可重复误执行

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 10 万事件会话的切换只返回元数据、概览与有界活跃尾部，分页游标无重复无遗漏（V-101）
- **SC-002**: 1 万任务数据集下任务概览查询报告 p50/p95/p99，且满足 M0 冻结后的性能预算（V-102）
- **SC-003**: 客户端断线重连后按游标补拉事件，关键事件零丢失，任何内容采样/脱敏均有可查询标记（V-103）
- **SC-004**: 已确认事务在进程终止与重启后状态与关键事件一致（V-104）
- **SC-005**: 在步骤边界、外部操作前/后与结果登记前注入崩溃，恢复状态符合“意图—执行—登记”协议，不确定操作标记 unknown（V-105、V-307）
- **SC-006**: 同一幂等键重复提交不产生重复任务或重复登记（V-106）
- **SC-007**: 清理/压缩操作保护活跃会话；compact 副本校验成功后方切换文件（V-107）
- **SC-008**: 同一组业务命令在 TUI/CUI/Web 三端的最终状态、权限与错误码一致（V-109）
- **SC-009**: 默认配置下 Web 仅监听回环地址、追踪默认脱敏、运行时子进程不泄露凭据（V-110）
- **SC-010**: 违反强制约束的产物不能通过门禁；Constitution 变更有版本和审计（V-201）
- **SC-011**: 未解决的高优先级澄清项使 Plan 转换被拒绝（V-202）
- **SC-012**: 遗漏需求、孤儿任务、无效引用、循环依赖与未覆盖验收项可被 Analyze 检出（V-203）
- **SC-013**: 解析连续两次纠偏失败后任务进入 blocked，错误与原始产物可查询（V-204）
- **SC-014**: 未满足或未测试的验收条件生成差异报告，不得标记成功收敛（V-205）
- **SC-015**: 人工放行审计包含执行者、理由、跳过项与产物版本（V-206）
- **SC-016**: 任意前端显示同一阶段、门禁结果与产物版本（V-207）
- **SC-017**: 关闭全部可选运行时的默认构建中主程序仍可运行，差异按实际文件与 RSS 报告（V-301）
- **SC-018**: 受限 JS、Python、Windows Git Bash 通过各自固定测试集；未经覆盖的能力返回结构化错误并声明限制（V-302、V-303、V-304、V-306）
- **SC-019**: 任务超时后子进程及子进程树按平台策略清理，stderr 尾部保留且状态可恢复（V-305）
- **SC-020**: 候选发布版本通过 5.5 小时稳定性测试（ADR-033）并产出规定指标时间序列报告（§11.5）
- **SC-021**: M0 结束时平台矩阵与候选性能预算正式冻结，或经 ADR 记录修订（V-006、V-007）
- **SC-022**: 前端新增能力未在登记表登记即对等门禁失败；登记为预留的能力在任一端调用均返回结构化 `not_supported`（CUI 退出码 55／Web HTTP 501），而非 404 或静默成功；对等门禁正负用例与行为等价夹具全绿（V-112）

## Assumptions

- **状态基线**：本 spec 为需求基线候选；M0 通过前平台与性能承诺不冻结（任务书 §0、§12.1）
- **TUI 非交互退出（M0）**：TUI 不得在 stdin 非交互（管道／重定向）时进入事件循环，无参数启动必须立即退出且退出码为 0，避免自动化环境挂起；验收判据见 `checklist.md` Check 226，证据由 `local/tui_smoke.py` 的 `graceful_exit_on_closed_stdin` 采集
- **用户故事↔里程碑映射**为本轮工程决策：US-n ↔ M-(n-1)；任务书里程碑范围未被改动
- **待决策事项 D-01—D-14** 以任务书建议默认值与后续决策进入对应决策点：首版优先 x86_64（D-01）；单库单工作区（D-02）；Web 为独立 UI（D-03）；SSH 公钥+受限入口（D-04）；追踪默认 redacted（D-05，M1）；性能硬指标 M0 冻结（D-06）；运行时独立 payload（D-07，M8 前）；首版不宣称完整 Node.js（D-08，M8 前）；Python 先验证子进程协议（D-09，M8 前）；独立 db compact（D-10，M1）；默认系统分配器（D-11，M9）；P1 运行时不阻塞首个可用版本（D-12，M0）；平台承诺修订（D-13）；平台范围收敛（D-14）
- **验收环境**：本轮只需 Windows 11 amd64 的真实构建/测试环境（已取得）；FreeBSD/NetBSD/OpenBSD/DragonFly 按 ADR-013 延后，不再作为本轮阻塞项；恢复任一平台时必须具备该平台真实环境并补齐证据，不得以交叉编译代替运行验证（G-01）
- **D-01 修订**：Windows 验收使用 `x86_64-pc-windows-msvc`，**不使用任何 GNU 工具链**；实测 rustc 1.99.1、MSVC 14.44.35207、Windows SDK 10.0.26100.0。`rust-toolchain.toml` 仅锁版本号 `1.99.1`；host triple 由各平台 runner 默认值决定，本机用目录级 `rustup override` 选 msvc（不入库）
- **DuckDB 分发策略**：采用官方预编译动态库，不源码构建；`.github/scripts/fetch-duckdb.py` 校验 SHA256 后解包到 `vendor/duckdb/2.0.0/`，`.cargo/config.toml` 注入 `DUCKDB_LIB_DIR`，Windows 由 `crates/whcode-store/build.rs` 复制 `duckdb.dll`；运行期引擎版本实测 `v2.0.0`，crate 精确锁定 `=1.20000.0`（详见 `docs/adr/ADR-DB-BUILD.md`、`ADR-034`）
- **平台范围收敛（ADR-013）**：唯一验收目标为 Windows 11 `x86_64`（`x86_64-pc-windows-msvc`）；**不考虑任何 32 位平台**；FreeBSD/NetBSD/OpenBSD/DragonFly 全部延后——保留代码、文档与 CI 定义，但不作为验收目标，恢复须新 ADR 并补齐完整证据链（构建、数据库冒烟、依赖记录、性能分位数、客户端/服务端证据）。延后不等同于“已支持”或“已放弃”
- **平台承诺修订（ADR-011）**：OpenBSD 与 DragonFly BSD 移出原生安装目标，改由内置 SSH 客户端（FR-611）控制；该方向仍有效，但按 ADR-013 延后，不进入本轮验收
- **自由与安全基线**：不替用户定义善、道德或自由；退出权、完整导出、离线核心能力与默认值可撤销进入验收；安全措施按威胁模型与证据评估，不以“最佳实践/合规”结项（NFR-218/219、Task T146、Check 244—245；详见 `docs/guides/philosophy.md` §10）
- **一刻哲学基线**：`docs/guides/yike-philosophy.md` 记录来源与工程翻译；不伪造/未知显式、反进步叙事、用户友好与文档时效作为设计与验收判据（NFR-220—222、Task T147、Check 246—248）
- **性能与并发策略**：多线程并发禁止原型先行；设计前至少研读 3 篇一手文献并提交并发设计档案；汇编仅按 ADR-015 例外使用；详见 `docs/guides/performance-and-concurrency.md`（NFR-216/217、Task T145、Check 241—243）
- **项目哲学基线**：`docs/guides/philosophy.md` 是设计与过程的方法论总纲；形式主义审查、正负和解、三重时间依据与 0 信任原则适用于 G0—G5，不得以“最佳实践”名义跳过证据（Task T144、Check 240）
- **范围外**（任务书 §1.3）：全功能代码编辑器、完整 LSP、调试器与 IDE 插件市场；多租户 SaaS 与计费；移动端原生应用；DuckDB 以外的默认持久化后端；主进程内执行任意不受信任脚本；**任何 32 位平台**
- **显示适配边界**：终端应用不能直接控制墨水屏驱动器的全刷/局刷模式，也不能直接调度 GPU；FR-613 对 TUI 的可交付承诺是“事件驱动重绘 + 静态布局 + 主题纯色”，对墨水屏残影与 OLED 烧屏的物理层缓解由终端模拟器与系统承担，spec 只承诺不加剧（无周期性全量重绘、无固定高亮闪烁元素）
- **宪法（Constitution）**：`.specify/memory/constitution.md` 当前为未批准的模板占位；本 spec 的治理约束以任务书 §2 的冻结 ADR-001—014 与 §0 规范用语为准，宪法文件待项目正式批准后替换
- **上游 Spec Kit 兼容**：WHCode 的 SDD 工作流与上游概念/产物兼容，但不假定上游某一版本的命令、模板或插件为稳定 API（§4.3）
