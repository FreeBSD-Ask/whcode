## 0. 任务认知卡（宪法原则 X，`docs/guides/knowing-before-doing.md`）

- **方向**：WHCode 的 GUI 与 Web 已实现“功能对等”（ADR-032 五维、ADR-056 交互化），
  但与 ZCode 的**使用体验**仍有可见差距——对话流呈现、工具调用卡、审批交互、todo／
  任务面板、高级能力面板、视觉语言。本计划把这些差距分批闭合。
- **目标**：一份可执行的分批计划（每批双端同交付、可判定、可追溯）＋一份判据与主题层
  的 ADR 草案；不先锁死渲染手段与色值（批次 R 侦察后冻结）。
- **用户真实意图**：从“能做”到“和 ZCode 一样好用、好看”；全量体验含视觉；
  双端（GUI＋Web）同批推进，不允许单端长期领先拉大对等债。
- **判据**：每批＝双端行为测试＋契约测试＋预算审计（`check-frontend-budget`／desktop
  探针）＋FR↔任务↔Check 三方追溯＋CI 全绿；总体＝对照批次 R 产出的 ZCode 体验清单
  逐项登记（实现／有意差异／预留），不留未登记差距。
- **非目标**：不改验收平台（Windows 11 amd64，ADR-013）；不放宽原生 GUI 铁律
  （ADR-026，无 WebView／CEF）；不放宽资源预算（ADR-027／前端预算）；不引入强制
  账户／联网（§8 冲突 6）；不重写后端能力边界——后端缺口作为前置依赖单独立项，
  不混入 UI 批次蒙混交付。
- **手段后置**：markdown 渲染方案、列表虚拟化、diff 呈现形态、zcode 主题精确色值
  均在批次 R／批次设计时定；本计划只锁范围、判据、纪律与批次框架。

## 1. G0 范围

**做什么**：六个批次（R＋B1—B5），每批 GUI（iced＋tiny-skia，ADR-027）与 Web
（服务端直出＋原生 ESM，ADR-014）同交付；新能力走 `SURFACES` 登记与 FR-610 同 PR 纪律；
FR／任务／Check 编号接续主账本（现 FR-738／T248／Check 343）。

**不做什么**（显式排除，均有归属）：

| 排除项 | 归属 |
|---|---|
| 工具级交互权限 broker 的**后端**设计定稿 | B3a（同计划内前置工作单元，需 ADR-048 修订或 ADR-058） |
| 插件／钩子面板（域 J） | M8+ 视排期（P2 级，登记不排期） |
| 远程协作服务端（Relay／daemon／分享服务） | M7+，另立 ADR（安全类须用户批准） |
| 扫码登录／OAuth | **不在承诺内**：仅作“可选供应商登录”评估登记（禁强制账户／联网，§8 冲突 6） |
| 凭据加密落库 | 不采纳（沿用既有 ADR 结论：不落库更简单） |
| TUI 对话输入整合、GUI 事件游标推进 | ADR-056 后续另行立项；本计划只登记引用，不重复排期 |
| 预览机制（CDP＋Playwright） | B5 仅做评估结论登记（引入外部浏览器驱动与轻量原则冲突，倾向不采纳） |

**正负和解**（G0 口径摘要，详见 ADR-057）：正面＝体验差距闭合、ZCode 用户迁移成本降低、
双端从“功能对等”升到“体验对等”；负面＝工程量大（六批）、渲染预算压力、对等债风险
（TUI／CUI 形态落后）、视觉对齐随 ZCode 演进漂移；承担者＝GUI／Web 维护者、B3a 后端、
用户（默认主题变化，可见可改可撤销）；和解＝分期小步、每批全绿结题、预算审计自动化。

## 4. G1 需求增量（FR 草案，编号接续 FR-738；批准后落入 spec.md）

- **FR-739**（P1）：新增 `zcode-day`／`zcode-night` 两套主题，精确色值批次 R 提取并冻结；
  **主题保证铁律（2026-11-05 用户补遗）**：既有四套主题（amoled-night 纯黑 `#000000`／
  eink 双主题墨水屏口径（真灰 R=G=B、避免大面积中间灰与渐变）／terminal-green 纯黑＋
  `#00FF00`）的精确色值与可用性**不可稀释**，zcode 主题为新增而非覆盖；四套主题色值由
  双端契约测试锁定（GUI／Web hex 断言，批次 R 起升级为六套主题全覆盖），视觉 token
  派生对其零影响；GUI／Web 同步支持，经 `theme.switch` 切换；默认主题是否切换为
  zcode 系由用户批准，默认值可见可改可撤销。
- **FR-740**（P1）：视觉 token（色板、间距、字号、圆角、层级）单一事实源定义一处，
  GUI 与 Web 由同一来源派生；双端一致性由契约测试断言（篡改 token 即失败，
  沿 ADR-032 受校验产物模式）。
- **FR-741**（P1）：GUI 对话流式渲染——turn 执行期间逐块增量呈现正文与工具卡进度；
  markdown 最小集（标题／列表／代码块／行内码）原生渲染，不嵌入浏览器引擎；
  超长消息与消息列表必须虚拟化或有界（复用既有游标，不无界累积）。
- **FR-742**（P1）：Web 对话页——WS 逐块推送、服务端直出无 JS 降级（显示有界尾部
  快照，语义同首页既有降级）；首屏 JS／CSS／DOM 预算不破。
- **FR-743**（P1）：工具调用卡——四端语义一致（事件源 `ToolCallStarted/Finished`），
  GUI／Web 卡片形态，CUI／TUI 结构化文本；参数与输出展示一律经脱敏管线
  （`redacted` 标记贯穿，正文不入事件 payload 的口径不变）。
- **FR-744**（P1，后端）：工具级交互审批 broker——权限规则（允许／询问／拒绝）、
  审批请求与决定落审计事件；拒绝语义与 FR-604 对齐（`permission_denied` 不可重试）；
  broker 不新增常驻线程、队列有界。
- **FR-745**（P1）：双端审批交互——四态决定（批准／拒绝／仅本次／记住规则）对齐
  域 C 勘察；破坏性工具默认确认；记住规则写入本地权限规则存储并可在设置页撤销。
- **FR-746**（P2）：会话侧栏对齐——搜索／排序／归档分组；GUI 与 Web 同形态语义。
- **FR-747**（P2）：任务／todo 面板——依赖、重试计数、进度呈现（`task.overview` 数据面）。
- **FR-748**（P2）：检查点浏览——列表＋差分摘要查看；回滚执行依赖后端能力，
  缺则本 FR 显式降级为浏览并登记缺口（不伪造可回滚）。
- **FR-749**（P2）：子代理运行视图——运行中／完成／失败状态与产出摘要
  （`whcode-app::queue` 编排面）。
- **FR-750**（P2）：技能库浏览与 MCP 服务器状态面板（连接状态、工具清单、超时配置展示）。
- **FR-751**（P2）：权限模式设置页——审批规则查看／撤销、工具权限规则管理；
  Web 设置页扩展＋GUI 设置视图。
- **FR-752**（P3）：会话分享导出——脱敏导出包（默认排除凭据、追踪原文、`redacted`
  之外的敏感项），本地文件落盘，不内置上传／联网；威胁模型与代价入 ADR-057 安全小节。
- **FR-753**（P3，评估性）：预览机制（CDP＋Playwright）评估结论登记——做或不做及理由；
  未评估前不得引入。

i18n（简中／英双语同批、RTL 口径）与无 JS 降级是所有新 UI 的通用约束（FR-615／625、
ADR-014 沿用），不逐条重复立项。

## 6. 与现行纪律的冲突与和解（逐条，均有 ADR 落点）

1. **ADR-032 对等判据（视觉不作判据）**：ZCode 对齐范围内，GUI／Web 的视觉与关键
   交互形态升级为判据；TUI／CUI 仍按五维。落点＝ADR-057 决策 1＋ADR-032 追加修订记录。
2. **四主题精确色值（AGENTS.md §6，用户指令；2026-11-05 补遗“主题仍确保 OLED 黑等”）**：
   不废除、不改值、不可稀释——amoled-night 纯黑、eink 双主题墨水屏口径（真灰 R=G=B、
   避免大面积中间灰与渐变）、terminal-green 纯黑＋`#00FF00` 全程保持；zcode 两套主题为
   **新增而非覆盖**，精确色值冻结后才入库；默认主题变更单独征求用户批准；四套主题的
   双端 hex 断言测试为每批结题前置。落点＝ADR-057 决策 2＋复审触发。
3. **资源与前端预算铁律**：不放宽。Web 靠服务端直出＋虚拟化控制 DOM；GUI 靠 iced
   原生文本能力＋最小自绘 markdown，禁 WebView／HTML 溢出文本。每批预算审计是
   结题前置。落点＝ADR-057 决策 3。
4. **原生 GUI 铁律（ADR-026）**：不放宽，零例外。视觉对齐≠引入浏览器引擎。
5. **脱敏与追踪纪律**：工具参数／输出、对话正文入 UI 前一律经既有 redacted 管线；
   新增日志／断言遵守 CodeQL 敏感词纪律（AGENTS.md §5.2）。
6. **自由与安全（禁止强制账户／联网）**：分享＝本地导出文件，无上传；扫码／OAuth
   仅评估登记；预览倾向不采纳。落点＝ADR-057 安全小节。
7. **单连接唯一写路径（Check 98）**：新视图一律只读经 `StoreViewSource`；
   后台执行沿用 ADR-056 Phase 2 的 `Arc<Mutex<Connection>>` 语义，不新增连接。

## 8. 依赖与顺序

```text
R（侦察＋token 提案）
  └→ B1（对话流核心）
       └→ B2（会话/任务管理 UI）      ── 可与 B3a 并行
             └→ B3a（审批 broker 后端，另立 ADR）→ B3b（工具卡＋审批 UI 双端）
                   └→ B4（高级面板）          ── 可与 B3b 并行
                         └→ B5（协作＋收尾＋结题对账）
```

每批独立可交付、可停（批间中止不留半成品语义）；批准后首动作＝批次 R。
