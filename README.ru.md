Локальная среда кодирования с LLM, нативная для Rust. Данные лежат в одном файле DuckDB, каждое
действие можно проследить, а шлюзы разработки по спецификации исполняются программами, а не
дисциплиной участников. Нативные GUI, TUI, CUI, Web и SSH используют один прикладной сервис.

- **Локальность прежде всего**: один файл DuckDB, данные можно забрать в любой момент.
  Ни учётной записи, ни принудительной работы в сети.
- **Прослеживаемость**: каждый вызов инструмента записывается как «намерение — исполнение —
  регистрация». Уровень трассировки по умолчанию — `redacted`, поэтому учётные данные не
  попадают ни в журналы, ни в события.
- **Несколько интерфейсов**: GUI, TUI, CUI, Web и SSH работают поверх одного сервиса.
  Настольный интерфейс рисуется нативно и не встраивает браузерный движок.
- **Разработка по спецификации**: требования, задачи и критерии приёмки связаны
  трёхсторонней трассировкой, и эту связь проверяют тесты и скрипты.

## Текущее состояние

Версия `0.1.0`, релиза ещё не было. Изменения — в [CHANGELOG.md](./CHANGELOG.md).

M0—M6, M8 и паритет четырёх интерфейсов готовы, SSH-сервер этапа M7 тоже работает. Для
5,5-часового испытания на стабильность (M9) пока нет данных, отвечающих критериям, а подключение
клиента к настоящему поставщику LLM не выполнено. Подробный прогресс, причины незавершённых
пунктов и места хранения свидетельств — в
[снимке состояния проекта](./docs/guides/project-status.md). Основные реестры —
[tasks.md](./specs/001-whcode-harness/tasks.md) и
[checklist.md](./specs/001-whcode-harness/checklist.md), известные ограничения —
[compatibility.md](./docs/matrices/compatibility.md).

## Поддержка платформ

| Платформа | Роль |
|---|---|
| Windows 11 amd64 | **Единственная цель приёмки** (`x86_64-pc-windows-msvc`, ADR-013) |
| Windows ARM64 | Цель поставки сборок (ADR-043): результаты CI служат только свидетельством платформы и не входят в приёмку |
| FreeBSD | Полный канал свидетельств платформы (жёсткий шлюз): CI при каждом изменении `main` собирает, тестирует и прогоняет шлюзы целиком, любая ошибка делает прогон красным; выводов о приёмке не даёт |
| NetBSD | CI запускается автоматически на `main`; только свидетельство платформы |
| OpenBSD / DragonFly | Ручная заготовка; вместе с NetBSD служат целью удалённой разработки по SSH (это подключаемая сторона, нативный инструментарий не требуется) |

Квантили производительности сейчас сняты только на канале Windows. Полная политика —
в [ADR-013](./docs/adr/ADR-013-platform-scope-windows-only.md) и
[compatibility.md](./docs/matrices/compatibility.md).

## Сборка и запуск

Нужны Rust 1.99.1 (зафиксирован в `rust-toolchain.toml`), инструментарий MSVC и Python 3.
Инструментарий GNU не используется нигде.

```powershell
# Перед первой сборкой получите и проверьте разделяемую библиотеку DuckDB (SHA256)
python .github/scripts/fetch-duckdb.py

cargo build --locked --workspace
cargo test --locked --workspace

# Самодиагностика окружения
cargo run -p whcode-bin --release -- doctor

# Интерфейсы: в Windows по умолчанию нативный GUI; --tui — терминал; --cli — командная строка
cargo run -p whcode-bin --release --
cargo run -p whcode-bin --release -- --tui
cargo run -p whcode-bin --release -- --cli task list --session <идентификатор сеанса>

# Web (по умолчанию HTTPS с самоподписанным сертификатом; --tls off возвращает открытый HTTP)
cargo run -p whcode-bin --release -- serve --web
cargo run -p whcode-bin --release -- serve --web --tls off
```

При запуске без аргументов в Windows открывается нативный GUI. Добавьте `--tui` для
терминального интерфейса (`1`—`6` переключают виды, `q` завершает работу) или `--cli` для
командной строки. TUI не получает нажатия клавиш в псевдотерминале (Git Bash, mintty) или пока
консоль находится в режиме выделения QuickEdit, поэтому запускайте его в Windows Terminal или
conhost. Сочетания клавиш и описание видов — в [tui.md](./docs/guides/tui.md).

Если консоли нет (CI, конвейер, перенаправление), программа не открывает интерфейс: печатает
подсказку и завершается с кодом 0.

## Точки входа

| Вход | Запуск | Описание |
|---|---|---|
| GUI | `whcode` (по умолчанию в Windows) или `whcode gui` | Нативный интерфейс только для чтения, без браузерного движка |
| TUI | `whcode --tui` | Шесть видов только для чтения; записи требуют двухшагового подтверждения. См. [tui.md](./docs/guides/tui.md) |
| CUI | `whcode --cli <подкоманда>` или `whcode <подкоманда>` | Единый конверт `--json` и стабильные коды выхода. См. [cui-manual.md](./docs/guides/cui-manual.md) |
| Web | `whcode serve --web` | По умолчанию только петлевой адрес, входящий TLS включён. См. [web-deployment-security.md](./docs/guides/web-deployment-security.md) |
| SSH | `whcode serve --ssh` | Ограниченная точка входа; системная оболочка по умолчанию не выдаётся. Приёмка на четырёх платформах отложена |
