## 6. 缺口清单（按可判定性，不含“需改实现”的建议）

- **G1（Check 284，部分写）**：缺“非阻塞写只接受部分字节、下一 tick 续写”的专项测试。
  现有 `serve.rs` 写泵（`869`、`1235`）与 `tls.rs::write_plain` 的部分接受语义只被
  `pending_output_is_bounded_and_never_swallows_bytes` 间接触及（该测试断言的是“暂存满 →
  `WouldBlock`、不吞字节”，不是“残余续写”）。
- **G2（Check 284，并发上限）**：无第 97 条连接（`MAX_CLIENTS = 96`）的测试；TLS 侧
  “直接关闭、不排队”只有 `serve.rs:660-668` 的代码事实。
- **G3（Check 284，每连接缓冲）**：`tls.rs:341-345` 的 `MAX_TLS_CIPHERTEXT`（64 KiB）守卫
  **不可达**——每轮先 `ciphertext.clear()` 再写入至多 `TLS_READ_CHUNK = 4096` 字节，
  长度恒 ≤ 4096。即“有界”成立，但该显式上限与其错误分支从未被触发；同时
  `MAX_TLS_PLAINTEXT` 与 `serve.rs:759` 的 HTTP 读取上限无测试。
- **G4（Check 282）**：① `external` 正向（`prepare_tls` 载入 PEM 链 + 未加密私钥 → 返回
  可用 `ServerConfig`）只有运行证据 `s3-external-*`，无单元测试；② “不可解析证书”仅覆盖
  空链与超限，非空畸形 PEM 未覆盖；③ 任务指定的 `cargo test -p whcode-bin tls` 过滤器
  漏掉 5 条相关测试（`fragmented_client_hello_is_accepted_by_serve_loop`、
  `invalid_client_hello_closes_connection_and_server_survives`、
  `enabled_modes_refuse_to_start_when_cert_store_unusable`、
  `external_mode_without_uploaded_material_is_refused`、
  `builtin_mode_prepares_material_and_fingerprint`），复核需加跑 `serve::tests`。
- **G5（Check 285）**：① 无“启用 token 时 `/api/certs` 缺 token → 403”的专项测试；
  ② 审计失败回滚只在 `whcode-app` 层测试，API 层无端到端注入。
- **G6（全部）**：CI 未运行（无远端仓库），按 ADR-037 属“未取得 CI 证据”，本地全绿
  不得冒充验收结论。
- **G7（证据文档内部不一致）**：`summary.md` 第 39 行把错误尾串抄成
  `…\s3-bad\.whcode\cert`，`s3-bad-stderr.txt` 原文为 `…\s3-bad\.whcode\certs`；
  以文件原文为准，本次不改 `summary.md`。
