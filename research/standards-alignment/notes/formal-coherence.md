# T13 研读笔记：形式化融洽性与充分性判定

**研读日期**：2026-11-17 | **域**：需求可验证性、保障案、架构对应关系、模型论满足关系 | **方法**：标准基线在档条款回查＋一手理论文献要点自述，逐条标注证据层级

## 1. 任务与读法

本笔记服务 ADR-085（形式化融洽性审计与三阶段充分性计算）的开工前置研读（`software-engineering-process.md` §1.6）。
任务要回答的是：把规则体系当作形式理论 Γ、把仓库状态当作模型 M 之后，哪些条款可以逐条计算
`M ⊨ γ`，哪些只能登记为不可判定。选读口径是“判定与承诺相关条款”，不逐卷通读。

## 2. 已登记标准的直接锚点

下列条目均以 `docs/guides/standards-baseline.md` 为唯一版本事实源，本节只写本任务用到的条款与落点。

| 标准 | 本任务用到的内容 | 证据层级 | 本仓落点 |
|---|---|---|---|
| ISO/IEC/IEEE 29148:2018 | 单条需求特征含“无歧义、可验证、可追溯”；需求集特征含“一致、可行” | 确证（基线在档，官方页与 IEEE SA 页交叉，2026-11-14） | 可验证性对应 `COH-A2-*` 与 `COH-R2-*` 谓词；一致性与可行性对应三阶段计算 |
| ISO/IEC/IEEE 15026-2:2022 | 保障案结构为 claim → argument → evidence | 确证（基线在档） | 每条公理条目即一个 claim；`evaluator` 与 `evidence` 字段即 argument 与 evidence；台账是未闭合 claim 的登记 |
| ISO/IEC/IEEE 42010:2022 | 架构描述要求视图之间的对应关系（correspondence）可核对 | 确证（基线在档） | 规则条款（Γ）与仓库产物（M）之间的对应关系由 `source` 锚点与 `evaluator` 双向可核对 |

| ISO/IEC 25010:2023 | 功能适合性与可维护性中的可分析性、可修改性 | 确证（基线在档） | 公理表可增删条目而不改脚本，对应可修改性；反例台账对应可分析性 |
| ISO/IEC/IEEE 12207:2026 | 验证过程与确认过程分离 | 确证（基线在档） | `pre` 阶段是确认（要求是否成立），`mid`／`end` 是验证（产物是否满足要求） |

## 3. 理论源流（非标准，标为解释层）

1. **Tarski 满足关系**：`M ⊨ φ` 的定义要求先固定语言、解释与模型。本仓的 Γ 是文档规则，
   M 是仓库事实；两者都不是形式语言原生对象，因此必须先划定可判定片段，不能宣称“全体系满足”。
   这一点与 `docs/analysis/software-engineering-logic-sufficiency.md` §3、§8 的口径一致。
2. **可判定性与半可判定性**：有限产物集合上的守恒式检查（文件存在、编号连续、计数相等、
   引用可解析）是可判定的；开放语义（意图是否正确、设计是否最优）不可判定。把不可判定项
   登记为 `registered`，而不是让它们静默通过，是本任务与“门禁全绿即充分”说法的分界。
3. **模型检验的代价边界**：模型检验适用于有限状态；本仓不对运行时状态空间做模型检验，
   只对仓库产物做静态检查。二者不可混称，ADR-085 §7 已登记为限制。

## 4. 判定用语与裁剪

| 用语 | 含义 | 本仓落点 |
|---|---|---|
| 可判定（decidable） | 有限步内可给出二值结论 | `tier = "I"`，`evaluator = "direct:*"` |
| 委托可判定（delegated） | 结论由既有门禁脚本的退出码给出 | `tier = "I"`，`evaluator = "delegate:<script>"` |
| 半可判定（semi-decidable） | 一次真实运行给见证，不给证明 | `tier = "III"`，需 CI 日志或 artifact |
| 已登记不可判定（registered） | 无判定程序，只有补偿控制 | `tier = "IV"`，`evaluator = "registered:<reason>"` |

裁剪：纯文案改动不新增公理；新增硬约束必须登记到某条既有公理下，或在 ADR 中新增公理。
边界模糊时按“登记”处理，不按“不适用”处理。

## 5. 研读结论

1. 本任务不需要引入新的外部标准：可判定片段对应 29148 的可验证性与一致性，保障案结构对应
   15026-2，对应关系核对对应 42010，独立性对应 1012 的思想层。
2. 本任务**不宣称合规**，也不把模型检验术语借来抬高门槛；形式化的范围与失效条件写入 ADR-085 §7。
3. 未取得：29148 与 15026-2 的条款原文逐字引用（付费墙内，按 `software-engineering-process.md`
   §1.6 作摘要级理解，标 `[待验证]`）；本笔记只用其已登记在基线的特征表，不复制原文。
