# T5＋T6 研读笔记：配置管理、度量、维护、架构描述

**研读日期**：2026-11-14

## 1. 配置管理（CM）

| 标准 | 现行状态 | 证据层级 |
|---|---|---|
| IEEE 828-2012 | **Inactive-Reserved**（已不维护；内容并入 ISO/IEC/IEEE 12207:2017 的 CM 过程） | 确证（IEEE 目录＋检索交叉） |
| ISO 10007:2017 | 现行（CM 指南；CM 计划结构在附录；新版 ISO/WD 10007 在研） | 确证（检索交叉） |
| 12207 配置管理过程 | 2017 版技术管理过程组内；2026 版延续 | 确证 |

CM 四要素：配置标识、变更控制、状态记实、配置验证与审核。

**对 WHCode 的映射**：git（标识/状态记实）＋ pathspec 提交与 ADR（变更控制）＋ 标签/CHANGELOG（状态记实）＋ traceability.py/check_counts.py（验证审核）——四要素齐备但**无成文 CM 计划**（过程 §5 已自登记“无正式分支策略文档”）。判定预判：部分覆盖；候选落地项是一份轻量 CM 说明（合并进 process 文档而非新文件，防文档增殖）。

## 2. 度量（ISO/IEC/IEEE 15939:2017）

现行版 15939:2017（新版 DIS 在研）。核心：测量信息模型（measurable concept → base measure → derived measure → indicator → 决策准则）。

**对 WHCode**：NFR-201—210（指标/目标/测量条件/分位数）＋ benchmarks 脚本＋ traceability 分布统计，与 15939 的信息模型同构；缺“决策准则”显式化（何时指标红灯须行动）——部分已被 resource-budget 的“不达标禁止落地”承担。判定预判：已覆盖（思想），不另立测量计划。

## 3. 维护（ISO/IEC/IEEE 14764:2022）

现行版 14764:2022（2021/2022，注意无 2012 版——检索纠错）。四类维护：纠正性、适应性、完善性、预防性。

**对 WHCode**：CHANGELOG“修复”段（纠正性）、ADR-069 类升级（适应性）、性能优化（完善性）、复审触发（预防性）——四类均有落点，但未按此分类标注。判定预判：已覆盖（实质），可选落地：CHANGELOG 类别词与四类对齐（低优先级，须过形式主义审查）。

## 4. 架构描述（ISO/IEC/IEEE 42010:2022）

现行版 42010:2022（2022-11-07 发布，替代 2011）。核心概念：利益相关方、关注点（concern）、视点（viewpoint）、视图（view）、模型、对应关系（correspondence）；架构描述框架（ADF）与评估指引。

**对 WHCode**：
- ADR 制度是 42010“架构决策”的实践形态（AD 实践源于 Nygard 2011“Documenting Architecture Decisions”与 ThoughtWorks 采纳）；plan.md 的 C-01—C-08 约束清单对应“关注点”；
- module-design.md 的逐 crate 六项（职责/不负责/关键类型/依赖/失败模式/测试位置）对应视图集；
- 本仓无按 42010 术语组织的 AD 文档——属形式取舍：42010 的对象是“架构描述”，本仓的等效物是 plan＋ADR＋layering 测试三件套，判定预判：已覆盖（实质），不重写为 42010 格式。
