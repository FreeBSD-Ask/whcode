# 标准规范全景研读与对标审计（standards-alignment）

**日期**：2026-11-14 | **性质**：研究证据（ADR-045 口径：不承载需求承诺；结论转化为承诺须走 G0—G5） | **状态**：研读完成，落地方案**待用户批准**

## 0. 任务认知卡（宪法原则 X）

- **方向**：把现行 G0—G5／文档治理／门禁脚本／工具链与全景标准逐域对标，取代“仅 3 份文档零散引用标准”的现状。
- **目标**：产出研读报告＋对标矩阵（每域五类判定＋证据链接），经用户批准后落地至少 1 次文档修订与至少 1 项可执行门禁（新 ADR），全验证链绿。
- **用户意图**（已确认，2026-11-14 三项范围选择）：研读清楚之前不批准任何结论；找真缺口与有意偏离，而非照搬最佳实践；范围取“全景含安全关键（不对标、只取思想参照）”；落地取“文档＋门禁”；一手材料“尽力抓取、逐条标注证据层级”。
- **非目标**：不宣称合规／认证；安全关键类只作思想参照；不放宽任何现行硬边界（Windows 唯一验收、零 unsafe、禁 GNU、原生 GUI 等）；不动用户未提交的 SDK WIP（sdk.rs、ADR-071、contracts/sdk-jsonrpc.md）；不以主流采用率为证据。
- **手段（后置）**：官方页核验＋多源检索交叉＋公开全文抓取评估；判定词汇五类（已覆盖／部分覆盖／缺口／有意偏离／不适用）。

## 1. 研读方法与证据层级

1. **来源**：ISO.org／IEEE SA／Open Group／NIST／slsa.dev／rust-lang 等官方页 fetch；多源检索交叉；GB 国标以 openstd.samr.gov.cn 官方信息页为准。
2. **标注**：〔官〕＝官方页或免费全文核验；〔检〕＝至少两个独立来源交叉；〔识〕＝训练知识未经本轮独立核验。无法核验处一律标 [待验证]，不冒充读过付费墙内全文（12207:2026、DO-178C、61508、26262、21434、5338 等仅取得官方摘要与公开预览）。
3. **三次复查**：版本事实（本研读最高风险项）均按“官方页→第二独立来源→判定”执行；两处训练知识与检索冲突（GB/T 25000.51 年份、14764“2012 版”不存在）以检索纠错。
4. **文件**：本目录 `notes/` 九份域笔记（逐标准：版本、结构、映射、判定）＋ `matrix.md`（五类判定矩阵）。

## 2. 执行摘要

研读了 10 域、约 45 份标准／规范／框架（版本全部核验到年）。三条主线结论：

1. **本仓过程体系与 ISO/IEC/IEEE 12207 的过程组高度同构**：G0—G5 覆盖技术过程 14 项与技术管理过程 8 项的实质；需求工程（29148）、测量（15939）、维护（14764）、架构描述（42010）均有成熟本地对应物，多处（文档可执行验收、零 open 告警铁律、action 版本+SHA 双重固定）**强于**标准最低要求。
2. **版本事实纠偏是本轮最大直接产出**：本仓引用的标准有 3 处已停用／过时、1 处特性计数过时（详见 §3）。这些不是缺陷，而是任何活文档体系都会遇到的漂移——恰说明“版本事实门禁”是值得程序化的规则。
3. **缺口少且轻**：真正的新缺口只有“轻量风险登记”与“已停用标准的引用状态标注”两处；其余“缺口”全部是仓库已知且已自登记的（需求属性表、CM 计划、测试计划文档、25010 逐特性映射）。

## 4. 超配项（本仓强于标准最低要求，登记防止后续误删）

1. **Code Scanning 零 open 告警铁律**（AGENTS §5.2）——SSDF PW 组无此强度；
2. **CI action 最新 release 版本＋固定 40 位 SHA＋action-versions.json 唯一事实源＋每周联网复核**（§5.1）——超出现有 SHA 固定惯例（SLSA 视角：这是依赖面卫生基线的高配形态）；
3. **文档可执行验收**（tool-catalogue 逐字节比对、check-docs-style、web-ui-check 等）——26513“用户信息测试与评审”的程序化超配；
4. **七值证据态＋明确拒绝评分制**（evidence-states.md）——比 15026-2 最低结构更细，且以“拒评分”防行为操纵；
5. **安全反教条**（威胁模型优先于合规清单）——与 27001/42001 类认证体系相比是另一条路线，本仓哲学 §10.6 已论证。
