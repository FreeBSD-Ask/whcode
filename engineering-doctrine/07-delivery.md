# 07 仓库、交付与评审

目录与交付规则不靠自觉，靠可执行门禁。任何新增文件都必须能被归类；任何结论都必须能落到
证据。

## 1. 目录分层

按“产品代码 / 验证 / 交付 / 治理 / 本地”五类分层：

| 目录 | 类别 | 职责 | 入库 |
|---|---|---|---|
| `src/` 或 `crates/` | 产品代码 | 源代码，单向依赖 | 是 |
| `tests/` | 验证 | unit/contract/integration/crash/stability/fixtures，各有 README | 是 |
| `.github/scripts/` | 验证（自动化） | 平台 workflow、基准脚本、依赖记录 | 是 |
| `docs/` | 治理文档 | ADR、矩阵、指南 | 是 |
| `specs/` | 治理（需求基线） | 规格、计划、任务、验收清单、契约 | 是 |
| `artifacts/` | 交付产物 | 运行期证据，默认忽略；治理报告可放行 | 默认否 |
| `vendor/` | 交付（二进制） | 预编译依赖，校验后解包 | 否 |
| `script/` | 本地 | 临时脚本、探测、日志；保留但不入库 | 否 |
| `target/` / 构建产物 | 本地 | 可再生成 | 否 |

根文件只允许工程清单、标准开源文件、编码策略文件与代理入口（如 `AGENTS.md`）。
新增根文件/顶层目录必须同步布局门禁与文档。

## 2. 命名与放置

- 新增模块进对应域目录，不建 `utils` 杂物间；
- 新测试按性质进六类之一，并在该类 README 登记；
- 新 CI 脚本按平台/测量归类；
- 新文档按用途进 ADR/矩阵/指南；需求变更进 `specs/`，不写进 `docs/`；
- 临时脚本一律放 `script/`，不清理、不入库。

## 3. 编码卫生

- 所有文本 **UTF-8 无 BOM**；
- 换行统一 **LF**；用 `.gitattributes`、`.editorconfig` 与格式化工具三重保证；
- 二进制类型在 `.gitattributes` 显式登记；
- 中文正文引号用“”或‘’，禁用方头括号与白双引号，以及英文直引号；
- 不篡改代码块与非注释代码；注释只在逻辑不自明处添加；
- 提供 `normalize_eol` 类脚本审计 CRLF/BOM。
- **计数单一来源**：FR/任务/Check 的数量由脚本从文件计算，文档只引用脚本输出；
  禁止手工维护多个计数。
- **文档元数据**：ADR/指南标注假设、适用范围与复审日期；过期文档下架或重写。

## 4. 版本与变更记录

- 语义化版本；未发布版本用预发布标识；
- `CHANGELOG.md` 记录新增/变更/修复/移除/安全；
- 标签只指向可复现提交；标签不可改写；
- 未实现与已知限制公开，不得用版本号暗示已交付。

## 5. 证据

- 构建/测试/基准/冒烟/依赖记录落 `artifacts/` 或等价目录；
- 证据含环境、命令、输出摘要、时间；
- 证据可再生成；不可再生成的产物记录哈希与来源；
- 未取得证据的项标“阻塞/未取得”，不得勾选通过。

## 6. PR 清单

- [ ] 需求/缺陷编号与范围明确；
- [ ] 正向与失败路径测试已更新；
- [ ] 输出/schema 变化有版本兼容审查；
- [ ] 资源、权限、持久化、恢复影响已说明；
- [ ] 平台限制/依赖升级已更新矩阵；
- [ ] 未实现事项明确标注；
- [ ] 形式主义审查：形式、矛盾、正负、过去/现在/将来依据；
- [ ] 0 信任复核：报错、文档、外部事实有独立复现或交叉验证；
- [ ] 当前和解：引用“最佳实践”时写明适用条件与失效条件；
- [ ] 物质—意识一致：文档、代码、产物、测量互相一致；
- [ ] 并发改动附设计档案、不变量/内存序/进展保证与验证计划；
- [ ] 性能/并发改动附一手文献与同夹具前后对比；
- [ ] 汇编改动有独立 ADR、隔离、安全包装、回退与差分测试；
- [ ] 自由与退出：导出、离线、退出路径可用；无暗黑模式；
- [ ] 主体性：无排行榜/连胜/羞耻/行为操纵；默认值可撤销；
- [ ] 安全：威胁模型、攻击面、证据、代价、失效条件齐备；
- [ ] 不伪造：工具/模型输出可追溯，未知显式；
- [ ] 文档含假设与复审日期。

## 7. 提交约定

- 小步提交，消息用 `type(scope): 摘要`，正文写“为什么”；
- 每次只暂存相关文件，不用 `git add -A`；
- 不提交本地脚本、构建产物、依赖二进制、状态目录；
- 不提交凭据与测试图片；
- 提交后回报：改了什么、证据在哪、还有哪些未取得。

## 8. 发布检查

- [ ] 标签指向可复现提交；
- [ ] 变更记录覆盖本增量；
- [ ] 已知限制与未验证项公开；
- [ ] 无超出证据的能力声明；
- [ ] 用户批准发布或明确“未发布”；
- [ ] 空壳形式已回溯，复审触发已登记；
- [ ] 文档复审日期与过时项已登记。

## 9. 交付反模式

- 把临时脚本放在仓库根或 `docs/`；
- 在产品代码里硬编码路径/版本；
- 复制文档内容而不链接唯一出处；
- 用“CI 绿”替代未执行的验收；
- 把交叉编译/静态推断当作运行验证；
- 用采用率、星数、版本号证明质量。
