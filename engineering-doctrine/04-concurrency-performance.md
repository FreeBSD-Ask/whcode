# 04 并发与性能工程

本文件处理两个最容易“看起来很快、实际上不可维护”的领域：内存/CPU 优化与多线程并发。
核心规则：**并发设计先行，绝不原型先行**；**汇编是例外，不是常规手段**。

## 1. 适用范围

- 新增或修改线程、任务调度、锁、无锁结构、内存序、共享缓存、异步运行时；
- 任何以降低内存或 CPU 为目标的优化；
- 任何汇编、SIMD intrinsics、外部 C/ASM 符号或平台专用指令；
- 性能基准、容量规划与资源上限调整。

不适用：单线程纯函数重构、仅文档改动、不改变运行时行为的格式化。

## 2. 并发设计先行

### 2.1 禁止原型先行

多线程与并发**不得**以“先写个原型跑跑看”为起点。原型先行会把偶然可运行误当成正确性，
把数据竞争、内存序错误与活锁藏到生产环境。设计未通过 G2 前，不得提交生产并发代码。

允许且要求的“先行”活动：

- 纸面分析、状态机与不变量推导；
- 非执行模型（TLA+、Alloy、Petri 网等）；
- 小模型可执行验证（Loom/Shuttle 的模型代码，不算生产原型）；
- 基线测量（只测现状，不实现目标并发设计）。

### 2.2 文献门槛

设计前至少研读 3 篇**一手来源**（论文、标准、权威手册），逐篇记录：

1. 结论；
2. 适用条件；
3. 与本案的差异；
4. 可借鉴的约束；
5. 反例或失败条件。

冲突结论必须写明取舍与验证方式。引用必须可定位（作者、标题、年份、DOI/URL/版本），
不得只写“业界通常”。

推荐基线（按设计类型选用）：

- Herlihy & Shavit, *The Art of Multiprocessor Programming*；
- Michael & Scott (1996), 非阻塞队列；
- Vyukov (2010), bounded MPMC queue；
- Boehm (2012), seqlock 与内存模型；
- Batty et al. (2011), *Mathematizing C++ Concurrency*；
- Rust Nomicon、`std::sync::atomic`、Loom 文档。

### 2.3 并发设计档案（G2 必交）

| 字段 | 要求 |
|---|---|
| 问题与边界 | 并发发生在哪、共享什么、哪些状态不共享 |
| 不变量 | 任何交错下都必须成立的条件，逐条可判定 |
| 线性化点 | 每个操作的原子可见点；无法定义者说明原因 |
| 内存序 | 每个原子操作的 ordering 及理由；不得默认 `SeqCst` 了事 |
| 进展保证 | wait-free/lock-free/blocking 的分类与最坏情况 |
| 数据所有权 | 谁创建、谁释放、谁借用；生命周期如何跨线程 |
| 失败模式 | 竞争、活锁、饥饿、ABA、伪共享、缓存行抖动、栈溢出 |
| 验证计划 | Loom/Shuttle 模型、压力测试、差分测试、TSAN/其他工具、测量条件 |
| 回退方案 | 出问题时如何退回单线程或更保守实现 |
| 文献依据 | §2.2 的记录与取舍 |
| 复审触发 | 线程数、负载、平台、依赖版本变化时何时重审 |

完成判据：不变量与进展保证可判定、验证计划可执行、回退方案可操作。不以页数或工时衡量；
“设计一百年”不等于无限期分析。

### 2.4 验证

- 小模型优先用 Loom/Shuttle 穷举交错；模型覆盖真实状态机；
- 压力测试记录线程数、数据规模、运行时长与失败复现方式；
- 差分测试：新实现与保守实现（单线程/粗锁）在同一输入下结果一致；
- 不得以“跑了几小时没崩”作为正确性结论。

## 3. 内存与 CPU 优化

顺序固定，不得跳步：

1. **测量**：固定夹具，记录环境/参数/采样窗口，给出 p50/p95/p99 与资源曲线；
2. **定位**：热点、分配次数、缓存未命中、锁竞争、线程/句柄增长；
3. **建模**：说明瓶颈机制与预期收益，给出可证伪假设；
4. **设计**：算法/数据结构层面的替代优先于微优化；
5. **实现**：一次只改一个变量，保留可回退提交；
6. **复测**：同夹具前后对比，报告收益、代价与副作用；
7. **归档**：测量条件与结论进入证据目录，预算变更走 ADR。

禁止：无基线优化、只报平均值、单次样本结项、“感觉更快”。

## 4. 资源纪律

- 内存、CPU、GPU、线程、句柄必须可测量；
- 新增固定占用（每会话/每连接/每前端）必须经 ADR；
- 队列、缓冲、缓存必须有容量上限与上限测试；
- 文件、套接字、线程、事件句柄遵循 RAII，并有释放测试；
- 普通代码禁止 `unsafe`；禁止 `mem::forget` 与用 `Box::leak` 规避生命周期；
- 长时泄漏用时间序列监控，不以单次 RSS 代替斜率。

## 5. 汇编例外

仅当同时满足下列条件时允许：

1. 有可复现测量证明确实是热点，且安全语言/算法优化已排除或不足；
2. 有独立 ADR 批准，写明指令集、ABI、平台范围与回退；
3. 代码隔离：独立 crate/模块；普通代码继续保持零 `unsafe`；
4. 安全包装：对外只暴露安全函数，前置条件、对齐、长度、生命周期在包装层校验；
5. 回退路径：非目标架构/禁用 feature/校验失败时走安全实现；
6. 差分测试：汇编路径与安全路径在相同输入下结果一致；
7. 安全评审：越界、未初始化、栈对齐、ABI、侧信道、可执行内存风险逐项记录；
8. 可复现构建：汇编器版本、参数与产物哈希记录在依赖记录中。

## 6. 反形式主义

- 并发档案不是文档表演：字段必须能改变实现或验证方案；
- 文献研读必须写出“与本案的差异”，否则视为未读；
- 汇编不是性能银弹：没有测量与差分测试的汇编优化一律拒绝；
- 优化必须回答“代价由谁承担”，不得只看吞吐提升。
