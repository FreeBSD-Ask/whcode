# 工程哲学与开发准则（可移植版）

本目录是 WHCode 项目工程方法论的独立、可移植版本，不依赖 WHCode 的代码、crate、平台或
技术栈，可直接复制到其他项目，作为需求、设计、并发、安全、UI 与交付规则的基线。

**本目录也是形式主义**：它只有在改变决策、产物或门禁时才成立；若只剩口号，应按
`00-philosophy.md` §9 删除或降级。

## 1. 适用场景

- 新项目立项、建立仓库规则与 AI 代理开工说明；
- 现有项目补充需求工程、设计评审、并发/性能、安全、UI 或交付规范；
- 为多个项目提供同一套可审计的工程语言。

不适用：一次性脚本、无协作的单文件实验、只需要库 API 说明的任务。

## 3. 最小采用步骤

1. 将本目录复制到目标项目（建议 `engineering-doctrine/` 或 `docs/engineering/`）。
2. 复制 `templates/AGENTS.template.md` 为项目根的 `AGENTS.md`，替换 `<PROJECT>` 等占位符。
3. 至少阅读 `00-philosophy.md`、`01-process.md`、`02-requirements.md`、`03-design.md`、
   `07-delivery.md`。
4. 用 `templates/spec.template.md`、`tasks.template.md`、`checklist.template.md` 建立首个迭代；
   用 `templates/adr.template.md` 记录架构决策。
5. 按 `07-delivery.md` 的 PR 清单与门禁命令做首次审计。

## 4. 采用级别

| 级别 | 内容 | 适用 |
|---|---|---|
| 最小 | `00` + `01` + `AGENTS.md` | 小团队、早期项目 |
| 标准 | `00`–`03` + `07` + 模板 | 多数长期项目 |
| 完整 | 全部文件 + 并发/安全/UI 专项 | 有并发、网络、UI 或合规要求的项目 |

## 5. 使用原则

1. **先读现有规则**：目标项目已有约定时，先对齐，不要另起一套；冲突处按 `00` §9 处理。
2. **只裁剪，不减证据**：可以不做完整 G0—G5，但不得用“项目小”跳过验证与记录。
3. **以可复现事实为准**：本目录与目标项目代码/测量冲突时，事实优先；更新本目录或开 ADR。
4. **不复制结论，复制方法**：示例中的平台、指标、工具是案例，不是普遍承诺。
5. **保留来源**：复制时保留 `NOTICE.md` 与 BSD-2-Clause 许可。

## 6. 维护

- 每次修订本目录，递增日期并在 `NOTICE.md` 记录变更；
- 每年至少一次复审，删除已成为空壳的条目；
- 任何条目若无法回答“它改变了哪个决策/门禁”，即视为形式主义，删除或降级。
