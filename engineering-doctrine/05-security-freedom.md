# 05 安全、自由与主体性

安全不是“最佳实践清单”，而是特定威胁模型下的和解；自由不是功能，而是不可外包的边界。

## 1. 威胁模型（每项安全措施必填）

```text
资产：        （数据、凭据、密钥、可用性、声誉）
对手：        （谁、能力、动机、入口）
攻击面：      （网络、文件、进程、依赖、用户输入、供应链）
信任边界：    （哪些组件/服务/用户被信任，为什么）
现有控制：    （认证、授权、隔离、加密、审计）
残余风险：    （控制失效后的影响）
证据：        （测试、审计、复现命令、日志）
代价：        （可用性/性能/隐私/维护成本）
失效条件：    （平台/版本/负载变化时何时重评）
复审触发：
```

没有威胁模型的“安全措施”视为合规表演。

## 2. 安全反教条

- “最佳安全实践”“行业标准”“检查清单”不能替代威胁分析与可复现验证；
- 每项措施必须写明代价与失效条件；不得只写“更安全”；
- 默认拒绝、最小权限、回环监听、敏感信息脱敏、凭据不落日志是常见起点，不是永恒教条；
- 安全与可用性冲突时，必须显式记录取舍与批准人；
- 不以“后续补”关闭安全缺口。

## 3. 默认值

- 网络服务默认只监听回环地址；
- 远程访问默认要求认证，禁止空口令/默认口令；
- 权限默认最小化，按需申请，可撤销；
- 追踪/日志默认脱敏；完整内容记录必须显式开启并警告；
- 凭据不进入日志、事件、错误消息、测试夹具、提交内容；
- 外部命令/脚本默认隔离运行，不进入主进程。

## 4. 秘密与供应链

- 凭据只存本地受控位置，不入库；仓库提供 `.env.example` 而非真实值；
- 依赖锁定版本，记录来源与哈希；升级必须审查变更与许可；
- 构建脚本与第三方二进制必须有来源、校验和与可复现步骤；
- 禁止从不可信来源下载并直接执行脚本；
- 发布产物记录依赖清单与构建环境。

## 5. 日志与可观察性

- 日志分级，生产默认不记录正文与凭据；
- 错误消息对用户可操作，对攻击者不泄露内部路径/堆栈/密钥；
- 审计记录不可静默删除；关键操作记录 actor、时间、对象、结果；
- 指标是局部证据，不是“全知”；未知与盲区显式标注。

## 6. 自由与退出权

- 用户可随时停止使用并带走全部数据；
- 提供完整导出/备份；导出格式开放、可读、可再导入；
- 核心能力可离线使用；不得以强制联网/账户作为使用前提；
- 默认值可见、可改、可撤销；
- 退出、导出、删除入口与进入路径同样可见，不得藏到三级菜单；
- 禁止私有格式锁定、隐藏导出、强制账户、强制联网、暗黑模式。

## 7. 反暗黑模式与反成瘾

- 不预选付费/订阅/遥测；
- 不隐藏取消按钮，不做虚假紧迫感；
- 不做排行榜、连胜、签到、推送轰炸；
- 用户拒绝某功能后不得反复纠缠；
- 失败提示指向可执行下一步，不评价用户人格；
- 安全提示给出威胁与代价，不以恐吓要求服从。

## 8. 反苦难与用户友好

- 不以 RTFM、加班、牺牲作为设计或贡献证据；
- 文档提供入口与“跑路”路径，不责怪新用户；
- 错误信息说明“发生了什么、为什么、下一步做什么”；
- 默认显示进度与可取消；不把“沉默是金”当默认；
- 维护者的长期投入是主体性体现，不渲染“牺牲”或“英雄”。

## 9. 不伪造与未知显式

- 工具、模型与代理不得编造命令结果、文件内容、外部事实或史料；
- 未知、失败、不可验证必须标 `unknown`/`[待验证]`；
- 模型生成内容不得作为唯一证据；关键结论必须回到一手来源；
- 工具输出保留原始来源与可复现命令；
- 不以“看起来合理”替代证据。

## 10. 事件响应

1. 记录：发现时间、影响范围、已知事实、未知项；
2. 隔离：停止扩大影响，保留证据；
3. 修复：最小必要变更，走 G3；
4. 复盘：区分事实与推测，不编造“必然原因”；
5. 更新：威胁模型、测试、文档、复审触发；
6. 公开：已知限制与影响，不隐瞒。

## 11. 安全检查清单

- [ ] 每项措施有威胁模型、证据、代价、失效条件；
- [ ] 默认回环/认证/最小权限/脱敏；
- [ ] 凭据不入库、不进日志与事件；
- [ ] 依赖锁定、来源与哈希可查；
- [ ] 退出/导出/离线核心能力可用；
- [ ] 无暗黑模式、成瘾机制、责怪用户文案；
- [ ] 不伪造结果，未知显式；
- [ ] 安全结论未被“最佳实践/合规”替代。
