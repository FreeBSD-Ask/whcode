# ADR-016 M0 有条件收口与 V-004/V-006 延后

**状态**：已批准（用户 2026-10-21 同意“按这个方案来”）
**日期**：2026-10-21 | **相关**：ADR-010、ADR-011、ADR-013、ADR-015、`artifacts/m0-report.md`

## 背景

M0 的 Windows 工程交付已取得构建、依赖记录、数据库冒烟、TUI 逻辑层、写者原型与基线测量证据。
但 V-003 的人工交互项、V-004 的服务端验收、V-006 的预算冻结未收口，导致“M0 整体通过”无法成立。
继续把 M0 悬置为“未通过”会阻塞 M1，并让后续里程碑缺少稳定基线。

## 决策

1. **Windows 工程基线判定为“有条件通过”**：工程侧 Go；正式通过仍以 V-003 人工证据为前置。
2. **V-003 保持“未通过”**：新增 `docs/guides/tui-manual-smoke.md` 人工协议；未取得 resize 与
   Ctrl-C 的真实终端记录前，不得改写为通过。
3. **V-004 延后至 M7**：依据 ADR-011/ADR-013，SSH 服务端与四平台客户端证据不在 M0 交付；
   客户端原型（回环测试）不等于节点验收。
4. **V-006 预算不冻结**：候选值只作参考；冻结条件仍是固定夹具、分平台分位数、测量纪律字段、
   72 小时时间序列与偏差记录（`docs/matrices/platform-matrix.md`）。
5. **允许进入 M1**，但所有对外表述必须写“M0 Windows 工程基线有条件通过”，不得写“M0 通过”。

## 条件与复审

| 项 | 条件 | 复审触发 |
|---|---|---|
| V-003 | 按人工协议取得 resize 与 Ctrl-C 记录 | 人工记录归档后 |
| V-004 | M7 服务端与节点证据 | M7 启动时 |
| V-006 | 72 小时 + 分平台数据齐备 | 预算冻结评审 |

## 后果

- README、M0 报告与平台矩阵统一为“有条件通过”；逐平台结论不变；
- M1（T032—T045）可启动，但性能声明仍只能引用候选值；
- 不得用“有条件通过”替代任何未取得的证据；条件未满足时自动退回“未通过”。
