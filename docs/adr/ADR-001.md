# ADR-001：一个工作区默认对应一个 DuckDB 数据库文件

- **状态**：已批准（M0 批准，2026-10-21；tasks.md T029 / V-007）
- **来源**：《WHCode 技术任务书 v3.0》§2 冻结前提（原状态"建议冻结"）
- **责任人**：架构负责人（存储与数据边界）；落地维护：`whcode-store` 维护者
- **退出条件**：M1 完成单库 schema、迁移与写者服务并通过 V-104/V-106 后复核；若需引入第二个默认持久化后端，必须先有新 ADR 批准（任务书封面约束、§9.1）
- **批准依据**：任务书 §2 冻结前提与 `specs/001-whcode-harness/spec.md` Assumptions 的 D-02；`data-model.md` 以 `workspace_meta` 作为版本源；`plan.md` C-01/C-02；`artifacts/deps-windows.txt` 的依赖树中仅存在 DuckDB 一个持久化后端。

## 决策

一个工作区默认对应**一个** DuckDB 数据库文件。默认不按会话分库。

## 理由与约束

任务、事件、消息、产物、检查点可在**同一事务边界**中更新；暂不引入分库和全局索引双写。
未经 ADR 批准不得增加第二个默认持久化后端（任务书封面约束）；不得以某平台构建困难为由静默
切换默认后端（§9.1）。

## 替代方案

- 按会话分库（v2.0 原方案）：被 §0.3-2 否决——任务、事件与检查点之间会出现跨库事务边界。
- 分布式/多库 + 全局索引双写：引入双写一致性风险，且当前规模无此需求。

## 影响

- 约束 crate：`whcode-store`（写者服务与事务边界）。
- 门禁：`plan.md` C-01/C-02；宪法原则 I。
- 数据模型：`specs/001-whcode-harness/data-model.md`（`workspace_meta` 为版本源）。
