# ADR-026：GUI 必须原生，禁止浏览器套壳

- **状态**：已批准（2026-10-23，用户决定；铁律级约束）
- **来源**：用户指令（2026-10-23，“严禁浏览器套壳，必须原生”）；FR-601（TUI）、
  FR-603（Web 独立前端）、FR-609（Web 业务操作）；ADR-014（极简前端）、ADR-013
  （Windows 11 amd64 唯一验收平台）；NFR-212（默认不创建 GPU 上下文）、NFR-215
  （零 `unsafe`／资源纪律）
- **责任人**：UI 与前端负责人（边界维护）；GUI 实现者待需求立项后指定
- **退出条件**：仅在用户**明确撤销**本条时失效；撤销须新 ADR 并写明套壳方案带来的
  常驻资源、供应链与攻击面代价，不得以“开发快”单独立项

## 决策

1. **禁止浏览器套壳**。桌面 GUI 不得以内嵌浏览器引擎承载界面，包括但不限于
   WebView／WebView2、CEF、Tauri／wry、Electron、NW.js，以及“自带 JS 引擎 + DOM
   实现”的等价形态。任何 PR 引入上述依赖作为桌面界面即违反本条。
2. **Web UI 的定位不变**。`whcode-web` 仍是**独立**前端：用户用系统浏览器访问
   `http://127.0.0.1:PORT/`（FR-603、ADR-004、ADR-014）。把该页面塞进原生窗口
   ——即使窗口是本项目自绘的——同样属于套壳，不在允许范围内。
3. **GUI 若实现，必须原生**：使用平台原生控件或自绘渲染，自行承担主题
   （`amoled-night`／`eink-day`／`eink-night` 三套精确色值）、i18n／RTL、无障碍与
   输入法；资源按 NFR-201—212 测量，默认不创建 GPU 上下文，最小化／不可见期间
   停止绘制并释放资源（FR-617 同口径）。
4. **GUI 当前不在验收范围**。`spec.md` 没有 GUI 类 FR；新增 GUI 必须**先**立需求
   （新 FR 或正式需求变更）与实现 ADR，附正负和解、资源预算、主题与无障碍方案、
   三端能力矩阵扩列，再写代码。不得以“先做出来再补需求”倒推。
5. **原型同样受约束**。不得以“仅作原型”为由引入套壳依赖后进入发布包或事实标准；
   原型与发布物同一形态边界。

## 理由（正负和解）

- **正面**：不引入第二套运行时（浏览器引擎、JS 引擎、网络栈与自动更新通道），
  没有浏览器版本漂移与随之而来的 CVE 面；常驻内存、进程数与句柄数可控；
  与“资源占用优先”“最小供应链”“零 `unsafe` 包装”一致；界面语义由本项目完全掌握。
- **负面**：实现成本显著高于套壳——布局、文本排版、滚动、输入法、无障碍、
  高 DPI 与三套主题都要自己做；Windows 之外暂无验证环境（ADR-013），
  自绘方案在 BSD 上的可用性没有证据。
- **承担者**：GUI 实现者与长期维护者；等待桌面形态的用户。
- **和解理由**：套壳省下的是实现时间，付出的是**常驻资源与不可控渲染语义**；
  本项目的硬约束是资源优先，且已明确“前端能多简陋就多简陋”（ADR-014）。
  在 TUI／CUI／Web 三端已可用的前提下，GUI 是增量体验而非生存需求，
  因此不接受用资源与供应链换取短期速度。

## 替代方案（已否决）

- **Tauri／wry／WebView2 壳**：常驻 WebView 进程与系统 JS 引擎，默认走 GPU 合成，
  且依赖系统 WebView 版本的渲染差异；与 NFR-212 及资源铁律冲突。
- **Electron／NW.js**：在依赖中同时引入 Chromium 与 Node 运行时，体积与内存代价最大。
- **自绘窗口 + 内嵌 Web UI**：形态上是“自己的窗口”，实质仍是浏览器引擎承载界面，
  按第 2 条判为套壳。
- **以浏览器 Web UI 冒充桌面 GUI**：不是原生，且无窗口、托盘、文件对话框等系统集成。

## 影响

- 未来任何 GUI 提案必须以“原生渲染／原生控件”为前提；ADR 需给出所选框架的资源
  测量（空载 RSS、空闲 CPU、线程与句柄数）与回退路径。
- `AGENTS.md` §1 硬边界、§6 UI 纪律、§8 禁止事项同步登记；`decisions.md` 新增 D-15。
- 当前无 GUI 代码，故无代码变更；不新增 FR 与检查点，`checklist.md` 计数不变。
- 与 ADR-014 的关系：ADR-014 约束 Web 前端“能多简陋就多简陋”，本条约束桌面形态
  “不许借浏览器”，两者共同限定前端边界。

## 复审触发

1. 用户明确撤销本条（须新 ADR，附代价分析）；
2. Windows 11 原生控件在输入法、无障碍或高 DPI 上出现无法克服的缺陷（须附复现步骤
   与替代原生方案的评估）；
3. 明确的 GUI 需求成立，但资源测量证明所有原生方案都无法满足冻结预算——
   此时的正确动作是**重新评估需求**或修订预算，而不是改用套壳。
