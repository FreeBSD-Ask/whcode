# ADR-086：规则权威层级——公理最高，AGENTS 为入口，软件工程理论为方法论

- **状态**：已批准（2026-11-17；用户指令：公理是最高，AGENTS.md 是入口和目录，
  软件工程理论是哲学和方法论）
- **来源**：2026-11-17 用户指令；ADR-085（公理表与三阶段求值）；ADR-045（研究不承载承诺）；
  `docs/guides/axiom-system.md`（45 条公理目录）；`docs/guides/coherence-audit.md`（可执行片段）
- **责任人**：过程门禁维护者、文档维护者
- **退出条件**：见 §8

## 1. 问题与边界

规则分散在 `AGENTS.md`、`specs/`、`docs/adr/`、`docs/guides/` 与标准文献中。此前只有
一条模糊口径：`AGENTS.md` 自述为入口，冲突时“以那些文档为准”；但那些文档之间谁更高、
标准与方法论在冲突中处于什么位置，没有写。后果是同一冲突可以按不同文件得出不同结论，
而“按标准/最佳实践”又常被拿来绕过公理与证据（违反 A1、A6）。

边界（非目标）：

- 本 ADR 不新增任何硬边界、平台承诺或资源预算；
- 不把方法论文档（`software-engineering-process.md`、`philosophy.md`、标准基线）升格为
  判据；它们仍是来源与解释，不是仓库事实的裁定者；
- 不改变 ADR、spec、指南的具体条款；只规定冲突时的优先级。

## 2. 决策

1. **L0 公理（最高）**：`specs/001-whcode-harness/coherence/axioms.toml` 的 `COH-` 条目与
   `docs/guides/axiom-system.md` 的 45 条目录。条款与公理冲突时，**以公理为准并修订条款**；
   新增硬约束必须能归入公理，或在公理表登记（不可判定项走 `registered`）。
2. **L1 规则正文**：`specs/`、`docs/adr/`、`docs/guides/` 的具体条款与门禁脚本。它们是公理
   的实例与执行；彼此冲突时按“具体条款优于概述、ADR 优于指南、事实优于叙述”。
3. **L2 `AGENTS.md`（入口与目录）**：只列必读路径、命令与完成定义，不复制正文、不作最终
   裁定；与正文冲突时以正文为准，正文与公理冲突时以公理为准。
4. **L3 软件工程理论（哲学与方法论）**：`software-engineering-process.md`、`philosophy.md`、
   `standards-baseline.md` 与 ISO／IEEE 文献。为公理提供来源、解释与复审理由；不直接裁定
   仓库事实，其结论转化为公理或条款后才生效（ADR-045 口径）。不得以“最佳实践／合规”
   替代公理与证据（AGENTS §1.2 冲突判定）。
5. **冲突判定顺序**：L0 ＞ L1 ＞ L2；L3 只在解释与复审中使用，不参与事实裁定。公理自身
   冲突时，按 A2（可证伪）与 A8（可修订）走 ADR 修订公理表，不得静默择一。
6. **程序判定**：权威层级在 `AGENTS.md`、`docs/guides/axiom-system.md`、
   `docs/guides/coherence-audit.md` 与本 ADR 四处声明一致，由公理 `COH-M1-06` 在 `pre`
   阶段判定；声明漂移即红灯。

## 3. 正负和解

- **正面**：冲突有唯一裁定顺序；公理从“审计对象”变成“最高条款”；AGENTS 的入口定位不再
  被误解为“AGENTS 说了算”；方法论被明确为来源而非挡箭牌。
- **负面**：（i）公理表本身若写错，错误会获得最高优先级；（ii）L3 不参与裁定，意味着标准
  更新不会自动改变仓库判定，需要显式转译；（iii）多一层声明，文档维护成本上升。
- **承担者**：公理维护者承担“公理正确性”的责任；规则修订者承担“条款与公理对账”的成本；
  用户在公理冲突时承担裁决。
- **和解理由**：此前的散落补正（Check 465、Check 462、traceability 反向覆盖）都源于没有
  裁定顺序；把顺序写死并用门禁判定，比每次靠记忆与语境推断便宜。负面（i）由 A8（可修订）
  与 ADR 修订流程承担；（ii）由 `standards-baseline.md` 的复审触发承担。

## 4. 三重时间

- **过去**：2026-10-21 起 AGENTS 自述为入口；2026-11-14 标准基线建立（ADR-072）；
  2026-11-17 分析文档给出 A1—A9 与四档可判定性，ADR-085 把它落成可执行公理表。
- **现在**：本 ADR 规定 L0—L3 与冲突顺序，并由 `COH-M1-06` 在 `pre` 阶段校验四处声明一致。
- **将来**：公理表被证明持续写错、或 L3 的转译需求频繁到阻碍工作，则复审层级划分（§8）。

## 5. 可判定判据与撤回条件

| 判据 | 绑定命令 | 不满足时 |
|---|---|---|
| 四处声明含“权威层级”“公理最高”“入口与目录”等关键表述 | `python .github/scripts/coherence.py --phase pre`（`COH-M1-06`） | 红灯，修声明 |
| 公理表条目仍能归入 A1—A9／M／R／H | `python .github/scripts/coherence.py --phase pre`（`COH-M1-01`） | 红灯，补归组或走 ADR |
| 方法论文档未宣称自己是判据 | `python .github/scripts/check-docs-style.py`＋人工抽查 | 记录并修订表述 |

撤回条件：若公理层在连续两个批次中被证明无法裁定实际冲突（每次都需回到条款），则本 ADR
降级为指南条目，恢复“ADR／spec 优先”的旧口径并在 ADR-085 留修订记录。

## 6. 标准与一手文献研读

沿用 `docs/guides/standards-baseline.md` 与
`research/standards-alignment/notes/formal-coherence.md`：29148 的“一致、可验证”、
15026-2 的 claim→argument→evidence、42010 的对应关系均支持“先定层级再判满足”。
本 ADR 不新增标准引用，也不宣称合规。

## 7. 已知限制

1. 公理是 2026-11-17 的重构，不是原文；层级只解决“谁优先”，不解决“公理是否写对”。
2. L3 不参与裁定，标准更新不会自动生效；转译缺口由 `standards-baseline.md` 复审触发承担。
3. `AGENTS.md` 仍是代理实际读取的入口，入口若缺失指向，层级声明本身看不到——因此
   `COH-M1-06` 把 AGENTS 也纳入断言。
4. 本 ADR 不覆盖用户自由与安全底线的例外：涉及这些底线时，用户批准仍高于一切文档
   （A9、AGENTS §1.2）。

## 8. 失效条件与复审触发

- **绑定命令**：`python .github/scripts/coherence.py --phase pre` 报 `COH-M1-06` ⇒ 四处声明
  漂移，先修声明再谈其他判定。
- **事件**：公理表新增条目无法归入 A1—A9／M／R／H ⇒ 复审 L0 的组划分。
- **事件**：连续两个批次出现“按 L3 标准与按 L0 公理得出相反结论且用户选择 L3” ⇒ 复审
  层级顺序，并按 A8 修订公理。
- **事件**：`docs/guides/axiom-system.md` 的 45 条目录与 `axioms.toml` 的组名再次出现同名
  不同义且未加前缀 ⇒ 复审两者的编号纪律（ADR-085 §8 同口径）。
