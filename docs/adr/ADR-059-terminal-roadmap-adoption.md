# ADR-059: 终态功能路线全量采纳——proposal-v3 全部 45 提案（不计实现成本口径）

- **状态**：**已批准（2026-11-07，用户指令）**——用户原话“批准所有不计成本的，最佳建议方案”，
  即 [research/synthesis/proposal-v3.md](../../research/synthesis/proposal-v3.md) 的 W1—W7 全部
  45 条提案与决策请求 D10—D15 全批（含各条的默认建议）。
- **日期**：2026-11-07
- **关联**：`research/synthesis/proposal-v3.md`（批准对象）、`research/dsh-comparison/`（19 域证据）、
  `research/zcode-comparison/`、`research/better-harness/`、`research/synthesis/README.md`；
  将被修订的既有 ADR：ADR-044/048/050/051/052/053/054/055（执行与互操作各条）、ADR-025/037
  （治理门禁）、ADR-046（复审触发）；**NFR-211（D13 修订对象）**；不放宽：ADR-026（原生 GUI）、
  ADR-013（平台范围）、NFR-215（零 unsafe）。

## 问题

1. **研究齐备但缺决策载体**：四份外部研究（ZCode 16 域、BH、DSH 19 域、三方综合）的可借鉴集
   已整理为 45 条提案，但“要不要做”没有一份已批准的路线锚点；不落账则每个批次都要重新请求批准，
   且无法防止范围漂移。
2. **“不计成本”与宪法的边界需要书面裁定**：开发 effort 不设限是用户口径，但资源铁律
   （NFR-211“每会话不加常驻线程”）、零 unsafe、原生 GUI 是用户已批准的宪法级约束；
   PTY/jobs 与 NFR-211 的冲突必须显式裁决，不能默许违宪。
3. **45 条一次性入册是巨型台账变更**：FR/tasks/Check 计数一致性（`check_counts.py`）风险高，
   且多提案需先立/修订 ADR（G2 先于 G1），一次性入册会制造一批“有 FR 无 ADR”的悬空需求。

## 决策

1. **全量采纳**：proposal-v3 的 W1—W7 共 45 条提案全部批准为路线项；其 §5 的 9 条反建议维持
   “不做”；§6 的 Phase 0—4 依赖序有效。批准的是**路线与范围**，不是“立即同时开工”。
2. **决策请求逐项裁定**（全部按 proposal-v3 §8 的默认建议批准）：
   - **D10**：P1.1 四态审批类型先行——`AllowedOnce/Rejected/Cancelled/Unavailable` 封闭枚举，
     T255 实施前定类型；审批请求只带 `exec_id` 不复制参数。
   - **D11**：P1.2 模型生成摘要——带失败回退（回退到现行结构折叠）与单次摘要成本上限。
   - **D12**：P5.1 shell 工具立项——**威胁模型先于代码**；审批 broker（P1.1）是前置。
   - **D13**：NFR-211 修订方向批准——由“每会话不加常驻线程”改为“常驻资源有上限常量＋空闲可
     回收＋释放测试”；**修订落 `specs/` 走 G1 门禁并同步 ADR-025/033 关联登记；修订未落地前
     P5.4（PTY）/P5.5（jobs）不得开工**。
   - **D14**：P6.1 SDK 最小协议＋主版本升级策略（不可逆决策，已知情批准）。
   - **D15**：P7.1 覆盖率 90% 试点（`whcode-app`/`whcode-store`），2027-05-07 复审。
3. **批次化入账（G1 纪律）**：批准≠一次入册。每批次开工前按 proposal-v3 §9 的门禁映射把该批的
   FR（FR-760+ 号段届时重编号）/tasks/Check 入 `specs/001-whcode-harness/`，并满足
   `traceability.py`/`check_counts.py` 全绿；**本 ADR 是路线层的 G0 载体，不替代逐批 G1 入账**。
4. **硬边界零例外**：本 ADR 不放宽零 unsafe（NFR-215）、原生 GUI（ADR-026）、本地优先/默认无
   遥测、平台范围（ADR-013）任何一条；P5.1/P5.2/P6.3/P6.4 实施前必须先交威胁模型
   （安全反教条，宪法 1.3-6）。
5. **并发纪律**：P1.8（steer 通道）/P5.4（PTY）/P5.5（jobs）/P6.1（SDK 流）实施前各交
   ADR-015 全字段并发设计档案；档案未批不开工。
6. **成本口径**：230—330 人日总账为知情基准；单条目实际超出预算 1.5× 即触发复审（同
   proposal-v3 §10.5），复审可缩范围、可追加预算，但不得静默超支。

## 正负和解

- **正面**：45 条能力获得可追溯的批准锚点，批次开工免重复请求；宪法冲突（D13）被显式裁决；
  反建议清单锁定，防止“对齐冲动”回潮；路线与证据链（四份研究）双向可查。
- **负面**：230—330 人日的长线承诺，台账与 ADR 数量显著增加；NFR-211 修订放松一条既有铁律
  （补偿：上限常量＋空闲可回收＋释放测试，且修订前 P5.4/P5.5 冻结）；路线绑定上游快照
  （DSH 0.2.x 迭代极快，判定可能过时）；Phase 2—4 的批准先于其详细设计（各条实施前仍需
  批次认知卡与 ADR）。
- **承担者**：实施批次负责人（逐批入账、取证、预算纪律）；路线维护者（复审触发监控、上游变更
  同步）；门禁维护者（计数一致性、layout/layering 不回退）。
- **和解理由**：批准的价值在把“要不要做”（已定）与“何时做、怎么验证”（仍按依赖与证据推进）
  分离；符合“知难行易”——方向已由用户裁定，手段在每批次认知卡中后置选择。
