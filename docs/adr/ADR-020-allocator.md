# ADR-020：分配器决策

- **状态**：已批准（2026-10-22，M9/T117）
- **来源**：D-11（全局分配器默认使用 Rust 系统分配器，仅当基准证明有益后才改变）；
  R-11（性能实现原则：不将自定义分配器作为普遍优化手段）。
- **责任人**：性能负责人（M9）
- **退出条件**：若 M9 后续基准（T115，须先冻结预算）证明热点分配可由替换分配器
  显著改善（≥10% 且 RSS 无回归），本 ADR 须复审。

## 决策

1. 全局分配器**默认使用 Rust 系统分配器**（不引入 mimalloc/jemalloc）；
2. 任何分配器替换必须先满足：D-06 性能预算冻结 → T115 热点测量定位 → 基准证明
   有益（同夹具前后对比）→ 本 ADR 修订；
3. 容器优化（SmallVec/ArrayVec）同样仅在基准数据支持时采用（R-11）。

## 理由

- D-11 已冻结此方向；引入分配器替换是全局行为变更，须以测量而非主流共识为依据
  （宪法 §I 形式主义、反进步叙事）；
- `memory_limit` 只约束 DuckDB 缓冲管理器，不代表进程 RSS（AGENTS.md §4.1）——
  分配器替换的收益/风险必须以 NFR-201—204 的 RSS 测量为准，而预算未冻结（阻塞）。

## 替代方案（已否决）

- **默认引入 mimalloc/jemalloc**：被 D-11 与 R-11 否决（未测量先行）。
- **按 crate 局部替换分配器**：全局性风险相同，收益未证明。

## 影响

- 当前零分配器依赖（workspace 无 global_allocator 覆盖）；
- T115（性能优化）在其前置（预算冻结、基准数据）就绪前保持阻塞；
- 长时泄漏斜率归 NFR-204 稳定性测试（T116，需 24/72h 长跑，阻塞）。
