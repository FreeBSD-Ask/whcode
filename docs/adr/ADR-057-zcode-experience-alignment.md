# ADR-057: GUI／Web 与 ZCode 全量体验对齐（含视觉层）

- **状态**：**已批准（2026-11-05，用户“全部批准”）**——2026-11-05 用户指令立项
  （“图形界面、web界面 要和 zcode 对齐，开启新计划书”），口径经四问确认：范围＝
  ZCode 全量体验；判据＝全面体验对齐（含视觉）；端序＝双端同批小步推进；落点＝
  001 内计划书（`specs/001-whcode-harness/plan-ui-zcode-alignment.md`）。
- **日期**：2026-11-05
- **关联**：ADR-026（原生 GUI 铁律，不放宽）、ADR-027（GUI 选型与预算，不放宽）、
  ADR-032（对等判据，本 ADR 修订其视觉条款）、ADR-044／048（turn 循环／工具系统）、
  ADR-056（GUI 交互对等，本 ADR 的直接前置）、`research/zcode-comparison/`（证据基线）。

## 问题

1. **体验差距**：四端功能对等（ADR-056 收口）后，GUI／Web 在对话流呈现、工具调用卡、
   审批交互、todo／任务面板、子代理／技能／MCP 面板、diff 形态上仍与 ZCode 有可见差距；
   用户与潜在迁移者感知到的是“能做”与“好用”的距离。
2. **判据缺口**：ADR-032 明确“视觉、交互形态不作为对等判据”，导致体验层差距无法被
   追溯体系表达（无 FR 可立、无 Check 可判），只能停留在研究文档。
3. **主题层缺口**：现行四套主题（amoled-night／eink-day／eink-night／terminal-green）
   面向墨水屏与 OLED 场景，无与 ZCode 视觉语言对齐的常规日／夜主题。

## 决策

1. **对等判据修订（限定范围）**：在“GUI／Web 对 ZCode 体验对齐”范围内，视觉语言与
   关键交互形态（对话流、工具卡、审批流、diff）升级为对等判据；TUI／CUI 与其余范围
   仍按 ADR-032 五维（业务能力、权限、状态迁移、错误语义、可审计性）。ADR-032 追加
   修订记录指向本条。
2. **主题层扩展（主题保证铁律，2026-11-05 用户补遗）**：新增 `zcode-day`／`zcode-night`
   两套主题，精确色值由批次 R 从 ZCode 基线（`local/zcode-src`，commit `3c5b227`）提取并
   冻结后写入 AGENTS.md §6 与主题清单；默认主题是否切换由用户单独批准（默认值可见可改
   可撤销，宪法 §1.3）。**既有四套主题的保证不可稀释**：`amoled-night` 纯黑背景
   `#000000`、`eink-day`／`eink-night` 的墨水屏口径（真灰判据 R=G=B、避免大面积中间灰
   与渐变）、`terminal-green` 纯黑＋`#00FF00`，其精确色值、可用性与语义在视觉对齐全程
   不得被替换、重定义或视觉漂移；zcode 主题是**新增**而非覆盖。锚点：
   `crates/whcode-gui/src/lib.rs`（Theme 枚举）、`crates/whcode-web/src/assets.rs`
   （THEMES＋hex 断言测试）。
3. **视觉 token 单一事实源**：色板／间距／字号／圆角／层级 token 一处定义，GUI 与 Web
   派生同一来源，一致性由契约测试断言（受校验产物模式，同 feature-parity 矩阵）；
   token 派生对既有四套主题**零影响**——四套主题的色值断言测试必须保持通过，
   任何 token 重构不得改写其渲染结果。
4. **渲染约束（预算与铁律不放宽）**：GUI 用 iced＋tiny-skia 原生文本能力＋最小自绘
   markdown 集，禁 WebView／HTML 渲染（ADR-026 零例外）；Web 用服务端直出＋原生 ESM
   ＋WS 增量（ADR-014），无 JS 降级保留；双端维持 ADR-027 与前端预算（JS ≤ 50 KB
   gzip、CSS ≤ 20 KB、DOM ≤ 2000 节点；GUI 空闲 RSS ≤ 96 MB、线程 ≤ 24、句柄 ≤ 256、
   CPU ≤ 0.2%），超线即复审渲染方案，不设灰区。
5. **安全与自由约束**：工具参数／输出与对话正文入 UI 一律经既有 redacted 管线；
   会话分享＝本地脱敏导出文件，无上传／联网；扫码登录／OAuth 仅评估登记不承诺
   （禁强制账户／联网）；预览机制（CDP＋Playwright）倾向不采纳，结论以 FR-753 登记；
   新视图只读经 `StoreViewSource`，后台执行沿用 ADR-056 Phase 2 连接共享语义，
   单连接唯一写路径（Check 98）不变。
6. **批次框架**：R（侦察＋token 提案）→ B1（对话流核心）→ B2（会话／任务管理 UI）
   → B3a（审批 broker 后端，另立 ADR 或修订 ADR-048）→ B3b（工具卡＋审批 UI）
   → B4（高级面板）→ B5（协作＋收尾）；每批 GUI＋Web 同批交付（FR-610 纪律），
   全项验收过才结题（详见计划书 §3）。

### 会话分享导出威胁模型（T261／FR-752，2026-11-11）

- **资产**：会话元数据（标题／模型／阶段）、任务清单（标题／验收条件）、事件载荷（含对话正文）。
- **威胁**：①分享者误以为“导出＝完全安全”，把自由文本中的秘密带出；②目标路径覆盖既有文件或
  写到非预期位置；③分享包在传输/存储中被篡改；④工具偷偷联网上传；⑤包体过大拖垮内存。
- **措施**：事件载荷固定经 `whcode_llm::trace::sanitize` 的 `redacted` 级处理（不提供 `full`
  选项）；包内注明 `trace_level`／`redacted`；`sha256` 覆盖规范 JSON 主体（键排序＋紧凑编码），
  用于完整性核对；目标已存在即拒绝，写入走同目录临时文件＋`sync_all`＋`rename` 原子替换；
  实现只用 `std::fs` 与只读库查询，无网络栈调用；事件 ≤ 2000 条、主体 ≤ 16 MiB，超限显式
  `truncated` 或拒绝写盘。
- **残余风险**：标题、任务标题／验收条件与事件正文是自由文本，脱敏只按字段名与已知令牌模式
  识别，**不能保证自由文本中的秘密被发现**；分享者须自行复核。`sha256` 只证明内容未变，不是
  签名，不能证明来源；文件离开工具后不受本仓库策略约束。
- **失效条件与复审触发**：若增加 `full` 级、上传/回传或云端分享，必须另立 ADR 并重做威胁
  模型；若 `trace::sanitize` 的字段/模式词表变化，重跑
  `share_bundle_redacts_secrets_and_self_verifies` 并复核本节。

## 理由与约束

- ZCode 是用户实际在用、可对照的标杆（证据层级第 1 层：`local/zcode-src` 源码）；
  以它为体验基准使“好用”从主观叙事变为可勘察、可登记、可判定的清单。
- 体验对齐不改后端能力边界：后端缺口（审批 broker、检查点回滚执行）作为前置工作
  单元显式立项，禁止 UI 批次伪造可用性（信号链完备：交付＝信号存在，不是界面存在）。
- 约束：不改验收平台与平台承诺（ADR-013）；不放宽零 unsafe、有界性、资源铁律
  （NFR-215—217）；i18n 双语同批与 RTL 口径（FR-615／625）适用于所有新 UI。

## 替代方案

- **只做功能对等（维持 ADR-032 原判据）**：零判据冲突，但体验差距永不可判定，与用户
  指令直接相悖——否决。
- **单端先行（Web 或 GUI）**：迭代快，但违反 FR-610 同批纪律、拉大对等债，用户已明确
  双端同批——否决。
- **新建 specs/00X 独立账本**：计数独立、隔离干净，但本轮范围仍属 001 主线的体验
  收口，分裂账本徒增追溯成本——否决（若后续膨胀可再议）。
- **视觉对齐＝引入成熟前端栈（如嵌入 WebView 渲染 markdown）**：违反 ADR-026 铁律
  与资源预算——否决。

## 影响

- **正面**：体验差距进入追溯体系（FR↔任务↔Check）；GUI／Web 获得常规日／夜主题；
  ZCode 用户迁移成本降低；审批交互补齐代理循环的最后人机缺口（域 C 勘察落地）。
- **负面**：六批工程量与持续预算压力；ADR-032 判据双轨制（GUI／Web 视觉入判据，
  TUI／CUI 不入）带来登记复杂度；视觉对齐随 ZCode 演进漂移，需要复审机制维持。
- **承担者**：GUI／Web 维护者（实现与预算）、B3a 后端维护者（broker）、用户
  （默认主题变化，可撤销；批次批准节奏）。

## 正负和解

正面（体验闭合、可判定化）与负面（工程量、漂移、双轨复杂度）的和解方式＝
**分期小步＋每批全绿结题＋预算审计自动化＋ZCode 基线失效条件绑定复审**：
大范围被拆成独立可交付、可中止的批次；漂移风险用“基线 commit 变更→复审勘察”
的绑定命令兜住，而非承诺一次对齐永久对齐。视觉判据只入 GUI／Web 范围，是因为
视觉对齐的成本承担者（iced／Web 维护者）与收益者（桌面与浏览器用户）重合；
TUI／CUI 用户不承担其不受益的成本。

## 复审触发（绑定命令＋判定）

- `python .github/scripts/check-frontend-budget.py` 任一项超线 → 复审该批渲染方案
  （判定：脚本退出码非 0 即触发）。
- desktop 预算探针（weekly schedule 任一 run）RSS／线程／句柄／CPU 任一失守 →
  复审 GUI 渲染选型并对照 ADR-027 预算（判定：探针报告任一字段超阈值）。
- `cargo test --locked -p whcode-tests --test frontend_parity` 失败 → 复审登记表、
  矩阵与 token 一致性（判定：测试失败即触发）。
- `cargo test --locked -p whcode-gui`／`cargo test --locked -p whcode-web` 中**主题色值
  断言**失败 → 复审视觉 token 与主题层改动（判定：任一 hex 断言失败即触发；批次 R 起
  该断言升级为覆盖六套主题的双端契约测试，见 FR-739）。
- ZCode 基线演进：`local/zcode-src` HEAD commit ≠ `3c5b227` 且 UI 相关差异清单非空 →
  复审批次 R 勘察与视觉 token（判定：勘察文档头部的基线 commit 字段比对）。
- 每批合并后 `python .github/scripts/traceability.py` 或 `python .github/scripts/check_counts.py`
  不一致 → 当批不得结题（判定：脚本退出码非 0 即冻结该批 Check 勾选）。
