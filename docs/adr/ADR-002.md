# ADR-002：DuckDB 写入通过单一应用层写者服务串行化

- **状态**：已批准（M0 批准，2026-10-21；tasks.md T029 / V-007）
- **来源**：任务书 §2（原状态"建议冻结"）、§7.3
- **责任人**：应用服务与存储负责人（写者服务为唯一写入路径）
- **退出条件**：M1/T034 写者服务完成并通过 V-105/V-106；批次阈值与执行上下文按 TBD-03 以基准校准（校准不改变单一写者决策）
- **批准依据**：`crates/whcode-store/src/writer.rs` 的 10 例原型测试与 `crates/whcode-app/src/queue.rs` 的 4 例队列测试在 `cargo test --workspace` 中通过；`Cargo.lock` 中 DuckDB 仅经 `whcode-store` 引入。

## 决策

所有数据库写入经**单一应用层写者服务**串行化：有界队列 + 幂等键 + 批量提交 + 写入结果确认。

## 理由与约束

便于有界排队、批量事务、顺序编号、去重与审计。这是 **WHCode 的应用策略**，不是 DuckDB 唯一
允许的并发方式（[S1]）。约束：队列必须有界且定义满载语义；关键事件提供显式 flush/提交确认；
事务成功后才向调用方返回持久化确认（§7.3）。

## 替代方案

- 连接池并发分发写入：被 ADR-002 与 §5.4 否决——DuckDB Rust `Connection` 为 `Send`、非 `Sync`，
  不得无锁共享同一连接给多个线程（[S5]）。
- 各模块自行写库：被 ADR-003 与宪法原则 II 否决。

## 影响

- 约束 crate：`whcode-store`；所有写入路径必须经写者服务。
- 基线参数：批量阈值 500 行 / 50 ms（可配置，M0/M1 基准校准，FR-503）；`threads` ≤
  `min(4, 可用物理核数)`。
