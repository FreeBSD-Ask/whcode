# ADR-025：性能预算冻结（Windows 11 amd64）

- **状态**：已批准（2026-10-23；冻结范围为 Windows 11 amd64，未测项保持候选）
- **来源**：D-06、NFR-201—NFR-210、V-006、SC-021、Task T027／T028／T055；
  ADR-010（平台承诺）、ADR-012（192 MB 过渡基线）、ADR-013（唯一验收平台）
- **责任人**：性能与存储负责人（决策）；基准夹具维护者（执行与归档）
- **退出条件**（任一触发即复审）：取得首个 BSD 原生运行证据；DuckDB 引擎或关键查询计划
  发生版本级变化；完成 5.5 小时时间序列（ADR-033）；用户环境基线与冻结夹具显著偏离（如逻辑核数、
  可用内存、持久化介质变化）

## 决策

1. **冻结范围**：预算只在 **Windows 11 amd64**（`x86_64-pc-windows-msvc`）上作为发布门槛。
   BSD 无运行证据，**不参与**冻结，平台矩阵标注“未验证”，不得与他平台合并或平均。
2. **冻结值沿用 spec 候选值**（NFR-201—210），不因实测偏低而放宽：实测优于预算即视为达标；
   劣于预算则进入优化待办，**不得修改预算掩盖**。修订预算须另立 ADR 并附同夹具前后对比。
3. **冻结依据**为固定夹具与归档证据（下表“证据”列，均在 `artifacts/` 内可复现）。
4. **未测项保持“候选”**：NFR-201／202／203／205／206／209 尚无合规测量，登记责任人与
   退出条件（发布前补齐，或按第 2 条以 ADR 修订），不得以“未复现失败”代替测量。
5. `memory_limit`（192 MB）仍是 DB 缓冲管理器的过渡基线（ADR-012），**不等于**进程 RSS 预算。

## 历史基线（不构成冻结）

- `artifacts/baseline-windows-amd64.json`（2026-10-21 05:40 UTC）：写入吞吐中位
  **158 条/秒**，聚合 p95 12 305 µs。该样本低于 NFR-210 候选值，已在平台矩阵登记偏差；
  其后同夹具优化（写者改为分块查键 + 分块多行插入、插入前分配连续 `seq`）在 384 MB 组
  达到 3 359 条/秒、192 MB 当前口径达到 6 921 条/秒。三次结果**不得**合并平均，
  冻结采用 192 MB 当前口径，历史值保留以备回归对照。

## 理由（正负和解）

- **正面**：把“未冻结”的长期模糊状态收敛为可判定的发布门槛；两项已达标的预算立即
  可用于回归拦截；未测项有责任人与退出条件，避免“看起来达标”。
- **负面**：Windows-only 冻结会让 BSD 用户缺少本平台的性能承诺；按 spec 候选值冻结
  可能偏严，后续开发会被较紧的预算拦住。
- **承担者**：性能负责人（补齐未测项）、后续功能开发者（受预算约束）、BSD 用户
  （无预算承诺，只有“未验证”标注）。
- **和解理由**：先用唯一验收平台把口径锁死，比维持“候选”更有用；偏严可通过
  ADR 修订放宽，而“无预算”无法被任何门禁拦截。

## 修订记录

- **2026-10-24（稳定性窗口，ADR-033）**：NFR-204 的稳定性窗口由 72 小时改为 **5.5 小时**
  （19 800 s、300 s 采样；CI 手动长跑 `.github/workflows/long-run.yml`）。24/72 小时深检保留为可选的
  self-hosted／本机运行，不再作为 CI 门槛。冻结预算值（≤ 0.5 MB/h）不变。
- **2026-10-24（NFR-203 证据更正，预算值不变）**：原表“0.32 MB”的测量含夹具缺陷——
  `tests/fixtures/gen_dataset.rs` 的第二个会话实际插入 0 条事件（循环上界误用绝对
  `events`，应为 `seq_base + events`），“10 万事件 ×2 会话交替切换”不成立。修正夹具并
  强化断言（尾部恒 50 条、截断标记、游标覆盖最新事件、尾部只属目标会话、概览行存在）后
  复跑：两会话各 10 万事件、20 次交替切换最大 RSS 增量 3.18 MB（同日另一复跑 1.16 MB），
  均 ≤ 10 MB。冻结预算与结论不变，仅更正证据与测量口径。
- **2026-10-24（DuckDB 2.0.0 引擎级复审）**：引擎由 1.5.6 升至 2.0.0 LTS，`duckdb.dll`
  由 36 697 896 字节增至 61 311 784 字节。复测结果：NFR-201 中位 **35.07 MB**（p95 35.12／
  峰值 35.29，199 样本；独占复跑 35.14），原 35 MB 预算不可达；NFR-202 中位 39.26 MB（≤80）、
  NFR-203 最大增量 0.32 MB（≤10）、NFR-205 0.156% 单核（≤0.5%）、NFR-206 0.337% 单核（≤8%）、
  NFR-207 p95 9.1 ms（≤200 ms）、NFR-209 独占复跑 p95 22.0 ms（≤30 ms）、NFR-210 release
  中位 4 054.6 条/秒（≥2 000）。据此仅把 **NFR-201 修订为 ≤36 MB**（+1 MB，仍为紧预算；
  修订决策、前后对比与复审触发见 **ADR-035**），其余冻结值不变。理由不是“把回归当达标”：
  1.5.6 的 23.12 MB 基线是在更小 DLL 下取得的，
  2.0 的常驻开销属引擎级变化；36 MB 覆盖 p95 与峰值，且保留“若后续 DLL/依赖减小则恢复
  35 MB”的复审触发。NFR-210 相对 1.5.6 的 6 921 条/秒明显下降（约 41%），仍高于 2 000
  条/秒门槛，登记为优化观察项。NFR-207/NFR-209 改为 `#[ignore]`，由 stability workflow
  以独立步骤独占执行；全 workspace 测试并行时实测 NFR-209 p95 45.8 ms，不具可归因性。

## 替代方案（已否决）

- **继续维持“未冻结”**：V-006／SC-021 永远无法判定，回归无参照。
- **按实测值反向冻结（如 158 条/秒）**：把一次未优化的样本固化成标准，等于用
  现状掩盖性能缺口。
- **等 BSD 与 72 小时数据齐备再冻结**：ADR-013 已把 BSD 移出验收范围，长跑又受环境
  阻塞；无限等待会让预算永远缺位。

## 影响

- Check 133（预算经 ADR 修订／冻结）与 136／55（概览 p95 ≤ 冻结预算）**可判定**；
- Check 195（十项预算各有分平台实测记录）**仍不通过**：只有 NFR-208／210 达标，
  其余六项未测、两项缺合规测量；
- Check 115／243 的优化工作**仍阻塞**于热点定位与全项测量，本 ADR 不放宽其前置条件。
