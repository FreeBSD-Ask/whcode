# ADR-061：品牌资产（logo／窗口图标／favicon／ASCII 字标）

- **状态**：**已批准（2026-11-07，用户指令“把 logo.svg 按规则放置，并作为 WHCode 的图标，
  cli tui 下用 ASCII 图”）**
- **日期**：2026-11-07
- **关联**：ADR-014（前端零构建链）、ADR-026（原生 GUI）、ADR-027（GUI 框架与资源预算）、
  ADR-028（内置字体：同样是“生成物入库”的先例）、ADR-046（复审触发的绑定命令口径）、
  `docs/guides/repository-layout.md`（资源目录分类）、`crates/whcode-domain/src/brand.rs`。
- **范围边界**：只解决“主标志放哪、以什么形态进入四个前端”。**不做**：视觉改版、
  新增品牌衍生品（安装包图标、托盘图标、社交卡片）、多语言字标、动画。

## 问题

1. **主标志没有归处**：用户提供的 `logo.svg`（1080×1080，92 KB）停在仓库根目录，
   而根目录白名单只允许工程清单与标准开源文件（`test_layout` 强制）。放在根上会被门禁
   判红，放在 `docs/` 又不属治理文档。
2. **四个前端没有身份标记**：GUI 窗口用系统默认图标、Web 无 `/favicon.ico`（且现有测试
   把 `/favicon.ico` 断言为**必须 404**）、CUI 与 TUI 完全没有识别标记。
3. **直接塞原图不可行**：GUI 与 Web 都不得为一张图标引入图像解码依赖（NFR-215）；
   Web 首屏预算（ADR-014）也不允许把 92 KB 的 SVG 当图标下发。
4. **终端形态不能机械派生**：该 logo 是位图封装的古籍版面（黄底竖排 + 水印），实测
   64/88/96/100 列降采样后只剩噪点，认不出品牌——ASCII 形态必须另行设计。

## 决策

### 1. 母版归位

- 唯一母版：`assets/brand/logo.svg`（作者创作，BSD-2-Clause），`assets/brand/SOURCES.md`
  记录来源、许可、SHA-256 与**位图封装结构**（两个内嵌 PNG + 两个 `<use>` 偏移）。
- `assets/` 既有分类是 `fonts/`、`certs/`；`brand/` 是**新增资源类型**，按 repository-layout
  的口径须有 ADR——本 ADR 即该载体，同批更新该指南的 `assets/` 行。
- 根目录不再保留 `logo.svg`（不计入根白名单）。

### 2. 位图派生：生成期完成，产物入库

`.github/scripts/make-brand-assets.py` 从母版派生两种二进制形态，**运行期零解码依赖**：

| 产物 | 消费方 | 形态 |
|---|---|---|
| `crates/whcode-gui/assets/brand/icon-64.rgba` | GUI 窗口图标 | 64×64 原始 RGBA，`include_bytes!` 直接交给 `window::icon::from_rgba` |
| `crates/whcode-web/frontend/favicon.ico` | `/favicon.ico` | ICO，16/32/48 三帧 |

- 脚本解 `--check`：重算并与入库字节比对，不一致即非零退出（可接 CI，不需 pillow 之外的依赖）；
- 脚本**按 `<use>` 偏移合成两层**，层缺失或结构不符时显式报错退出，**不回退**到“只取
  第一层”（静默生成缺字的图标比失败更坏）；
- Web 路由白名单由“六路径”扩为“七路径（含 `/favicon.ico`）”，原“`/favicon.ico` 必须
  404”的断言同批翻转为“必须可达且非空”。

### 3. 终端形态：手工字形常量

`whcode-domain::brand::ASCII_LOGO`（47 列 × 8 行，纯 ASCII，语言中立）：

- **CUI**：`whcode doctor` 人类可读输出顶部打印一次；`--json` 分支**不打印**
  （机器可读信封不混装饰行）。
- **TUI**：两处落点（用户 2026-11-07 选择“两者都要”）——①`run_with` 进入全屏界面前向
  stdout 打印一次（留在滚动历史，不占帧、不参与重绘，故不触碰 T129 空闲零重绘）；
  ②空态视图内显示字标 + 空提示，**放不下就只显示空提示**（不裁切、不顶掉空态语义）。
- stdout 被重定向（管道、日志）时不打印，避免污染机器可读输出。

## 正负和解

| 面向 | 正面 | 负面（代价） | 承担者 |
|---|---|---|---|
| 归位 | 母版有唯一位置，来源与许可可考，根白名单不被破坏 | `assets/brand/` 成为新资源类型，需要本 ADR 与指南同步 | 仓库维护者 |
| 生成物入库 | 运行期零解码依赖；图标不随首屏预算增长；字节级可复现 | 产物是二进制，diff 不可读；母版改了必须重跑脚本（`--check` 兜底） | 改母版的人 |
| 窗口图标 | 原生 GUI 有身份（ADR-026 前提下不引入浏览器壳） | 多 16 KB 静态二进制体积 | GUI 维护者 |
| favicon | 浏览器不再 404，标签页可辨识 | 原“必须 404”的测试断言必须翻转（否则门禁自相矛盾） | Web 维护者 |
| ASCII 字标 | 四个前端齐备；纯 ASCII 宽度可预测，不依赖宽字符处理 | 8 行启动输出会进入滚动历史（可被重定向抑制）；字标是**另设计**的，不是 logo 的精确描摹 | 终端用户／前端维护者 |

## 三重时间

- **过去来源**：ADR-028 已确立“生成物入库 + 生成脚本 + SOURCES 记录”的先例（字体子集）；
  repository-layout 已确立“新增资源类型需 ADR”；ADR-014 已禁止前端构建链。
- **现在证据**：`test_layout` 对根文件的枚举会拒绝根上的 `logo.svg`；Web 既有测试把
  `/favicon.ico` 断言为 404；GUI `window::Settings` 未设置 `icon`；TUI/CUI 无品牌输出。
- **将来失效条件**：Actions/安装包需要额外的品牌形态（托盘、安装器图标）时扩展本节；
  母版改为矢量重制（不再是位图封装）时，派生脚本的合成步骤可整体删除——那不属于本 ADR
  的失效，而是**简化**；若某前端引入统一的图标管线（如系统级 .desktop 条目），本 ADR
  的“运行期零解码”约束仍适用。

## 已知限制

1. **不是矢量**：母版是位图封装，图标质量上限等于降采样质量；放大必然糊。
2. **不承诺跨机字节一致**：pillow 重采样随版本变化，`--check` 失败先比对 pillow 版本。
3. **ASCII 字标不是 logo 描摹**：它是手工字形表（`WHCODE` 块字形 + 定位说明），与位图
   母版只有“同一产品”的关系，没有像素对应。
4. **favicon 只有 16/32/48 三帧**：高 DPI 标签页由浏览器上采样，未提供 256 帧。
5. **TUI 启动横幅不可配置**：当前无 `--no-banner` 开关；重定向即静默（脚本场景已足够）。

## 复审触发（绑定命令＋判定）

1. `python .github/scripts/make-brand-assets.py --check` 非零退出 → 产物与母版漂移，
   复审本 ADR 与 `assets/brand/SOURCES.md`（判定：是母版变更还是 pillow 版本变化）。
2. `cargo test -p whcode-domain brand::` 失败 → 字标尺寸契约（47 列 × 8 行）被破坏，
   复审 TUI 空态与本文档的尺寸声明。
3. `cargo test -p whcode-web assets::` 失败 → favicon 路由白名单与断言不一致。
4. `python .github/scripts/benchmarks/check-frontend-budget.py`（涉及 `frontend/` 时）失败 →
   图标是否被误计入首屏预算。
