# ADR-006：原始事件持久化与实时广播分离

- **状态**：已批准（M0 批准，2026-10-21；tasks.md T029 / V-007）
- **来源**：任务书 §2（原状态"必须冻结"）、§4.2 事件可靠性分级
- **责任人**：应用服务（事件路由与队列）负责人
- **退出条件**：M1/M3 完成持久化与广播分离并通过 V-103/V-104；实现与文档不得出现“自动原子双写”表述
- **批准依据**：`crates/whcode-app/src/queue.rs` 的 4 例有界队列测试（关键条目背压、快照丢弃计数）在 `cargo test --workspace` 中通过；`whcode-domain::PersistenceLevel` 与 `contracts/event-schema.md` 已定义分级。

## 决策

原始事件**持久化**与**实时广播**分离：广播队列可丢弃/合并可重建的低优先级快照；持久化队列按
事件等级提供不同的背压与确认语义。

## 理由与约束

两类可靠性诉求互斥：广播面向在线消费者、容许合并；持久化面向审计与恢复、关键事件不得丢失
（§4.2 分级：关键／内容／展示快照）。**禁止**把"实时广播 + 数据库写入"描述为自动原子双写；
实现必须明确事件何时被确认持久化，并处理两种半态——"广播已发出、写入失败"与"写入已成功、
客户端未收到"。

## 替代方案

- 单队列同时承载广播与持久化：无法同时满足低延迟与不丢失，且会诱使实现宣称不存在的原子性。
- 以分布式事务保证广播与写入原子：广播目标为消费者集合，不存在对应事务参与者（§0.3-8）。

## 影响

- 约束 crate：`whcode-app`（事件路由与有界队列语义）、`whcode-store`（持久化确认）。
- 已有基础设施：`whcode_app::BoundedQueue`（关键条目背压 / 快照丢弃计数）。
- 契约：`contracts/event-schema.md` §3–§4。
