# ADR-023：Web 服务仅限局域网 + 认证边界

- **状态**：已批准（2026-10-22，用户指令："web 仅限局域网"）
- **来源**：FR-606（对外监听必须显式认证与 Origin 检查）；V-110 默认仅回环；
  批次 4（Web 部署面补全）
- **责任人**：Web 适配层负责人
- **退出条件**：若需公网暴露（反向代理/隧道），必须重新评估传输加密（TLS）、
  会话有效期与速率限制，本 ADR 失效；当前实现**不承诺**公网安全。

## 决策

1. **地址边界**：`serve --web --bind` 只接受
   - 回环（`127.0.0.0/8`）：无认证，V-110 默认；
   - **RFC1918 私网 IPv4**（`10/8`、`172.16/12`、`192.168/16`）：**必须**同时提供
     `--token-file`（启用认证与 Origin 检查）。
   - 其他地址（公网 IP、`0.0.0.0`/通配）一律拒绝启动，错误援引本 ADR 与"仅限局域网"。
2. **凭据传递**：token 只从**文件**读取（`--token-file PATH`），不接受命令行参数
   （避免进程列表/日志泄漏，§10.2）；不写入日志与事件。
3. **浏览器凭据**：Token 经 URL **fragment**（`#token=…`）传入页面——fragment 由浏览器
   本地保存、**从不发送给服务器**（不同于 query，§10.2 禁止 query token）；前端在
   内存中保存并以 `Authorization: Bearer` 头调用 `/api/*`。
4. **Origin 允许集**（认证模式）：`http://<bind-ip>:<port>`、
   `http://localhost:<port>`、`http://127.0.0.1:<port>`（按 scheme+host，端口参与端口
   匹配，见 ADR-022 的 host 语义）。
5. **WebSocket**：认证模式下 WS 同样要求 `Authorization: Bearer`；浏览器无法为
   WebSocket 设置自定义头→**认证模式下列表页不使用 WS**（前端本就用轮询；T094）。
   未来如需浏览器 WS 认证，须新 ADR（子协议或 Cookie 方案）。

## 威胁模型与代价（正负和解）

- 防护目标：同网段未授权设备不得读取工作区数据（会话/事件/任务/状态）。
  局域网内攻击者可直接访问 `<ip>:<port>`，因此认证必须默认启用（非回环）。
- **不承诺**：公网暴露、TLS、暴力破解防护（token 长度由用户负责，建议 ≥32 字符随机）；
  ARP/DNS 欺骗不在本层处理范围。
- 代价：token 文件需用户自行生成与保管；URL fragment 会留在浏览器历史（本机泄露风险
  与"本机已登录"同级）；局域网广播/组播不隔离（用户须信任所在网络）。
- 失效条件：网络不可信（公共 Wi-Fi）、需要跨网段访问、需要多用户审计隔离——这些
  场景必须改用带 TLS 与账户体系的反向代理方案（本 ADR 不适用）。

## 影响

- `whcode-web::bind`：新增 `is_lan(addr)` 与地址边界拒绝（公网/通配）；
- `whcode-bin` 的 `serve --web`：新增 `--token-file`；LAN 绑定强制认证；
  计算 Origin 允许集并传入 `api::handle_request`（签名新增允许集参数）；
- `frontend/app.js`：从 `#token=` 读取凭据并附加 `Authorization` 头（内存保存）；
- 验证：`bind` 策略单测；curl 无/有 token（401/200）；浏览器 LAN 页面加载；
  证据 `artifacts/web-lan-2026-10-22-batch4.txt`。
