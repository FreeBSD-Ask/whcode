# ADR-009：功能对等按业务能力定义，不按视觉交互定义

- **状态**：已批准（M0 批准，2026-10-21；tasks.md T029 / V-007）
- **来源**：任务书 §2（原状态"必须冻结"）、§4.6 三端对等定义
- **责任人**：三端与 SSH 接口负责人
- **退出条件**：M5 交付 `docs/matrices/feature-parity.md`（T087）并通过 V-109 契约测试；新能力须同 PR 更新矩阵、API/CLI 行为、权限与测试
- **批准依据**：`spec.md` §4.6 与 FR-610；`contracts/app-service.md` 规定四端统一语义；`tests/contract/test_layering.rs` 已落实分层前提；三端对等契约测试尚未实现。

## 决策

三端（TUI/CUI/Web）与 SSH 入口的功能对等，按**业务能力**定义：相同业务能力、权限检查、状态迁移、
错误语义与可审计性必须一致；交互形态可不同（CUI 输出 JSON、TUI 使用键盘、Web 使用浏览器组件）。

## 理由与约束

以界面外观或终端画面判断对等，会掩盖权限与状态语义的真实分叉。约束：三端共用功能能力矩阵
（FR-610）；新能力的 API、CLI 行为、权限与测试必须同 PR 定义；任一端产生的更改须在其他在线端
可见（FR-605）。

## 替代方案

- 以"功能列表/截图"作为对等验收：不可程序化验证，且无法发现权限差异。
- 要求三端视觉一致（例如 Web 复刻 TUI 键盘交互）：被 §4.6 明确否决。

## 影响

- 约束 crate：全部前端；矩阵文档 `docs/matrices/feature-parity.md`。
- 验收：V-109、Check 143。

## 修订记录（2026-10-24）

- 对等判据在原五维（业务能力、权限检查、状态迁移、错误语义、可审计性）基础上细化，
  并补充**差异资格**：GUI 只读 v1（`GUI_READ_ONLY_V1`）、CUI 命令面
  （`CUI_COMMAND_SURFACE`）、视图面（`VIEW_SUMMARY_ONLY`）、本地管理命令
  （`CLI_LOCAL_ADMIN`）与保留命令（`RESERVED_MILESTONE`）等差异必须以稳定理由码登记，
  不得以隐性假设或自由编辑的矩阵表述——五维判据、四态判定表与理由码全表见
  `docs/adr/ADR-032-frontend-parity-and-intended-differences.md`（D-17）。
- 对等范围由“三端 + SSH”扩展为 CUI／TUI／GUI／Web 四端 + SSH；SSH 仍为独立传输入口
  （`TRANSPORT_SPECIFIC`），不参与视图／命令对等判定；判据本身（五维）不变。
- 能力矩阵（`docs/matrices/feature-parity.md`）由自由编辑改为登记表受校验产物；
  预留／排除能力被调用时返回结构化 `not_supported`（CUI 退出码 55／Web HTTP 501），
  不得伪装成 404 或静默成功。
- 本节为适用边界的当前口径；上文历史正文不改，以修订记录为准。
