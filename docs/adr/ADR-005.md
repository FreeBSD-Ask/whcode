# ADR-005：SSH 是独立传输入口，复用应用服务

- **状态**：批准（2026-10-21 部分批准 → **2026-11-03 转正**：选型、TOFU、FreeBSD/NetBSD 回环与服务端四项证据、真实 sshd 互操作证据均已取得；V-004 跨机口径归 M7 里程碑工作——详见修订记录）
- **来源**：任务书 §2（原状态“必须冻结”）、D-04
- **责任人**：SSH 入口负责人
- **退出条件**：M7 完成服务端与客户端交付，并取得 FreeBSD/NetBSD 服务端验收 + 四平台客户端连通性/命令执行证据（V-004 修订判据见 ADR-011）；服务端实现选型（TBD-05）须在 M0 原型后定案
- **批准依据**：`crates/whcode-ssh/src/proto.rs` 已实现客户端风险原型并按“意图—执行—登记”登记；`crates/whcode-ssh/src/lib.rs` 明确服务端尚未实现；ADR-011 将 OpenBSD/DragonFly 移出原生安装目标；V-004 目前无四 BSD 运行证据
- **未决条件**：服务端实现选型（自研 `russh` 服务端或系统 `sshd` 受限子系统）；FreeBSD/NetBSD 服务端与四平台客户端运行证据；原型的主机密钥校验恒接受（已知中间人风险，M7 必须补齐）
- **未决项处置（2026-10-24 修订）**：按 ADR-013 将 BSD 与 M7 整体延后，三项未决条件转为“M7 启动时一次性结清”：① 选型已定（ADR-030：自研 russh 服务端）；② 服务端与四平台客户端证据随 M7 验收（进程内测试已交付，BSD 证据仍未取得）；③ 主机密钥恒接受阻断项**已结清**——`proto.rs` 已接入 known_hosts 风格信任文件校验（TOFU，`<workspace>/ssh/known_hosts`，不匹配即结构化拒绝，见 ADR-030 §4.5）。复审触发：M7 验收、或用户要求恢复任一 BSD 平台（须新 ADR）。

## 决策

SSH 作为**独立传输入口**（传输适配器），复用同一应用服务；不允许每个 SSH 会话各自打开数据库
并直接写入。

## 理由与约束

前端不直连存储（ADR-003）在 SSH 场景同样适用；四类 BSD 上的认证、终端尺寸与断连语义须分平台
验证（V-004、R-02）。首版权限：公钥认证 + 受限 WHCode 交互入口，不默认授予任意系统 Shell
（FR-608、D-04）。

## 替代方案

- 直接复用系统 sshd 的受限子系统（`force-command`/`subsystem`）：优点是不自研认证栈；缺点是依赖
  各 BSD 版本行为差异，须实测。**保留为候选**（research.md R-06），M0 原型后定案。
- 自研完整 SSH 服务端：可完全控制会话隔离，但扩大协议实现面与审计成本；同样作为候选保留。

## 修订记录

- **2026-11-03（证据取得＋状态转正）**：三项未决条件逐条结清——
  ① **服务端选型**：ADR-030 定案（自研 `russh` 服务端，仅公钥认证、每连接独立会话上下文），
  不再悬置。
  ② **服务端与客户端运行证据**：FreeBSD 15.1 与 NetBSD 11.0 上
  `bsd_client_acceptance_loopback` 与 `bsd_server_acceptance_loopback` 均 GO
  （`ssh_loopback_gate = GO`；服务端四项＝公钥认证／会话隔离／resize／安全退出，
  客户端四项＝公钥认证／受限命令／输出上限／超时断连；
  `artifacts/ssh-acceptance/{freebsd,netbsd}-client.txt`，CI run `41481740766`／`41568982820`）；
  Windows amd64／ARM64 为真实 TCP 回环协议验收（含指纹不匹配拒绝）。
  另新增 **real-sshd 互操作**验收（`real_sshd_acceptance_loopback`）：对目标机**系统自带
  OpenSSH sshd**（真实进程、独立密钥对、真实 TCP 回环）验证公钥认证、通道执行、退出码
  映射、stderr 捕获、TOFU 记录、显式授权内容回传与超时终止——Windows 与 FreeBSD VM
  均实测 GO（run `41529766439` 日志、`41568982820` 证据 `real_sshd_gate = GO`，
  `sshd=/usr/sbin/sshd`、配置档 full）。该项为**记录型证据**（不并入 `ssh_loopback_gate`
  硬判定），稳定后再评估升门。
  ③ **主机密钥恒接受**：已于 ADR-030 §4.5 结清（known_hosts TOFU，不匹配即结构化拒绝），
  本轮 real-sshd 验收又给出正向复证（首次连接写入指纹）。
  ④ **V-004 跨机口径**：仍属 M7 里程碑工作（真实外部节点连通性），但按 ADR-013 修订
  （2026-11-03：NetBSD/OpenBSD/DragonFly 仅支持 SSH 远程开发，被 Windows/FreeBSD 内置
  客户端连入）其取得方式已定案——属里程碑验收项，**不再是本 ADR 的未决条件**。
  **正负和解**：正面＝SSH 入口的“独立传输、复用应用服务”原则有了跨实现证据（自研服务端
  回环 + 第三方 OpenSSH 互操作），TOFU 与受限入口不再是纸面承诺；负面＝跨机证据仍缺、
  互操作验收暂为记录型而非门禁——承担者＝SSH 入口负责人；和解理由＝先取得可复现的
  同机双实现证据，再谈跨机，避免把“没条件测”写成“已通过”。
  **三重时间**：过去＝2026-10-21 原则批准、2026-10-24 延后处置；现在＝FreeBSD/NetBSD
  回环 GO + Windows/FreeBSD real-sshd GO（run 41568982820）；将来失效＝`russh` 主版本
  变化、OpenSSH 配置档不再被接受、或用户恢复 BSD 原生通道（须新 ADR）。
  **复审触发**（绑定命令＋判定）：`sh .github/scripts/platform-matrix/bsd-ssh-client.sh`
  产出的 `ssh-acceptance/<platform>-client.txt` 中 `ssh_loopback_gate` 不再是 GO、或
  `real_sshd_gate` 连续两轮 NO-GO（非 SKIPPED），即复审本节。
