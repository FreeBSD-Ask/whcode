# ADR-005：SSH 是独立传输入口，复用应用服务

- **状态**：部分批准（M0 原则批准，2026-10-21；未决条件见下）
- **来源**：任务书 §2（原状态"必须冻结"）、D-04
- **责任人**：SSH 入口负责人
- **退出条件**：M7 完成服务端与客户端交付，并取得 FreeBSD/NetBSD 服务端验收 + 四平台客户端连通性/命令执行证据（V-004 修订判据见 ADR-011）；服务端实现选型（TBD-05）须在 M0 原型后定案
- **批准依据**：`crates/whcode-ssh/src/proto.rs` 已实现客户端风险原型并按“意图—执行—登记”登记；`crates/whcode-ssh/src/lib.rs` 明确服务端尚未实现；ADR-011 将 OpenBSD/DragonFly 移出原生安装目标；V-004 目前无四 BSD 运行证据
- **未决条件**：服务端实现选型（自研 `russh` 服务端或系统 `sshd` 受限子系统）；FreeBSD/NetBSD 服务端与四平台客户端运行证据；原型的主机密钥校验恒接受（已知中间人风险，M7 必须补齐）
- **未决项处置（2026-10-23）**：按 ADR-013 将 BSD 与 M7 整体延后，三项未决条件转为“M7 启动时一次性结清”：① 选型由 SSH 入口负责人在 M7 启动时二选一并记录 ADR；② 服务端与四平台客户端证据随 M7 验收；③ 主机密钥恒接受列为 **M7 阻断项**——在补齐主机密钥校验前，`whcode-ssh` 的客户端原型不得对外表述为可安全连接受信任网络之外的目标。复审触发：M7 启动、或用户要求恢复任一 BSD 平台（须新 ADR）。

## 决策

SSH 作为**独立传输入口**（传输适配器），复用同一应用服务；不允许每个 SSH 会话各自打开数据库
并直接写入。

## 理由与约束

前端不直连存储（ADR-003）在 SSH 场景同样适用；四类 BSD 上的认证、终端尺寸与断连语义须分平台
验证（V-004、R-02）。首版权限：公钥认证 + 受限 WHCode 交互入口，不默认授予任意系统 Shell
（FR-608、D-04）。

## 替代方案

- 直接复用系统 sshd 的受限子系统（`force-command`/`subsystem`）：优点是不自研认证栈；缺点是依赖
  各 BSD 版本行为差异，须实测。**保留为候选**（research.md R-06），M0 原型后定案。
- 自研完整 SSH 服务端：可完全控制会话隔离，但扩大协议实现面与审计成本；同样作为候选保留。
