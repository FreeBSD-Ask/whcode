# ADR-046：Check 证据五态登记与复审条件机制化

- **状态**：已批准（2026-10-29，用户批准建议书 D1：`research/synthesis/proposal.md` §7）
- **来源**：`research/better-harness/README.md` §3.1（Better Harness 证据五态，commit
  `b605532`）；`research/synthesis/README.md` §3 交叉发现 6/10；本清单证据类别复核（§1.3）
- **责任人**：checklist 维护者、追溯/计数门禁脚本维护者
- **退出条件**：态标注与复核事实脱节率经抽样超过 10%、或标注维护显著拖慢复核节奏
  （须另立 ADR 退回二值 + 日期制）

## 1. 事实与证据

1. `specs/001-whcode-harness/checklist.md` 现行 308 条 Check 为**二值判定**（`[x]` 通过 /
   `[ ]` 未通过），头部语义自述"每项可由'通过/不通过'二值判定"；勾选权归复核人。
2. **证据类别复核（2026-10-29，关键词启发式 + 人工抽样校验）**：308 条判据中约 67 条为
   纯"机制存在"级（存在/声明/登记/含）、约 58 条为接线级（调用/透传/消费）、约 125 条为
   行为断言级（测试可观察行为）、约 58 条含结果验证语言（实测/长跑/远端 CI/基线）。
   **等级差异在清单中不可见**——"目录存在"与"远端 CI 实测通过"同样呈现为 `[x]`。
3. Check 3 的复核叙事已经**隐式**呈现证据强度演进（未通过 → 接线 → 结构性阻塞 → 远端
   CI 首轮通过 → 缺口收口），但该语义不结构化，脚本不可解析、统计不可行。
4. Better Harness 证据五态（`Present`/`Wired`/`Exercised`/`Outcome-supported` +
   `Missing`/`Unobserved`/`Not applicable`）是本仓信号链完备原则（"配置的能力不是被观测
   的使用"，`docs/guides/signal-chain-completeness.md`）迄今最完整的机制化参照；
   其判定由 LLM 代理作出，**不满足本仓门禁程序化铁律**（AGENTS.md §5），只可吸收语义、
   不可吸收判定主体（`research/synthesis/proposal.md` §1.2）。
5. `check_counts.py` 以 `^- \[[ x]\] Check (\d+):` 解析条目——证据态标注必须置于编号与
   冒号**之后**，否则破坏既有门禁解析。

## 2. 决策

1. **Check 增加证据态标注**，状态枚举七值（标识符用英文，脚本可直接解析）：
   `present`（机制/判据已登记，未复核）、`wired`（验证路径已接通：有可执行命令/测试）、
   `exercised`（复核已实际执行并留痕）、`outcome-supported`（后续可比结果支持：长跑/
   远端 CI/复测）、`missing`（确认判据未满足/未实施）、`unobserved`（观察边界外，
   证据未取得且无法判定）、`not-applicable`（经检视证明不适用）。
2. **语法**：`- [x] Check N: [state] 判据（来源：…）——复核叙事`。态标注紧跟冒号后的
   判据正文之前；**无标注按 `present` 处理**（未复核初始登记）。`[x]`（勾选通过）的
   态**不得低于** `exercised`——"通过"意味着复核已执行留痕，仅"机制存在"不构成通过。
3. **门禁同步**：`check_counts.py` 新增证据态解析与校验（`[x]` 且态低于 `exercised`、
   或态值不在枚举内 → 门禁失败）；`traceability.py` 输出态分布统计（不阻断）。
   现有解析正则不受影响（态在冒号后）。
4. **迁移（一次性回填）**：292 条 `[x]` 按"默认 `exercised`，叙事含长跑/远端 CI/实测
   测量/基线达标证据者升 `outcome-supported`"回填；16 条 `[ ]` 逐条定态——平台证据与
   长跑未取得者（Check 22/25/96/99/116/195）标 `unobserved`，确认未实施/判据未满足者
   （Check 134、300—308）标 `missing`。回填脚本辅助生成 + 逐条人工确认，勾选权与
   改态权同归复核人。
5. **复审条件机制化**：此后新立 ADR 的"复审触发"节**优先写成"绑定命令 + 判定规则"**
   （命令失效或输出越界即触发复审），日期仅作辅助；存量 ADR 不回填（历史文档不改写，
   以可复现事实为准）。AGENTS.md §9 完成定义同步增补。
6. **边界**：证据态是**登记语义**，不是新的门禁判定器——通过/不通过仍由 checkbox 与
   既有脚本实施；LLM 不得修改态级（与勾选权同属复核人），只能提交修改建议。

## 3. 正负和解

- **正面**：等级差异结构化可见，"配置存在即通过"被格式性排除；Check 3 式演进叙事可被
  脚本统计（traceability 输出分布）；BH 语义与本仓程序化门禁结合，形成"程序化 + 证据
  分级"的完整答案（`research/synthesis/README.md` §3 发现 6）。
- **负面**：308 条一次性回填成本；Check 行格式新增约束（脚本与人工均需遵守）；
  `check_counts.py`/`traceability.py` 需同步扩展并保持兼容。
- **承担者**：checklist 维护者（回填与后续每条新 Check 标注）、脚本维护者（解析与校验）。
- **和解理由**：一次性成本换长期可统计性；语义吸收自外部参照但判定主体保持程序化，
  符合门禁铁律与 0 信任口径；回填规则保守（默认 `exercised`），不虚构态级。

## 4. 三重时间

- **过去来源**：Better Harness `models/agent-work-loop.md`（commit `b605532`）证据五态；
  本仓 Check 3 复核叙事的演进实证；`docs/guides/signal-chain-completeness.md` 信号链
  完备原则（T116 复盘）。
- **现在证据**：§1.2 的 308 条类别复核（2026-10-29，可复现：提取判据 + 关键词分类 +
  抽样校验，脚本方法见提交记录）。
- **将来失效条件**：见头部退出条件；复审触发见 §5。

## 5. 复审触发

1. 每个复核批次收口时，`check_counts.py` 态校验随门禁自动执行（格式与升降级合规）；
2. `traceability.py` 态分布统计随每批复核输出——若"outcome-supported 占比连续两个批次
   下降"或"unobserved/missing 超过 30 天未动"，登记为复审议题；
3. 季度抽样：随机抽 10 条 `exercised` 态 Check 人工复核叙事与态是否一致（一致性 < 90%
   触发退出条件评估）。
