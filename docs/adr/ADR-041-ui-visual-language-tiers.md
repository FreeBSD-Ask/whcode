# ADR-041：界面视觉语言分层——终端族与应用族

- **状态**：**已决策（2026-10-25）**，随 `modernize-ui-visual-language` 变更落档（T193）
- **来源**：用户指令（2026-10-25）“不影响内存占用的前提下，把界面实现的更现代化，类似流行的
  同类 Harness 软件（命令行、网页，桌面），其中命令行 cli、tui 风格应与其他几种不同”；
  FR-601／612／613／615／617／618、FR-711—717（`specs/001-whcode-harness/spec.md`）；
  ADR-014（极简前端）、ADR-026／ADR-027（原生 GUI 与非功能预算）、ADR-032（四端对等与差异
  登记，视觉不参与判等）、ADR-035（NFR-201 修订）
- **责任人**：UI 与前端负责人（四端视觉规范维护）
- **退出条件**：任一复审触发（见“三重时间”将来项）即复审本 ADR；不得以“现代化”“主流审美”
  为由绕过色值、动效与资源纪律

## 决策

1. **两族视觉语言**。四端分成两个视觉族，语法互不套用：
   - **终端族（CUI／TUI）**：等宽字符网格；线框与列对齐表达结构；选中用反显或 `>` 前缀；
     常驻键位提示；不使用留白装饰、比例字体层级或鼠标依赖。
   - **应用族（Web／GUI）**：比例字体的字号层级；间距刻度与留白分组；分区面板；右对齐的
     等宽元信息；常驻状态栏；不模拟终端字符画。
2. **色值与动效纪律不变**。只允许主题登记色值（`#000000`／`#FFFFFF`／`#E6E6E6`／`#00FF00`）；
   不引入第三色值（含已登记未实现的 `#3A3A3A` 边框）、渐变、阴影、模糊；不新增动效与定时器。
   层次只能由**位置、对齐、反显、字号刻度与留白**表达。状态除颜色外必须另有符号或文字。
3. **CUI 允许非颜色强调（新增边界）**。仅在同时满足“stdout 是交互终端、未设置 `NO_COLOR`、
   `TERM` 不为 `dumb`、未使用 `--json`”时，允许输出**粗体与弱化**属性；**禁止输出颜色**，
   禁止非必要的游标定位与清屏序列。其余情况输出纯 ASCII。
   本决定不改变 ADR-032 理由码 `CUI_NO_THEME`：CUI 仍不提供主题选择、不宣称控制配色。
4. **TUI 装饰字符清单**。新增装饰只允许实测为 1 格的制表符（`─│┌┐└┘├┤`）与 ASCII；新文案
   不引入歧义宽度字形（`·`、`×`、`—`、`“”`），避免触发 `RowBackend` 的运行时字形实测。
   依据：`crates/whcode-tui/src/rowbackend.rs` 的 CP 65001 实测记录。
5. **GUI 交互边界**。GUI 允许新增**依据输入事件驱动**的只读交互（侧栏点击切换视图），
   消息效果类别仍为 `EffectClass::Read`；不得引入定时器、周期重绘、新增线程或 GPU 上下文。
   只读 v1 与 `GUI_READ_ONLY_V1` 理由码不变。
6. **Web 交互与结构**。tablist 采用 ARIA 标准的 roving tabindex 与方向键循环；布局使用
   逻辑 CSS 属性以支持 RTL；服务端数据只经 `textContent`／属性赋值渲染，禁止 `innerHTML`、
   `outerHTML`、`insertAdjacentHTML`。仍无框架、无打包器、无第三方字体、无 WebGL。
7. **门禁由程序实施**。DOM 节点上限（≤ 2 000）与 DOM 注入 API 禁令进入
   `.github/scripts/benchmarks/check-frontend-budget.py`，与体积检查同一 CI 入口（ADR-037）；
   四端结构由 Rust 测试断言，不以人工目视代替。
8. **资源中性判定口径**。改造前后用同一夹具实测：TUI 帧预算 p95 ≤ 16 000 µs（UI 自定候选
   预算，非 NFR 冻结项）；GUI 空闲 RSS ≤ 96 MB、私有 ≤ 80 MB、线程 ≤ 24、句柄 ≤ 256、
   CPU ≤ 0.2% 单核，且线程与句柄数不得高于 2026-10-24 基线（24／241）；主进程空载 RSS
   ≤ 36 MB（NFR-201）；Web 首屏 JS ≤ 50 KB gzip、CSS ≤ 20 KB gzip、DOM ≤ 2 000。
   相对基线的比较只作**同机参照记录**（debug 剖面单次 50 样本的 p95 噪声约 ±30%，不足以
   判定 20% 级差异），不作硬门槛；静态推断不得替代测量。
   三区布局引入后同机实测 p95 约 2 000—2 400 µs（改造前单面板参照约 1 000—1 500 µs），
   绝对预算余量仍 ≥ 84%，且帧内分配仍由主面板高度界定（不随快照行数增长）。

## 理由（正负和解）

- **正面**：把“现代化”从主观审美变成可判定的两族语法与可测量的资源门槛；终端族保住墨水屏、
  AMOLED 与低算力适配（纯色、无动效、字符网格），应用族获得字号层级与留白带来的可读性；
  DOM 与注入禁令把长期只存在于文档的承诺变成门禁；CUI 的非颜色强调在不引入配色的前提下
  改善长输出可读性。
- **负面**：两套语法增加维护面（同一信息的两种排版需分别测试）；TUI 布局重构触及既有帧
  断言与边框字符约束；CUI 人类可读文本变化会让依赖文本抓取的脚本失效；CUI 的 ANSI 属性在
  少数终端会被渲染为不可见差异。
- **承担者**：四端维护者（两套排版与测试）；依赖 CUI 人类可读文本的脚本作者（改解析
  `--json`）；GUI 与 TUI 的评测者（需重跑帧预算与资源探针）。
- **和解理由**：用户的差异化要求本身要求两套语法；文本抓取本就不是契约（`--json` 与退出码
  才是契约），以展示层变更换取可读性属可接受代价，并在 CHANGELOG 明示；资源口径用同夹具
  实测兜底，避免“看起来更现代”变成隐性的内存增长。

## 三重时间

- **过去（来源）**：FR-612（纯色主题）、FR-613（渲染纪律）、ADR-014（无框架、文本优先、
  预算）确立了“简陋优先”的底线；ADR-032 明确视觉与交互形态**不参与**四端对等判定，为
  “同一能力、不同视觉语法”提供了合法空间。此前的界面实现把“简陋”做到了下限，却没有
  定义“简陋之上如何组织信息”。
- **现在（证据）**：TUI 为单边框 + 单列文本（`crates/whcode-tui/src/lib.rs` 的 `draw_frame`）；
  Web 仅 58 行 CSS、无层级（`frontend/styles.css`）；GUI 为固定 180 px 侧栏 + 单列文本；
  CUI 多字段结果压成一行。预算余量充足：首屏 JS gzip 约 8.2 KB／CSS 约 1.1 KB（预算 50／20 KB），
  TUI 帧 p95 约 1.5 ms（预算 16 ms）；但 GUI 线程数已触 ADR-027 上限（24），句柄 241／256，
  因此本轮不得新增线程与句柄。
- **将来（复审触发）**：① 任一前端引入框架、打包器、第三方字体或动效；② DOM 预算或帧预算
  连续两轮逼近上限；③ GUI 线程或句柄触顶且无法在不新增资源的前提下扩展；④ CUI 需要受控
  配色或长驻会话；⑤ 新增前端（含远程传输前端）；⑥ 用户要求第三种视觉族或主题扩展；⑦ 门禁
  被证明可被绕过（负向自测失效）时立即复审门禁本身。

## 替代方案（已否决）

- **引入组件库或 CSS 框架（Tailwind、Bootstrap、shadcn 等）**：体积、构建链与第三方字体
  直接违反 ADR-014 预算，且在墨水屏上引入阴影与过渡；否决。
- **给终端族加真彩色、渐变或动画**：墨水屏残影与 OLED 烧屏风险，且违反 FR-613；否决。
- **让 Web/GUI 采用终端字符画风格以“统一视觉”**：牺牲可访问性、比例字体可读性与应用族
  的桌面惯例，且与用户“CLI／TUI 与其他几种不同”的要求相反；否决。
- **只写规范、不加门禁**：DOM ≤ 2000 长期只有文档承诺、无程序判定，已被证明会漂移；否决。
- **用截图目视验收代替测试**：不可重复、不可定位回归点；否决。

## 影响

- 代码：`whcode-app`（结构化列投影）、`whcode-tui`（三区布局）、`whcode-cui`／`whcode-bin`
  （记录式输出与终端能力检测）、`whcode-web`（外壳、ARIA、逻辑属性）、`whcode-gui`（原生
  外壳与点击选择）、`whcode-domain`（双语词条）。
- 门禁：`check-frontend-budget.py`（DOM 与注入禁令）、TUI／CUI／Web／GUI 结构测试。
- 文档：`docs/guides/ui-design.md`（视觉语言分层与刻度）、`docs/guides/tui.md`、
  `docs/guides/cui-manual.md`、`CHANGELOG.md`、`docs/matrices/decisions.md`（D-19）。
- 风险：R-16（TUI 布局重构触及既有帧与宽度断言）、R-17（CUI 人类可读文本变化影响文本抓取
  脚本）。缓解：帧预算与宽度用例进测试；CUI 以 `--json` 为契约并在 CHANGELOG 标注。

## 回退路径

- 视觉层为纯展示改动：单独 revert 单个前端的布局／样式文件即可回退，不影响 JSON、退出码、
  权限与数据。
- 门禁扩展若误伤：删除 DOM 与注入检查两段，体积检查保持；须在 ADR 修订记录说明原因。
- CUI 强调：将终端能力检测恒判为“非交互”，即恢复纯 ASCII 输出。

## 修订记录

- **2026-10-25（首版，T193）**：确立两族视觉语言、CUI 非颜色强调边界、TUI 装饰字符清单、
  GUI 只读交互边界、Web ARIA 与注入禁令、资源中性判定口径与门禁落点。
- **2026-10-25（T201 实测后修订，判定口径）**：决策 8 的“相对基线不劣化 20%”改为“绝对预算
  + 同机参照记录”。理由：同一台机器、同一夹具、同一 debug 剖面下，单次 50 样本的 p95 在
  1 071—1 471 µs 之间波动（legacy 参照三次测量），20% 级差异落在噪声内，无法作为可判定
  门槛；绝对预算（16 000 µs）与帧内分配有界性才是可复现判据。三区布局实测 p95 约
  2 000—2 400 µs，仍余 ≥ 84%。本修订不改变任何内存指标，也不放宽 GUI/Web 预算。
