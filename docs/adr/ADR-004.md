# ADR-004：Web 是原生 Web UI，不是 TUI 的 PTY 镜像

- **状态**：已批准（M0 原则批准，2026-10-21；技术选型待验证，见 TBD-04）
- **来源**：任务书 §2（原状态"必须冻结"）、§0.3-1、D-03
- **责任人**：Web 端负责人
- **退出条件**：M6 完成 Web 端并通过 V-109/V-110；Web 框架与 WebSocket 库选型（TBD-04）须在 M6 前定案并记录
- **批准依据**：`specs/001-whcode-harness/spec.md` 的 ADR-004、FR-603、FR-606；`research.md` R-05 明确“具体 Web 框架、WebSocket 库与前端构建方式在 M6 前按五平台验证证据确认”；M0 未实现 Web 代码，本批准仅覆盖“独立原生前端、非 PTY 镜像”的原则，技术选型未验证。

## 决策

Web 端为**独立原生前端**，通过统一应用服务访问状态与命令（HTTP API / WebSocket），
**不是** TUI 的 PTY 镜像。

## 理由与约束

功能能力对等必须基于命令和状态，不可由终端画面（xterm.js 等）代替。约束：前端状态由同一事件
流驱动；断线端可从持久化游标补齐事件（FR-605）；默认绑定 `127.0.0.1`，对外监听必须显式启用
身份验证、Origin 检查与安全配置（FR-606）。

## 替代方案

- PTY 桥接 TUI（v2.0 原方案）：被 §0.3-1 明确调整——把浏览器交互降级为终端像素传递，无法提供
  浏览器原生交互与脚本化能力。
- 各端独立状态源：导致功能漂移（R-04），被 ADR-003/009 否决。

## 影响

- 约束 crate：`whcode-web`；能力矩阵文档 `docs/matrices/feature-parity.md`。
- 门禁：`plan.md` C-04；宪法原则 III。
