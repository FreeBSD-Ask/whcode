# ADR-072：标准基线与对标结论采纳

**状态**：已批准（用户 2026-11-14「全面批准」） | **日期**：2026-11-14 | **来源**：用户指令“充分研读学习 ISO 规范、IEEE 规范、编程规范、国标等标准规范，全局审阅本地工具链、软件工程理论、流程规范、文档治理……研读清楚了再批准，落地”

## 1. 形式审查与矛盾

- **形式**：一份基线文档（`docs/guides/standards-baseline.md`，单一事实源）＋一个结构门禁脚本（`check-standards-baseline.py`）＋过程文档版本事实修订＋研究证据留档（`research/standards-alignment/`，不承载承诺）。
- **矛盾**：本仓引用标准散落在三份文档里（process／requirements／module-design 各自引用），无人保证“引用的是现行版”；标准会停用与换版（研读实测：IEEE 1016／730／828 已停用、12207:2026 已取代 2017、25010 已变 9 特性），漂移无人检出。不做会怎样：过时版本事实随文档扩散，后来者按讹传对标（如“MISRA Rust”）。
- **正面**：版本事实有一处可复核的出处；停用对象引用可程序化拦截；对标结论（五类判定）一次成形、按行复审。
- **负面**：基线文档自身需要维护（约 40 行登记）；版本复核有年度成本；strict 模式对文档措辞有约束（引用停用对象必须带注记）。
- **承担者**：登记维护成本由文档作者承担（改标准引用时同步基线）；年度复核由代理批次承担。

## 2. 决策

1. **基线单一事实源**：`docs/guides/standards-baseline.md` 登记本仓承认的标准／框架：现行版本、状态、五类判定、映射锚点、复审触发；另设「已停用与负向事实登记」节。其他文档引用标准时链接该文件，不各自登记版本。研读方法与证据层级（〔官〕〔检〕〔识〕）见 `research/standards-alignment/README.md`。
2. **版本事实纠偏（2026-11-14 批次落文档）**：25010:2023 为 9 特性（新增 Safety；usability→interaction capability、portability→flexibility），process §5 改正并新增 §5.1 逐特性映射；IEEE 1016-2009 加停用注记、架构描述锚点补 42010:2022；12207 现行版 2026（GB/T 8566-2022 仍 IDT 2017 内容，双轨登记）。
3. **思想采纳清单（已在本仓有落点，登记防误删）**：DO-330 工具鉴定思想（验证工具自身需被验证——门禁脚本自检＋每周 action-audit 承担）；ISO/IEC/IEEE 15026-2 保障案结构（Check→判据→证据态七值即分布式保障案）；IEEE 1012 完整性分级思想（`resource-budget.md` 任务级铁律按风险分级验证强度）；ISO/SAE 21434 TARA 步骤（威胁模型条款 NFR-219、ADR-070 同构）；NIST SSDF 对照（PO/PS/PW 高覆盖、RV 组以已知缺口表＋0 信任复测＋CHANGELOG 修复段承担）；ISO/IEC 5338 集成方子集（数据生命周期＝事件＋脱敏＋purge；持续监控＝关联 ID＋断链检出）。
4. **明确不做（当前和解，复核触发见 §5）**：ISO/IEC 33000 过程评估评级（单人项目评级＝形式主义）；ISO/IEC 27001 ISMS 与 ISO/IEC 42001 AIMS 认证（合规表演；哲学 §10.6 安全反教条）；SLSA 构建签名 provenance（触发条件：发布产物被外部引用或分发时按 §5.1 铁律立项）；GB/T 8567 文档模板体系（瀑布交付口径）；Diátaxis 四象限门禁化（导航参照可用，无判定价值）；EU AI Act 对标（本地开发工具，最小风险域；向欧盟分发时重评）；IEEE 1012 全套 V&V 计划文档体系与 29119-2 独立测试计划（维持 checklist＋tests/README 承担，仓库自登记缺口不变）；GB 18030 兼容层（内部存储与导出 UTF-8；面向中国发行时评估）。
5. **门禁**：`check-standards-baseline.py` 默认模式（基线文件六字段结构＋判定取值＋停用登记在场）接入 `platform-verification.yml` windows 步骤；`--strict`（停用对象裸引用同行须带注记）含证伪路径测试，暂不接 CI——其覆盖面（process 等四份共享文档）当前随用户 SDK 批次在途，落账后评估接入（本 ADR 复审触发）。

## 3. 正负和解

| 项 | 内容 |
|---|---|
| 正面 | 版本事实可复核、停用引用可拦截、对标结论按行复审而非重读全文 |
| 负面 | 登记维护成本；strict 对措辞的约束；基线文件自身可能过时 |
| 承担者 | 文档作者承担同步义务；代理批次承担年度复核 |
| 边界 | 本 ADR 不宣称任何合规或认证；安全关键类（61508／26262／DO-178C／21434）只作思想参照，任何时候不得写成“对标”或“符合” |
| 和解理由 | 研读实测证明漂移已发生（4 项停用／换版事实未被人察觉）；单一事实源＋结构门禁是“不伪造”原则对标准引用的延伸 |

## 4. 过去／现在／将来依据

- **过去**：本仓规范依据自 2026-10-21 引用 29148/1016/25010，从未登记版本状态；研读发现其中 1 项已停用、1 项特性计数过时（研究证据 `research/standards-alignment/` §3）。
- **现在**：40 项标准／框架版本经官方页或多源交叉核验（〔官〕〔检〕标注）；门禁脚本双模式本机通过（含负向探针转红验证）。
- **将来失效条件**：见 §5。

## 5. 复审触发（绑定命令＋判定规则）

| 触发 | 命令／事件 | 判定 |
|---|---|---|
| 门禁红 | `python .github/scripts/check-standards-baseline.py` | 失败即复审基线文件结构或登记内容 |
| strict 接入时点 | SDK 批次（FR-778）落账后 | 评估把 `--strict` 加入 platform-verification.yml；届时四份共享文档的注记已入库 |
| 年度版本复核 | 每年至少一次（下次 2027-11-14 前） | 按基线文件口径 1 重核现行版本；上游换版改对应行并跑门禁 |
| 上游重大换版 | 12207 国标跟进 2026、29148 新版发布、25010 换版 | 改基线对应行＋受影响文档引用 |
| 评级／认证提案 | 任何人提议 ISMS／AIMS／33000 评级 | 先过形式主义审查（philosophy §1）再修本 ADR，不得以“行业惯例”立项 |

## 6. 已知限制与失效条件

1. 门禁只做**结构**检查（字段齐全、取值合法、注记在场），不验证版本事实真伪——真伪依赖年度官方页复核，脚本通过不等于版本正确。
2. 基线登记约 40 行，覆盖研读过的标准；未研读的标准不在登记内，引用未登记标准时本门禁不拦截（缺口，按需扩行）。
3. `--strict` 未接 CI 前，裸引用拦截只在本地批次运行时生效；接入前的窗口期依赖文档作者自觉。
4. 研读证据中付费墙内标准（DO-178C、61508、26262、21434、5338 等）仅基于官方摘要与公开预览，条款级差异标 [待验证]；本 ADR 的“思想参照”结论不受此影响，但不得据此宣称条款级对标。
5. 本 ADR 与基线文件的判定结论不改变任何现行硬边界（Windows 唯一验收、零 unsafe、禁 GNU、原生 GUI 等）；冲突时以 ADR-013／ADR-026／NFR-215 为准。
