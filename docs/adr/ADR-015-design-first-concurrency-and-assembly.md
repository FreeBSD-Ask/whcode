# ADR-015：并发设计先行与汇编例外

- **状态**：**已批准（2026-10-21，用户决策）**
- **来源**：用户指令“优化内存和 CPU 占用；多线程并发宁可设计一百年也绝不原型先行；必须充分研读前沿科学论文再行动；为优化资源占用甚至允许使用汇编”
- **责任人**：性能与并发负责人
- **退出条件**：若要恢复“原型先行”或扩大汇编使用范围，必须新 ADR，并给出正确性、资源与回退证据

## 决策

1. **并发设计先行，禁止原型先行**：线程、调度、锁、无锁结构、内存序、共享缓存与异步运行时，
   必须先有书面设计档案并通过 G2，才允许提交生产代码。原型先行被视为错误方法：
   它把“偶然能跑”误当成正确性，掩盖数据竞争、内存序错误与活锁。
2. **文献门槛**：设计前至少研读 3 篇一手来源（论文/标准/权威手册），逐篇记录结论、
   适用条件、与本案差异、可借鉴约束与反例；冲突结论必须写明取舍与验证方式。
3. **并发设计档案**：必须包含问题边界、不变量、线性化点、内存序、进展保证、数据所有权、
   失败模式、验证计划、回退方案、文献依据与复审触发。完成判据是“不变量与验证计划可判定”，
   不以工时或页数衡量；设计先行不等于无限期分析。
4. **汇编例外**：仅当测量证明热点、安全 Rust 与算法优化已排除或不足，且满足以下全部条件时允许：
   独立 ADR 批准、代码隔离（优先独立 crate）、安全包装、跨平台回退、差分测试、安全评审、
   可复现构建。普通 crate 继续保持 `unsafe_code = "forbid"`。
5. **资源优化流程**：测量 → 定位 → 建模 → 设计 → 实现 → 复测 → 归档；禁止无基线优化、
   只报平均值、单次样本结项与“感觉更快”。

## 理由

- **并发的失败代价不对称**：单线程错误通常可复现；并发错误依赖交错、内存序与负载，
  可能在生产环境才出现，且难以回滚。设计成本远低于线上数据损坏的成本。
- **原型先行有确认偏误**：原型能跑会强化“设计没问题”的错觉；Loom/TLA+ 等模型检查能在
  写生产代码前暴露反例，属于设计活动而不是原型。
- **文献是廉价的并行经验**：无锁队列、内存序与进展保证已有大量一手研究；不读文献等于
  用生产事故重做别人的实验。
- **汇编的收益与破坏性并存**：汇编可降低指令数与分配，但破坏可移植性、可验证性与安全性；
  因此只允许作为有测量、有回退、有差分包的最后手段。

## 替代方案

- **原型先行**：被用户明确否决；不作为候选。
- **完全禁止汇编**：与用户“允许汇编优化”的决策冲突；保留为默认状态，但允许例外。
- **默认开启不安全优化 / 内联汇编散落业务代码**：破坏零 `unsafe` 基线与供应链审计，
  且难以跨平台回退；拒绝。
- **无限期设计**：会把“设计先行”变成分析瘫痪；以可判定的不变量与验证计划作为完成条件。

## 影响

- `spec.md`：新增 NFR-216（并发设计先行）与 NFR-217（性能优化与汇编例外）；
  修订 NFR-215 的零 `unsafe` 表述为“普通 Rust 零 unsafe，汇编例外独立登记”。
- `docs/guides/performance-and-concurrency.md`：并发档案模板、文献门槛、汇编条件与门禁映射。
- `tasks.md`：新增 T145；`checklist.md`：新增 Check 241—243。
- 过程门禁：G2 增加“并发档案 + 文献 + 汇编 ADR”；G3 增加模型/差分/回退验证；
  G4 增加前后对比与 0 信任复测。
- 交付节奏：并发功能的前置设计时间显著增加；这是用户明确选择的代价，不得用“先跑起来”
  绕过。若未来要缩短，只能通过复用已批准的设计模式与验证工具，而不是取消设计。
