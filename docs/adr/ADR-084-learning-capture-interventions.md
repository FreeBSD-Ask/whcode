# ADR-084：学习捕获与干预台账（复发归因、关闭原因码、结论自动判定）

- **状态**：已批准（2026-11-17；用户指令要求收口在途实现，本文按代码事实回填设计与判据）
- **来源**：ADR-080（发现台账四要件与迁移表）、ADR-036（JSON 语义列口径）、ADR-018（SQL 只在
  store）、ADR-038（确认与审计口径）；在途实现（`crates/whcode-store/src/interventions.rs`、
  `crates/whcode-store/migrations/0014_learning_capture.sql`、`crates/whcode-app/src/interventions.rs`、
  `crates/whcode-web/src/api.rs` 台账路由）
- **责任人**：store 维护者、app 维护者
- **退出条件**：见 §8（绑定命令与判定规则）

## 0. 任务认知卡（宪法原则 X）

- **方向**：发现台账只回答“有一个缺口”，回答不了“我们为阻止它再次发生做了什么、是否有效”。
  用户方向（P2.4）是把台账补成学习闭环，而不是加一个仪表盘。
- **目标**：①发现可归因到复发模式并计数；②关闭发现必须说明“为什么不修”；③干预以四要件
  登记，结论由复发计数自动判定，人工不得自证有效。
- **判据**：Check 466 的可判定条目（迁移与读写、负面控制、自动结论、四端台账第四节）。
- **非目标**：自动从对话中抽取干预（模型建议不等于登记）、跨项目模式库、干预的审批流、
  排行榜类统计（宪法 §1.3 的主体性原则）。

## 1. 问题与边界

三个真实矛盾：

1. **复发不可见**：`findings` 只有状态与严重度，同一个模式反复出现时计数为零，无法判断
   “上次的修复是否真的防住了”。
2. **关闭可被滥用**：没有原因码的 `dismissed` 等于“静默丢弃”，与宪法 §1.4 的“不伪造”
   及 ADR-080 决策 4 的迁移表冲突。
3. **改进无记录**：修完之后做了什么、预期防住什么、怎么验证，全靠记忆，不可审计。

边界：本 ADR 只定义数据与判定口径，不改权限模型（仍用 `SessionCreate`／`SessionRead`），
不新增网络面（台账复用 `GET /api/ledger`），不改事件 schema。

## 2. 决策

1. **复发归因字段（schema v14）**：`findings` 增加 `pattern TEXT`（模式归类，≤200 字符）、
   `recurrence_count BIGINT NOT NULL DEFAULT 0`、`dismiss_reason TEXT`。读取时未知枚举值、
   负计数一律按 `ParseError` 报错（库内容漂移显式化，不默认为 0／空）。DuckDB 限制：
   表上挂索引时 `ALTER TABLE ... ADD COLUMN` 会报依赖错误，迁移先撤 `idx_findings_status`
   再按原定义重建（与 0012 定义逐字一致）。
2. **复发是显式动作**：`record_finding_recurrence` 只在 `fixed` 状态可登记（状态回 `open`、
   `recurrence_count + 1`、可写回 `pattern`，`COALESCE` 保留既有归类），乐观锁与迁移同款；
   “修复尚未声明完成的重开”不计复发——语义写进错误消息，调用方无需猜。
3. **关闭原因的负面控制**：`dismissed` 迁移必须带封闭原因码（`by-design`／`superseded`／
   `duplicate`／`cost`／`wontfix`），其余迁移携带原因码即拒绝；字符串解析在 app 层，拒绝判定
   在 store 层（两处同口径）。
4. **干预台账四要件**：新表 `interventions`（`pattern`／`action`／`expected_effect`／
   `verification` 必填，各 ≤2000 字符，模式 ≤200），与 findings 同构；`session_id` 可空；
   `status ∈ {active,concluded}`；索引 `(status, created_at, id)` 与 `(pattern, status, id)`。
   登记时记 `recurrences_before`＝该模式当前复发计数总和（预防性干预基线为 0，属正确的零）。
5. **结论自动判定，不接受人工指定**：`conclude_intervention` 只收 id 与期望版本；`outcome`
   由 `recurrences_after == recurrences_before` 判 `effective`，否则 `not_effective`——人工在
   结论里写“有效”不算数，计数算数（防自证）。结论是终态，重复结论显式拒绝。
6. **台账第四节**：`view.ledger` 由三节扩为四节（待办／交付物／发现／干预），TUI／GUI／Web
   同源（`whcode_app` 只读命令）；单节失败进 `errors` 且其余各节照常返回，不把“查不到”
   画成“没有”；各节全因会话不存在失败才回 404。

## 3. 正负和解

- **正面**：复发计数与干预结论把“修好了没有”从叙述变成可复算的数字；关闭原因码让
  “不修”也必须交代；台账第四节让改进本身可审计。
- **负面**：① 多一张表与三个字段，schema v14 迁移与导出表清单各增一项；② 自动结论只认同
  模式计数相等，判断力有限（计数不变也可能是没人在用，不是真的防住）；③ `pattern` 靠人工
  归类，写错归类会让聚合失真；④ 台账再多一节，快照读取多一次查询（已按节独立有界）。
- **承担者**：store 维护者（迁移与不变量）、app 维护者（权限与字符串归一）、四端维护者
  （第四节渲染）；写台账的人承担归类质量。
- **和解理由**：这些代价都是“一次性结构成本＋每批次少量人工归类”，换来的是复发与干预两件
  事第一次有了可复算口径；不做则继续用记忆管理“上次修没修好”。

## 4. 三重时间

- **过去来源**：ADR-080 的四要件与迁移表已经要求发现写清“最小修复／验证路线”，但没要求
  记录修复后的复发；v0.1.0 台账视图（FR-787）三节齐备，缺的正是“改进”这一节。
- **现在证据**：`cargo test -p whcode-store` 172 通过（含本 ADR 的负面控制、自动结论、漂移
  检测用例）；`cargo test -p whcode-app`／`-p whcode-web` 全绿；覆盖率试点 store 90.02%、
  app 90.31%（本机 `check-coverage.py`）。
- **将来失效条件**：若出现“自动结论”被高频误判的场景（计数口径无法区分“没人复发”与
  “没人使用”），本决策失效，需引入使用面证据或改判据；若 DuckDB 支持带索引加列，迁移中
  的撤建索引步骤应删除。

## 5. 回退方案

迁移为增量（加列、加表），旧库可继续读（新列有默认值）；回退到 v13 需先导出，再由
`migrations` 回退策略重建——本 ADR 不承诺运行期降级。代码侧回退：删除第四节渲染与
`interventions` 模块即可回到三节台账，`findings` 新列保留不影响旧代码（读取有默认）。

## 6. 已知限制与失效条件

- **已知限制**：
  1. `outcome` 只比较同模式复发计数的前后值，不识别“使用面为零”的假有效；
  2. `pattern` 为自由文本，大小写与近义写法不会被归并（聚合按精确匹配）；
  3. 干预跨会话（`session_id` 可空），但写入仍是会话内动作，不适合当作全局知识库；
  4. 台账第节渲染不做跨节排序，四节各自按状态与时间排列。
- **失效条件**：
  1. DuckDB 版本变更导致撤建索引步骤不再必要或 `RETURNING` 行为变化——迁移测试立即失败；
  2. 数据库出现未知枚举值（外部工具写入）——按 `ParseError` 拒绝读取，需人工核对；
  3. 台账第四节的查询上限被突破（>200 条）时列表截断由调用方分页，若四端未同步分页，
     本决策的“不静默截断”承诺失效，需补分页。

## 7. 文献依据（标准研读记录，§1.6 口径）

- ADR-080（发现台账四要件与迁移表）与 ADR-018（分层：SQL 只在 store）——本项目既有决策；
- ISO/IEC/IEEE 12207:2017 §6.4.9（问题解决过程要求记录处置与验证）——处置结论需有证据，
  故结论由计数判定而非声明；
- ISO 9001:2015 §10.2（不合格与纠正措施：原因、措施、有效性评审）——四要件与自动结论的
  直接依据；
- DuckDB 官方文档（ALTER TABLE 限制、`RETURNING`、`nextval` 序列）——迁移实现口径。

## 8. 复审触发（绑定命令＋判定）

1. `cargo test --locked -p whcode-store` 失败 ⇒ 迁移、负面控制或自动结论被破坏；
2. `python .github/scripts/check-coverage.py` 报 store < 90% ⇒ 新路径缺行为测试（本 ADR §4
   的“现在证据”失效）；
3. `python .github/scripts/traceability.py` 报 FR-794 断链 ⇒ 需求到验收的追溯被破坏；
4. 出现“结论自动判定被误用”的实例（同一干预在计数不变的前提下仍被判有效但实际复发）⇒
   按 §4 失效条件 1 复审本决策。
