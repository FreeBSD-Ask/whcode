# ADR-014：前端极简路线——无框架、无打包器、文本优先

- **状态**：**已批准（2026-10-21，用户决策）**
- **来源**：用户指令“前端能多简陋就多简陋，力求适配墨水屏、A 屏显示器和降低内存占用”；FR-612（三套纯色主题）、FR-613（渲染纪律）、FR-617（最小化挂起）
- **责任人**：Web 端负责人
- **退出条件**：若以后要引入任何前端框架/打包器/WebGL，必须新 ADR 并给出体积、内存与墨水屏适配的实测对比

## 决策

Web UI（M6）采用**极简实现**：

1. **无前端框架、无打包器**：不使用 React/Vue/Svelte 等运行时；不引入 bundler 与 node 构建链。
   页面由服务端直出 HTML（axum 模板或手写字符串），交互用**原生 ES modules**（浏览器直接加载）。
2. **文本优先**：页面以文本与表格为主；不使用装饰性大图、视频、自动播放、背景动画。
3. **CSS 变量主题**：三套主题（A 屏夜间纯黑 `#000000`、墨水屏日间纯白 `#FFFFFF` 黑字、
   墨水屏夜间纯黑白字）只通过 CSS 自定义属性切换，不下载图片、不做主题动画。
4. **预算上限（首版硬性目标）**：
   - 首屏 JavaScript **≤ 50 KB（gzip）**、CSS **≤ 20 KB（gzip）**；
   - 单页 DOM 节点数目标 ≤ 2 000（长列表用分页/游标，不做无限滚动）；
   - 不加载第三方字体；系统字体栈；
   - 无 WebGL、无 Canvas 动画。
5. **渐进增强**：无 JavaScript 时，只读视图（会话/任务/事件列表、Spec 状态）必须可用；
   写操作在无 JS 时给出明确提示而非空白页。
6. **预算校验进 CI**：新增 `ci/benchmarks/check-frontend-budget.py`，对 `whcode-web/frontend/`
   的产物做体积与依赖审计；超预算即失败（等价于性能门禁）。

## 理由

- **墨水屏**：刷新慢（整屏 2—4 秒级）、黑→白转换残影最重；文本优先 + 纯色背景 + 无动画是
  最稳妥的适配方式（见 FR-612 依据）。
- **AMOLED/A 屏**：只有纯黑 `#000000` 才关断像素；“简陋”天然减少发光面积与烧屏风险。
- **内存与 CPU**：SPA 框架的运行时、虚拟 DOM 与打包产物是常驻内存与启动抖动的主要来源；
  无框架方案把内存与 CPU 成本压到浏览器原生渲染的水平，符合 FR-613/FR-617 的纪律。
- **供应链**：无 node 构建链意味着没有 `node_modules`，依赖面与审计成本显著下降（BSD-2 项目
  对第三方许可证也更干净）。

## 替代方案

- **React/Vue SPA**：交互丰富，但运行时常驻内存、需构建链、对墨水屏动画不友好；与本项目
  “低内存 + 纯色 + 无动效”的目标冲突。
- **TUI 的 PTY 镜像**（xterm.js 等）：已被 ADR-004 否决（浏览器端变成终端像素搬运，无法提供
  原生交互与可访问性）。
- **服务端模板 + HTMX 类小库**：可作为“原生 ES modules”的等价替代；若引入，按预算评审决定，
  不得超出上述体积上限。

## 影响

- `crates/whcode-web/frontend/`：只允许静态 HTML/CSS/原生 JS 与必要的图标（内联 SVG）；
  **禁止**提交 `node_modules`、打包产物、sourcemap 之外的大型资源。
- `tasks.md`：T093/T133/T136 需遵守本 ADR；新增 T137（极简基线 + 预算校验脚本）。
- 验收：新增 Check 229（预算与依赖审计）。
- 不影响 TUI：TUI 本来就没有前端框架，本 ADR 只约束 Web。
