# ADR-095：审批规则纳入导出/导入，并以可选表保持向后兼容

- **状态**：已批准（2026-11-22，用户“继续”；修复 ADR-080 §6 自登记缺口）
- **关联**：ADR-080（评审发现台账 §6 缺口）；V-106（导入冲突拒绝）；FR-786；导出格式 v1

## 任务认知卡

- **方向**：把 `approval_rules` 纳入工作区导出/导入，使备份与迁移不丢失审批规则。
- **目标**：新导出文件含该表并可往返；旧导出文件（不含该表）仍可导入，按无数据处理；导入冲突仍拒绝。
- **用户意图**：用户要求继续功能开发；本项是 ADR-080 明确自登记的缺口，属真实数据丢失风险。
- **非目标／边界**：不递增 `EXPORT_FORMAT_VERSION`（不破坏旧文件）；不改导入冲突语义；不导出 `audit`／`runtime_state` 等既有排除表；不改审批规则的写入路径。
- **现有证据**：`export.rs` 的 `EXPORT_TABLES`／`TABLE_KEY_COLUMNS` 均无 `approval_rules`；`EXCLUDED_TABLES` 也无（即“静默丢失”，既非导出也非显式排除）；表结构 `approval_rules(tool PK, rule, created_at_ms, updated_at_ms)`（迁移 0009）。
- **手段（后置）**：`EXPORT_TABLES` 增表 → 新增 `OPTIONAL_TABLES` 兼容机制 → `TABLE_KEY_COLUMNS` 增键 → 三处遍历容忍可选表缺失 → 往返与旧文件兼容测试。

## 问题

ADR-080 §6 自登记：`approval_rules` 既未出现在 `EXPORT_TABLES` 也未在 `EXCLUDED_TABLES` 登记，导出/导入会丢审批规则。这是**静默数据丢失**——比显式排除更危险，因为用户无从察觉。

## 判定：应当导出

1. **安全语义**：审批规则是工作区级安全配置（`allow`／`deny`）。丢失后恢复的库对原本 `deny` 的工具回落到默认策略，属安全倒退。
2. **数据归属**：规则是工作区数据，与 `findings`／`interventions` 同口径，应随备份迁移。
3. **冲突安全**：导入对已存在主键一律拒绝（V-106），不会静默覆盖目标库现有规则。

## 决策

1. `EXPORT_TABLES` 增 `approval_rules`（位置在 `interventions` 之后，无外键依赖）。
2. `TABLE_KEY_COLUMNS` 增 `("approval_rules", &["tool"])`。
3. 新增 `OPTIONAL_TABLES: &[&str] = &["approval_rules"]` 与 `is_optional_table(table)`：
   导入的三处遍历（完整性校验、键列冲突检查、插入）在**表本身缺失**且属可选时跳过；
   **表存在但校验和缺失一律报错**——不得借可选机制绕过完整性校验；既有表缺失仍报错。
   新导出一律包含该表；旧文件（v0.1.1 及更早）缺失时按无规则导入，`ImportReport`
   不出现该表键（如实反映“文件没有”）。
4. 模块文档“导出 14 张业务表”改为 15，并说明可选表兼容。

## 理由与约束

- 为何不递增格式版本：递增会让用户已有的导出文件全部不可导入，代价远大于收益；
  新增可选表的缺失是可安全降级的（无规则 = 默认策略，与旧版本行为一致）。
- 为何不把旧表也设为可选：既有表缺失意味着文件损坏或格式不符，必须报错，不得宽容。
- 承担者：store 导出维护者（清单与兼容分支）；用户无感（新文件多一表，旧文件仍可导入）。

## 正负和解

| 项 | 内容 |
|---|---|
| 正面 | 审批规则不再丢失；旧文件仍可导入；冲突仍拒绝，无静默覆盖 |
| 负面 | 导出文件多一表、体积略增；“可选表”概念增加一处分支逻辑 |
| 承担者 | store 维护者承担分支与测试；用户承担极小体积增长 |
| 和解理由 | 以最小格式变更消除静默数据丢失，兼容成本仅为三处 `if is_optional` |

## 三重时间

- **过去来源**：ADR-080 §6 缺口登记；V-106 冲突拒绝；迁移 0009 表结构。
- **现在证据**：三处清单均无该表；导入对缺表一律报错（627／667／684 行）。
- **已知限制与失效条件**：①旧文件导入后审批规则为空（如实，不伪造“已恢复”）；②若未来该表结构变更需递增格式版本；③导出格式 v1 的字节布局因多一表而变，但版本号不变——旧版本程序读新文件会因未知表报错，属预期（向下不兼容仅限“新文件给旧程序”，不属本 ADR 承诺）。
- **复审触发**：①`cargo test -p whcode-store export::` 失败→回退；②导出格式版本递增→重审可选表机制；③审批规则表结构变更→同步清单与测试。

## 影响

- 正面：消除静默数据丢失；兼容旧文件。
- 负面：导出多一表；新增兼容分支。
- 不做什么：不递增格式版本、不改冲突语义、不动审批写入路径。
