# ADR-028：内置开源字体与四类字体分工

- **状态**：已批准（2026-10-23，用户选定“完整入库 + 运行子集、Sarasa Mono SC、包含 TUI”）
- **来源**：用户新增任务（英语／简体中文／等宽英语／等宽简体中文各用不同开源字体，完全本地化）；
  FR-615（i18n）、FR-712（CJK 字体不得整份常驻）、FR-716／FR-717；ADR-027（GUI 框架选型）
- **责任人**：GUI 与前端实现者；字体版本、许可与子集由构建维护者负责
- **失效条件**：见“复审触发”。本条修订 ADR-027 第 5 条“按族名使用系统字体”的字体来源决策

## 背景

ADR-027 落地时因系统字体不可再分发，字体走“按族名使用系统字体”，代价是字形依赖目标系统，
且无法区分英语与中文的字体。用户要求四类文本各用不同开源字体，并**完全下载到本地**，
不依赖系统字体与网络。

终端（TUI）的字体由终端模拟器控制，程序无法直接指定；因此“包含 TUI”只能通过
**字体随包 + 用户级安装 + 终端配置声明**实现，不能承诺程序内强行换字体。

## 决策

1. **四类字体**（全部 SIL OFL 1.1，可再分发）：

   | 用途 | 字体 | 完整文件 | 运行子集 |
   |---|---|---|---|
   | 英语比例 | Inter Regular | 0.39 MiB | 0.15 MiB |
   | 简中比例 | Noto Sans CJK SC Regular | 15.68 MiB | 3.40 MiB |
   | 英语等宽 | JetBrains Mono Regular | 0.26 MiB | 0.14 MiB |
   | 简中等宽 | Sarasa Mono SC Regular | 24.43 MiB | 3.98 MiB |

2. **入库形态**：新增顶层资源目录 `assets/fonts/`，保存四份**完整字体**与上游许可原文；
   `SOURCES.md` 记录上游、版本、下载日期与 SHA-256。完整字体不嵌入可执行文件。
3. **运行形态**：GUI 只加载由 `ci/subset-fonts.py` 生成的子集（合计 7.68 MiB），
   字符集 = ASCII/Latin + 通用标点与符号 + GB2312 全量 + 仓库文本实际字符；
   子集外的生僻字由系统字体栈回退，并在文档标注覆盖范围。子集随可执行文件编译进去，
   发布包不新增外部文件。
4. **分派规则**：按字符类别**显式分段**渲染，不依赖字体回退顺序：
   - 比例文本：拉丁 → Inter，CJK（U+2E80 及以上）→ Noto Sans CJK SC；
   - 等宽文本：拉丁 → JetBrains Mono，CJK → Sarasa Mono SC。
5. **TUI**：新增 `whcode font install|status`（CUI 子命令）：
   - `install` 把四份完整字体复制到**用户字体目录**并注册（HKCU），可 `uninstall` 撤销；
   - `status` 检测字体是否已安装、当前终端是否声明使用；`install` 输出 Windows Terminal
     配置片段供用户确认，**不自动改写用户配置**；
   - 不采用自绘终端；若将来需要，另立 ADR。
6. **许可合规**：字体文件与许可原文一并入库；发布包附 `assets/fonts/SOURCES.md` 与许可；
   不单独售卖字体，不改字体名。

## 理由（正负和解）

- **正面**：字形与上游版本绑定，跨机器一致；英语与中文、比例与等宽四类可区分；
  完全离线，无运行时下载；OFL 允许再分发。
- **负面**：仓库增加约 40.8 MiB；发布包增加约 7.7 MiB（子集）；运行期 RSS 增加约
  7.7 MiB（四份子集全部加载）；子集不覆盖 GB2312 之外的生僻字，需要系统回退；
  TUI 只能“安装 + 声明”，不能强制终端使用。
- **承担者**：仓库与发布包维护者（体积）、需要生僻字的用户（回退到系统字体）、
  想用自定义字体的 TUI 用户（需手动确认配置片段）。
- **和解理由**：用户明确要求“完全本地化、四类字体不同”。以 7.7 MiB 运行子集换
  离线一致字形与明确分工，同时用分段渲染消除“回退到系统字体”的不确定性；
  完整字体入库保证可复现与可重新子集化。预算仍有约 47 MB 余量（RSS 41→约 49 MB）。

## 影响

- 新增顶层目录 `assets/`：同步 `tests/contract/test_layout.rs` 白名单与
  `docs/guides/repository-layout.md`；新增目录本身由本条 ADR 授权。
- 新增 FR-716／FR-717、任务 T153—T155、Check 253—255，计数随之更新。
- `ci/subset-fonts.py` 依赖 `fonttools`（仅生成子集时需要；日常构建不需要）。
- GUI 的字体候选常量由“系统族名”改为“内置子集 + 固定族名”，
  `docs/guides/module-design.md` 同步。
- 打包脚本的包内清单增加字体许可与 `SOURCES.md`（若选择随包分发完整文件）。

## 复审触发

1. 任一字体许可变更或上游停止维护；
2. 空闲 RSS > 96 MB，或字体加载导致启动首帧明显变慢；
3. 子集缺字在界面或事件内容中反复出现（需要扩大字符集或换字体）；
4. `whcode font install` 引发用户配置损坏或无法撤销；
5. 需要 RTL／阿拉伯语等新语种（现有四类字体不覆盖，需另立需求）。

## 修订记录

### 修订 1（2026-10-24，T155 实现时补足 `font install` 的字体来源）

第 5 条未写明 `install` 从何处取得完整字体。实现口径：

1. `--from <DIR>`：显式指定来源目录，支持两种布局——平铺（目录内直接含四份字体文件）
   与仓库布局（`<DIR>/source/<family>/<file>`）；
2. 无 `--from` 时按序探测：可执行文件旁 `assets/fonts/source/` → 当前工作目录
   `assets/fonts/source/`（在仓库根运行时命中）；
3. 发布包**不随带完整字体**（维持包体增量 7.7 MiB 的既定和解；包内只有 `SOURCES.md`
   与许可原文）；来源缺失时给出可操作错误，指引 `--from` 与 `SOURCES.md` 的上游地址。

其余实现口径：注册位置为用户字体目录 `%LOCALAPPDATA%\Microsoft\Windows\Fonts\` 与
`HKCU\Software\Microsoft\Windows NT\CurrentVersion\Fonts`（`reg.exe` 子进程实现，零
unsafe、零新依赖，同 ADR-021 的子进程先例）；`status` 只读解析 Windows Terminal
（Store／Preview／解包安装）settings.json 的 `font.face`，找不到配置不视为错误；
不做 `WM_FONTCHANGE` 广播，输出注明"终端可能需重启后才能看到新字体"。
复审触发：若用户反馈发布包内安装字体路径不可用，重议随包分发完整字体（+40.8 MiB）。
