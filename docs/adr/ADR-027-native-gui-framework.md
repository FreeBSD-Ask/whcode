# ADR-027：原生 GUI 框架选型（iced + 软件光栅）

- **状态**：已批准（2026-10-23，用户选定“iced + tiny-skia”）
- **来源**：FR-711—FR-715（原生桌面 GUI，只读 v1）；ADR-026（GUI 必须原生，禁浏览器套壳）；
  ADR-013（Windows 11 amd64 唯一验收平台）；NFR-212（默认不创建 GPU 上下文）、
  NFR-215（零 `unsafe` 与资源纪律）；实测记录 `artifacts/gui-spike-2026-10-23.md`
- **责任人**：GUI 实现者（需求已立，人员待指派）；边界与预算由 UI／前端负责人维护
- **失效条件**：见“复审触发”。本条不改变 ADR-026 的形态边界

## 决策

1. **框架**：采用 `iced`（实测版本 0.14），**关闭默认 `wgpu` 特性，改用 `tiny-skia`
   软件光栅**。默认不创建 GPU 上下文；探测或初始化失败时降级而非崩溃。
2. **范围**：v1 只读——六视图浏览、会话选择、刷新；破坏性命令不经 GUI（FR-711）。
   写入能力须另立需求增量，不在本条授权范围内。
3. **分层**：新增前端 crate `whcode-gui`，只依赖 `whcode-app`，禁止直接触库、禁止绕过
   应用服务（与 `whcode-tui/cui/web/ssh` 同一条纪律）。`unsafe` 在仓库 crate 内保持
   `forbid`；iced 及其依赖内部的 `unsafe` 按“第三方依赖不作零承诺”登记（§4.1），
   但**不把 Win32 绑定引入本仓库**。
4. **资源预算**（可判定，取自 FR-712）：空闲 1200×800 下 RSS ≤ 96 MB、私有 ≤ 80 MB、
   线程 ≤ 24、句柄 ≤ 256、CPU ≤ 0.2% 单核。超出即触发复审，不得以“GUI 本来就重”结项。
5. **字体与主题**：CJK 字体按需／子集加载（禁止整份 19.7 MB 常驻）；三套主题精确色值；
   抗锯齿灰阶占比须量化（目标 ≤ 5%），并写入每次 GUI 验收证据。
6. **可验证性**：GUI 必须自带截图＋按键注入＋资源采样三件套，证据落 `artifacts/gui-*/`
   （FR-715）；人工目视不得作为唯一证据。

## 理由（正负和解）

实测数据（同一屏内容、同一采样口径、仓库外构建；详见 `artifacts/gui-spike-2026-10-23.md`）：

| 方案 | 空闲 WS | 线程 | 句柄 | crate | exe | 首帧 | GPU | 仓内 unsafe |
|---|---|---|---|---|---|---|---|---|
| TUI 基线 | 27.4 MB | 4 | 131 | — | — | — | 无 | 零 |
| Win32 + `windows` | 53.6 MB | 8 | 482\* | 16 | 172 KiB | 136–143 ms | 无 | 19 处 |
| **iced + tiny-skia** | **80.9 MB** | **22** | **199** | 96 | 3.94 MiB | 71 ms | 无 | 零 |
| iced 默认（wgpu） | 206.5 MB | 31 | 351 | 153 | 10.4 MiB | 273 ms | 有 | 零 |
| egui + eframe | 350.8 MB | 24 | 445 | 168 | 13.8 MiB | 217 ms | 有 | 零 |

\* Win32 句柄含本机输入法注入（空窗口对照亦为 485），纯 Win32 基线 `[待验证]`。

- **正面**：不引入 GPU 上下文（满足 NFR-212）；仓库 crate 内仍为零 `unsafe`（满足 NFR-215），
  不必为 GUI 开一条新的 `unsafe` 例外；界面、主题、排版完全自绘，三套精确色值可实现；
  事件驱动、空闲零重绘（实测 10 s／20 s 各 1 帧）；代码可跨平台保留，符合“BSD 代码级兼容、
  验收延后”的现状。
- **负面**：80.9 MB／22 线程仍显著高于 TUI（27.4 MB／4 线程）；抗锯齿产生 3.46% 中间灰；
  19.7 MB 字体默认常驻，需子集化才达标；依赖树把 `softbuffer`／`winit` 等 unsafe 面带入
  进程（不属于本仓库代码，但扩大供应链风险面）；构建时间（冷 49.5 s）高于 Win32（8 s）。
- **承担者**：GUI 实现者与长期维护者；以及接受“GUI 比 TUI 多约 53 MB 常驻”的用户。
- **和解理由**：Win32 的资源最优（53.6 MB／8 线程）只差 27 MB，但代价是本仓库必须开一条
  新的 `unsafe` 例外（19 处、`forbid` 级不可 `#[allow]`）、表头／选中条／标题栏需
  owner-draw、DPI 与 RTL 都要自己补；在“内存安全”优先级不低于“资源占用”的前提下，
  用 27 MB 换“不开 unsafe 例外”是当前和解，并写死了失效条件（预算与灰阶阈值）而不是
  当作永久结论。

## 替代方案（已否决／保留）

- **egui + eframe**：实测 350.8 MB、24 线程，且只有 GPU 后端（wgpu/glow），无法满足
  “默认不创建 GPU 上下文”。否决。
- **iced 默认（wgpu）**：206.5 MB 且启动即建 Vulkan 设备。否决；但保留为“若软件光栅
  性能不可接受”的候选（须先改 NFR-212 并立 ADR）。
- **Win32 + windows-rs**：资源最优且是系统控件，但需新建 `whcode-gui-win32` 边界 crate
  承载 19 处 `unsafe`，并新开 `unsafe` 例外 ADR（格式同 ADR-015）；主题需
  `LVS_OWNERDRAWFIXED`／`NM_CUSTOMDRAW` 与 DWM 定制。**保留为有条件备选**：当 iced 路线
  连续两轮触发资源预算失败时启动评估，不得直接切换。
- **Tauri／WebView／Electron**：ADR-026 明令禁止，不参与比较。

## 复审触发

1. `iced` 升级导致软件光栅后端被移除、或默认强制 GPU 上下文；
2. 连续两轮验收 RSS > 96 MB 或线程 > 24（即使优化后仍超）；
3. 墨水屏灰阶 > 5%，或三套主题无法达到精确色值；
4. 高 DPI（125%/150%）、输入法或 RTL 出现无法克服的缺陷——此时评估 Win32 备选，
   但仍须新立 `unsafe` 例外 ADR，不得直接引入；
5. 72 小时内存／句柄斜率异常；
6. 用户撤回对 iced 路线的选择（须新 ADR）。
