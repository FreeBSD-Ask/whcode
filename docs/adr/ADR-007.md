# ADR-007：外部工具调用采用"意图记录—执行—结果登记"协议

- **状态**：已批准（M0 批准，2026-10-21；tasks.md T029 / V-007）
- **来源**：任务书 §2（原状态"必须冻结"）、§0.3-8、§4.4 检查点时序
- **责任人**：工具与运行时负责人
- **退出条件**：M8 完成运行时与 SSH 客户端的协议落地，`tests/crash/` 四个注入时点通过（V-105/V-307）；M0 仅有协议原则与客户端原型，不构成恢复行为验收
- **批准依据**：`whcode-domain::RuntimeExecutionStatus` 含 `prepared`/`unknown`；`whcode-ssh/src/proto.rs` 按三段协议执行并登记（`ExecRegistry`）；`tests/crash/` 目前仅有目录与 README，注入用例未实现。

## 决策

外部工具调用一律采用三段协议：**意图记录 → 执行 → 结果登记**。
- 执行前：提交 `prepared` 意图与检查点；
- 启动后：标记 `running`；
- 结束后：记录输出摘要、退出码与副作用凭证，并在**同一事务**登记结果；
- 无法判断是否完成：标记 `unknown`，要求核对、幂等重试或人工决策。

## 理由与约束

文件系统、子进程与 DuckDB **不能**组成单一原子事务，因此系统不得承诺 exactly-once。进程若在
副作用发生后、结果登记前崩溃，恢复逻辑不得宣称操作从未发生，也不得盲目重放有副作用的操作
（R-07）。重复执行缓存仅可用于明确判定为纯函数或显式启用缓存的任务（FR-707）。

## 替代方案

- 盲目重试：可能重复产生副作用（如重复写入、重复提交），被 R-07 明令禁止。
- 宣称 exactly-once：无法证明的语义会在恢复路径上造成状态谎报（§0.3-8）。

## 影响

- 约束 crate：`whcode-tools`、`whcode-runtime`、`whcode-store`（检查点同事务提交）。
- 状态类型：`whcode_domain::RuntimeExecutionStatus`（含 `prepared`/`unknown`）。
- 检查点：`tests/crash/` 四个注入时点；Check 196、Check 207。
