# ADR-010：跨 BSD 可构建与 DuckDB 原生构建分开验收

- **状态**：部分批准（M0 原则批准，2026-10-21；FreeBSD/NetBSD 的 V-002 结论阻塞；OpenBSD/DragonFly 已移出原生安装目标，见 ADR-011）
- **来源**：任务书 §2（原状态"必须冻结"）、§9.1、G-01
- **责任人**：平台矩阵负责人
- **退出条件**：FreeBSD 与 NetBSD 在真实平台完成 DuckDB 原生构建与运行验证（V-002），或形成正式 Go/No-Go 决策并修订平台承诺；在此之前不得以交叉检查结果标记通过
- **批准依据**：`docs/adr/ADR-DB-BUILD.md` 记录的 Windows 实测（rustc 1.99.1 msvc、MSVC 14.44.35207、SDK 10.0.26100.0、引擎 v1.5.6）；`artifacts/deps-windows.txt`；`cargo check --workspace --exclude whcode-store --exclude whcode-bin --exclude whcode-ssh --target x86_64-unknown-freebsd` 与 `--target x86_64-unknown-netbsd` 均通过（代码级检查）；`whcode-store`（`libduckdb-sys`→`ureq`→`aws-lc-sys`）与 `whcode-ssh`（`russh`→`aws-lc-rs`）因需目标 C 工具链无法交叉检查
- **未决条件**：FreeBSD/NetBSD 的原生运行证据（阻塞项）；DuckDB 预编译包在 BSD 的获取/构建路径未定（见 ADR-DB-BUILD 的替代方案）
- **未决项处置（2026-10-23）**：ADR-013 已将 BSD 移出验收范围；两项未决条件转为“平台范围恢复时结清”：① 原生运行证据（V-002）由平台矩阵负责人随首个 BSD 环境取得；② DuckDB 获取/构建路径在恢复前不得以交叉编译或预编译包推断可用（G-01）。当前状态维持“部分批准”，不因交叉检查通过而改变；复审触发：ADR-013 范围恢复、或 DuckDB 对 BSD 的支持状态发生版本级变化。

## 决策

"Rust target 可构建"与"DuckDB 原生依赖可构建并运行"是**两个独立**验收项：Rust target 存在不代表
所有 C/C++ 依赖、SSH、终端、TLS 或运行时 payload 已在该平台通过测试。每个平台的实际数据库构建
与运行验证是 **M0 退出条件**（V-002）。

## 理由与约束

风险登记 R-01 为"高"：DuckDB Rust/native 依赖可能在个别 BSD 版本构建失败；对策为 M0 原生
验证、固定工具链/编译器、记录补丁与上游状态。不得以交叉编译成功代替运行验证（G-01）；DuckDB
原生依赖若在任一硬目标平台无法构建或运行，必须在继续大规模实现前解决或正式调整平台承诺
（§11.1 退出条件、§9.1）。

## 替代方案

- 以交叉编译产物代替原生运行验证：被 G-01/ADR-010 否决。
- 遇到构建失败即换默认后端：被任务书封面与 §9.1 否决（须经 ADR 批准，且须先形成 Go/No-Go 决策）。

## 影响

- 约束 crate：`whcode-store`（DuckDB 依赖引入时点）、`whcode-platform`；CI `ci/platform-matrix/`。
- 验收：V-001、V-002；Check 20—23；research.md TBD-01。

## 修订记录

- **2026-10-24（DuckDB 2.0.0 引擎复审）**：本 ADR 第 7 行的“批准依据”是 M0 在 DuckDB
  `v1.5.6` 下的历史记录；2.0.0 的 Windows 证据见 `ADR-DB-BUILD` 与
  `artifacts/duckdb-2.0-audit-2026-10-24.md`。同时更正依赖链表述：`whcode-store`
  无法对 BSD 交叉检查的原因是缺少目标平台的 libduckdb 原生库（官方无 BSD 预编译包），
  不是 `libduckdb-sys → ureq → aws-lc-sys`；`whcode-ssh` 仍经 `russh → aws-lc-rs`
  需要目标 C 工具链。BSD 结论仍为阻塞/延后，验收范围不变。
