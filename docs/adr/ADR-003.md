# ADR-003：TUI/CUI/Web 只依赖应用服务接口，不直接写数据库

- **状态**：已批准（M0 批准，2026-10-21；tasks.md T029 / V-007）
- **来源**：任务书 §2（原状态"必须冻结"）
- **责任人**：前端边界负责人（TUI/CUI/Web/SSH 适配层）；落地维护：各前端 crate 维护者
- **退出条件**：M5/M6 三端接入后由 `tests/contract/test_layering.rs` 持续守护；新增前端或新增依赖须先通过该契约测试
- **批准依据**：`tests/contract/test_layering.rs` 已实现并在 `cargo test --workspace` 中通过；ADR-005 将该约束扩展至 `whcode-ssh`；`specs/001-whcode-harness/contracts/app-service.md` 规定四端统一语义。

## 决策

TUI、CUI、Web 三个前端只依赖**应用服务接口**（命令／快照／事件），不直接写数据库。

## 理由与约束

避免业务逻辑、权限检查和门禁在不同前端出现分叉。约束：前端 crate 的依赖图中不得出现
`whcode-store`（由 `tests/contract/test_layering.rs` 编码为可执行断言）；能力对等按业务能力
定义（ADR-009）。

## 替代方案

- 各前端直接访问存储：权限与门禁语义必然分叉，且无法保证可审计性。
- 抽象"存储门面"由前端自行持有：仍是前端直连存储，违反本决策。

## 影响

- 约束 crate：`whcode-tui`、`whcode-cui`、`whcode-web`、`whcode-ssh`（经 ADR-005 扩展）。
- 门禁：`plan.md` C-03；宪法原则 II；Check 19。
