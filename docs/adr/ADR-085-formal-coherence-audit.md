# ADR-085：形式化融洽性审计与三阶段充分性计算

- **状态**：已批准（2026-11-17；用户指令：把规则体系视为形式理论 Γ、仓库现状视为模型 M，
  对可判定片段逐条计算 `M ⊨ γ`，反例登记到文件；公理体系与充分性审计接入 WHCode 内部流程，
  执行前证明要求可成立、执行中独立审计、结束再计算一遍）
- **来源**：`docs/analysis/software-engineering-logic-sufficiency.md`（2026-11-17，A1—A9／
  R1—R8／四档可判定性／缺口 G1—G6）；`docs/guides/knowing-before-doing.md`（宪法原则 X）；
  `docs/guides/signal-chain-completeness.md`；ADR-037（CI 唯一验收入口）；ADR-046（复审触发
  绑定命令）；ADR-045（研究不承载承诺）
- **责任人**：过程门禁维护者、产品执行层维护者
- **退出条件**：见 §8（绑定命令与判定规则）

## 1. 问题与边界

规则体系已积累到 363 处规范模态（分析文档 §2 实测），但它们分散在 `AGENTS.md`、`specs/`、
`docs/guides/` 与 ADR 中，**没有可执行载体**。后果有三：

1. **要求、检查点、手段三者不一致时无人计算**：任务写了要做什么（FR）、验收看什么（Check）、
   用什么做（脚本与工具链），三者是否闭合成一组可判定的三元组，此前靠人读。代理执行出错
   多源于此，而不是模型能力不足。
2. **“满足”无法区分层次**：可判定片段（文件存在、编号连续、引用可解析、计数相等）与不可
   判定片段（意图是否正确、设计是否最优）混在同一句“门禁全绿”里，后者被前者冒充。
3. **反例无归处**：审计发现的不一致以文字补正散落在 Check 条目与提交信息中，没有台账、
   没有责任人与退出条件，复发靠记忆。

边界（非目标）：

- 不把自然语言规则整体形式化：只登记可判定片段，不可判定项显式登记，不静默通过；
- 不替代 G0—G5 的人工评审与用户批准；用户仍是意图与发布的唯一批准者（A3、A9）；
- 不做运行时模型检验；只对仓库产物做静态检查；
- 不在本 ADR 内改动既有门禁判据强度；`pre` 阻断只作用于本 ADR 新登记的公理条目。

## 2. 决策

1. **Γ 的载体是声明式公理表**：`specs/001-whcode-harness/coherence/axioms.toml`。每条公理
   登记 `id`、`axiom`（归入 A1—A9 或 M 元公理）、`statement`、`source`（原文位置）、
   `tier`（I／III／IV）、`phase`（pre／mid／end）、`severity`、`evaluator`。
   `evaluator` 三种取值：`direct:<谓词>` 由求值器直接计算；`delegate:<脚本>` 复用既有门禁
   退出码；`registered:<理由>` 为不可判定项，必须写明补偿控制。
2. **求值器唯一**：`.github/scripts/coherence.py` 读公理表，对当前工作区计算 `M ⊨ γ`，
   输出 `artifacts/coherence/run-<phase>-<timestamp>.json` 与摘要。退出码语义：
   `pre` 阶段任一 `severity = "hard"` 的反例即退出 1（阻断开工）；`mid`／`end` 默认退出 0
   （记录），`--strict` 时任一反例退出 1。
3. **三阶段计算**（对应用户要求的三次计算）：
   - `pre`（开工前）：Γ 自身一致性（公理表字段齐全、`source` 锚点可定位、台账合法）＋
     要求可成立性（每条新 FR 有任务与 Check、未勾选任务有认知卡、任务引用的手段路径存在）。
     不通过不得开工；
   - `mid`（实现几轮后）：主路径从公理表正向求值，**独立路径**从产物反向枚举（由 check
     条目、任务块、FR 行反推覆盖与计数）再与主路径逐条对账；两份结果的差异即反例。
     反向路径使用不同算法与不同起点，是单人与 AI 条件下可执行的独立性替代；
   - `end`（收口）：重算全部公理，与 `mid` 报告逐条比对，并校验反例台账；未登记反例在
     `end` 阶段按失败处理，已登记反例必须仍带责任人与退出条件。
4. **反例登记到文件**：`specs/001-whcode-harness/coherence/counterexamples.md`。每条含
   `id`、`axiom`、`evidence`、`owner`、`exit`（退出条件）、`status`。登记不等于通过；
   修复后销号必须指回修复证据。脚本拒绝缺少任一字段的条目，也拒绝当前运行中未登记的
   反例（`pre` 阶段判红，`mid`／`end` 记录并列入报告）。
5. **流程接线**：`AGENTS.md` §3 标准验证链、`software-engineering-process.md` G0／G3／G4
   退出判据与 §6 命令、`platform-verification.yml` 的 `docs-gates` 与代码路径各加一步
   `python .github/scripts/coherence.py --phase pre`。中间与收口两次计算由批次执行者在提交前
   与 G4 前各跑一次，报告路径写入 Check 取证。
6. **产品内建能力**（FR-794／FR-795）：WHCode 自身在任务执行前对（要求、检查点、手段）
   做可判定充分性计算，不通过拒绝执行；执行中按轮次重算、结束时收口重算，报告持久化并
   可查询。语义充分性始终标 `unknown`，由用户确认，不以门禁绿冒充。
   **实施边界（并行会话协议）**：先落 `whcode-domain` 纯求值器与规格、任务、契约；P2.4
   在途文件（`surface.rs`／`api.rs`／`schema.rs` 等）落盘后，本批已补齐 app／store／事件
   接线、Web 只读视图与四端登记（T374、Check 470）。仍未做的：TUI／GUI 报告面板（登记为
   预留）、反例自动进入发现台账（非目标）。

## 3. 正负和解

- **正面**：要求—检查点—手段的三元组在开工前被计算，缺项立即成为反例；审计结论从文字
  变成可复跑的 JSON；不可判定项显式暴露，不再被“门禁全绿”吸收；反例有台账与退出条件，
  复发可定位。
- **负面**：（i）公理表本身成为新的维护对象，新增规则要同步登记；（ii）`source` 锚点靠
  文本匹配，规则改写会让锚点失效并误报；（iii）`mid`／`end` 先记录不阻断，存在“记录了但
  没人修”的窗口；（iv）反向求值路径与主路径共享同一份仓库事实，无法发现两边同时读错的
  事实（例如文件内容本身被误读）；（v）不可判定项登记后容易被当成“已处理”。
- **承担者**：规则修订者承担同步公理表的成本；批次执行者承担三相计算的时延；用户承担
  `pre` 阻断带来的开工延迟。
- **和解理由**：三元组不一致的返工成本高于计算成本，且已有实测反例（2026-11-17 融洽性
  审计发现任务到 Check 映射缺失与工作树／提交树不一致各一例）。`mid`／`end` 先记录、连续
  两个批次无新增反例后再硬化，避免台账时滞把每次提交都判红。负面（iv）由 0 信任与三次
  复查（AGENTS §4.2）承担，不在本 ADR 内解决。

## 5. 可判定判据与撤回条件

| 判据 | 绑定命令 | 不满足时 |
|---|---|---|
| 公理表字段齐全、`source` 锚点可定位 | `python .github/scripts/coherence.py --phase pre` | 红灯，修表或修锚点 |
| 每条新 FR 有任务与 Check | 同上（`direct:fr_closure`） | 红灯，补任务或 Check |
| 未勾选任务有认知卡 | 同上（`direct:card_present`） | 红灯，补卡 |
| 任务引用的手段路径存在 | 同上（`direct:means_exist`） | 红灯，修路径或登记 |
| 反例台账字段齐全且覆盖当前反例 | 同上（`--ledger-check`） | 红灯，登记或销号 |
| 反向路径与主路径逐条一致 | `python .github/scripts/coherence.py --phase mid --independent` | 记录差异；连续两个批次有差异未登记即转红 |
| 三相位报告均存在且可复跑 | 三份 JSON 的摘要行与重跑输出一致 | 记录为缺口，不勾选 |

撤回条件：若连续两个批次 `mid`／`end` 报告与人工审计结论冲突（脚本判绿而人工发现不一致），
或维护公理表的成本超过其发现的反例价值，则撤回本 ADR 的执行层，只保留分析文档与台账。

## 6. 标准与一手文献研读（2026-11-17）

- ISO/IEC/IEEE 29148:2018：单条需求“可验证、无歧义”，需求集“一致、可行”——本 ADR 的
  `COH-A2-*` 与三阶段计算是其在可判定片段上的落点（条款级引用受付费墙限制，标 `[待验证]`）。
- ISO/IEC/IEEE 15026-2:2022：claim → argument → evidence——公理条目的 `statement`、
  `evaluator`、`evidence` 三字段与之同构。
- ISO/IEC/IEEE 42010:2022：视图间 correspondence 必须可核对——`source` 锚点是 Γ 与 M 的
  对应关系登记。
- IEEE 1012-2024：V&V 独立性思想——反向求值路径是单人与 AI 条件下的独立性替代，不宣称
  达到人际独立。
- 详见 `research/standards-alignment/notes/formal-coherence.md`。

## 7. 已知限制

1. **只覆盖可判定片段**：意图正确性、设计优劣、威胁完备、文档语义全同仍不可判定（分析
   文档 §8 第 IV 档），以 `registered:` 条目登记，补偿控制是用户确认与季度抽样，不产生判定。
2. **锚点靠文本匹配**：`source` 中的字符串在规则改写后可能失效；失效即红灯，必须改锚点，
   不得放宽匹配。
3. **`mid`／`end` 默认不阻断**：报告存在但无人修复的窗口由台账责任人与批次收口检查承担，
   连续两个批次无新增反例后才硬化。
4. **独立性有限**：反向路径与主路径共享同一份工作区事实；文件内容本身被误读时两边同错。
   该情形由 0 信任复核与 CI 真实运行覆盖，不在本层解决。
5. **产品覆盖面**：app／store／turn／Web 已接线（T374）；TUI／GUI 报告面板登记为预留，
   反例不自动进入发现台账（非目标）。未完成部分按任务清单登记，不宣称已交付。
6. **不覆盖运行时**：不对会话状态机、工具调用与并发行为做模型检验；那些由测试与 CI 承担。

## 8. 失效条件与复审触发

- **绑定命令**：`python .github/scripts/coherence.py --phase pre` 失败且原因不是规则漂移
  （锚点、公理表字段、台账）⇒ 复审本 ADR §2 的求值语义。
- **绑定命令**：`python .github/scripts/coherence.py --phase mid --independent` 连续两个批次
  报出未登记差异 ⇒ 复审独立性设计与台账纪律（§2 决策 3、4）。
- **绑定命令**：`ls docs/adr | wc -l` 显示新增 ADR 缺“已知限制／失效条件”节
  （`check-adr-limits.py` 红）⇒ 本 ADR 的 ADR 级判据失效，先修 ADR 再谈审计。
- **事件**：规则源新增无法归入 A1—A9 的硬约束，或分析文档 §10 的缺口 G1—G6 被落实 ⇒
  公理表与本文同步复审。
- **事件**：用户判定三阶段计算未改变任何开工或收口决策 ⇒ 按 `knowing-before-doing.md` §7
  的同一口径降级或删除执行层。
