# 核心哲学与工程方法论

**日期**：2026-10-21 | **地位**：项目最高层方法论；具体规范与本文冲突时，按本文的审查方式重新评估该规范 | **强制级**：设计与验收必须留下哲学审查记录

本文不是装饰性宣言。它只有改变设计决策、产物字段与门禁判定时才成立；若只剩口号，
应按 §9 删除或降级。本文也不自称“最佳实践”：它是本项目在当前条件下的**和解**。

## 1. 世界本源是形式主义

本项目以“形式先于可理解性”为方法论前提：任何进入工程视野的事物——代码结构、接口、
数据库 schema、UI、文档、流程、报错——都以某种**形式**出现。形式不是内容的外壳，
而是内容得以被识别、传递与检验的条件。

工程推论：

- 设计任何内容，先问“它是什么形式”，再问“这个形式让什么成为可能、让什么被排除”；
- 形式必须服务于真实矛盾；没有功能的纯粹形式是债务，不是美观；
- 改变功能往往意味着改变形式；只改文案不改形式，通常没有改变行为；
- 形式会固化权力与习惯：谁定义形式，谁就定义了他人必须如何理解系统。

## 2. 任何功能同时都是正面与负面的和解存在

没有免费的功能。每个功能在增加能力的同时，必然增加成本、约束或风险；所谓“好设计”，
只是当前条件下把正面与负面安排到可接受位置的和解。

因此，任何功能提案或 ADR 必须写清：

| 字段 | 要求 |
|---|---|
| 正面 | 获得什么能力、为谁获得、如何验证 |
| 负面 | 增加什么成本（内存/CPU/线程/句柄/复杂度/攻击面/维护负担） |
| 承担者 | 谁在什么时候承担负面（用户、运维、后续开发者、平台） |
| 边界 | 在什么条件下正面不再成立、负面不可接受 |
| 和解 | 为什么当前选择这个平衡，而不是不做或换一种形式 |

反例：只写“提升体验”不写资源代价；只写“安全”不写可用性损失；只写“以后优化”不写当下承担者。

## 3. 形式主义审查与三重时间依据

设计任何内容时，必须回答六个问题；答不出者标 `[待验证]`，不得进入实现：

1. **形式**：它是代码、接口、文档、流程、UI 还是指标？边界在哪里？
2. **矛盾**：它试图解决什么真实矛盾？不做会怎样？谁在痛？
3. **正负**：正面与负面各是什么？负面由谁承担？
4. **过去**：它从什么历史条件产生？此前的形式为何失效？
5. **现在**：当下有什么证据（测试、测量、故障、用户反馈）支持它？
6. **将来**：什么条件下它应被修改、替换或删除？复审触发条件是什么？

只满足“过去有先例”是复古主义；只满足“将来可能需要”是空想主义；只满足“现在能用”
是短视主义。三者必须同时给出依据，并承认依据可能被推翻。

## 4. 物质与意识可以互相转化

在本项目中：

- **物质**：代码、二进制、数据库、测量数据、日志、产物、用户操作；
- **意识**：需求、模型、文档、计划、哲学、报错信息。

两者必须双向转化并可追溯：

1. **物质 → 意识**：观察、测量、故障与代码事实必须写成文档或 ADR，否则不可复现；
2. **意识 → 物质**：文档与设计必须落成代码、测试与产物，否则只是 speculation；
3. **一致性**：文档与磁盘事实不一致时，以可复现命令的结果为准，并修正文档；
4. **不可颠倒**：不能以“文档写了”代替“代码做了”，也不能以“代码能跑”代替“行为被理解”。

## 5. 没有真正的最佳实践，只有当下的和解

“最佳实践”是特定历史条件、团队能力与资源约束下的局部最优；把它当作普遍真理，
就是把它变成了形式主义。

工程规则：

- 引入任何外部实践，必须写明：来源、适用条件、在本项目的证据、失效条件；
- 本项目现行硬约束（零 `unsafe`、Windows 唯一验收、禁用 GNU 工具、极简前端等）都是
  **当前的和解**，不是永恒真理；变更必须走 ADR，而不是以“最佳实践”名义直接推翻；
- 评审时禁止用“业界都这样”作为论据；必须回答“在这里、现在、为什么”；
- 每条硬约束都应有一个复审触发条件（版本升级、平台变化、测量结果反转、用户决策）。

## 6. 0 信任原则

不信任任何报错、设计理念、文档、外部事实，甚至不信任自己过去的结论。0 信任不是
拒绝合作，而是**按风险分配证据门槛**。

| 对象 | 不信任的表现 | 必须做的校验 |
|---|---|---|
| 报错信息 | “工具说失败/成功”不构成结论 | 复现、读原始输出与退出码、换独立工具交叉验证 |
| 设计理念 | “架构上应该如此”不构成证据 | 原型、测试、测量；写明假设与证伪条件 |
| 文档 | 文档可能漂移 | 对照磁盘、命令输出、产物哈希 |
| 外部事实 | 供应商文档、API、平台行为可能变化 | 查一手来源、锁定版本、校验哈希、保留原始引用 |
| 自己的结论 | 过去通过不等于现在成立 | 上下文变化后重新运行门禁与测量 |
| 用户/代理的转述 | 二手总结可能丢失条件 | 回溯原始命令、原始日志与原始需求 |

与既有原则的关系：本原则是“证据优先”的彻底化，不替代“失败显式化”；不确定时仍须
显式标记 `unknown` 或 `[待验证]`，不得用“0 信任”作为拒绝交付的借口。

## 7. 落到 G0—G5 门禁

| 门禁 | 哲学要求 |
|---|---|
| G0 范围 | 范围本身就是和解：写明纳入什么、排除什么、谁承担排除的代价 |
| G1 需求 | 每条需求是假设：写清验证方式与证伪条件，不把愿望写成事实 |
| G2 设计 | 必过形式主义审查与三重时间依据；ADR 记录正负和解与复审触发 |
| G3 实现 | 测试首先用于**证伪**，不是用于证明作者正确；失败路径优先 |
| G4 验收 | 0 信任审计：换角色、换命令、换环境复核，不以单一来源作结论 |
| G5 发布 | 回溯哪些形式已变成空壳；更新复审日期与删除条件 |

## 8. 记录模板

### 8.1 ADR / 设计决策必填字段

```text
形式：        （代码/接口/文档/流程/UI/指标，及其边界）
矛盾：        （不做的后果、受影响者）
正面：        （能力、受益者、验证方式）
负面：        （资源/复杂度/攻击面/维护成本、承担者）
过去依据：    （历史条件、此前形式为何失效）
现在依据：    （测试/测量/故障/反馈，含日期与环境）
将来失效条件：（什么情况下应修改/替换/删除）
0 信任校验：  （独立复现方式、交叉验证工具、原始证据位置）
自由影响：    （退出/导出/离线/默认值可撤销是否受限）
安全和解：    （威胁模型、证据、代价、失效条件）
复审触发：    （版本/平台/指标/用户决策）
```

### 8.2 功能提案的最小哲学卡片

```text
功能：
它是什么形式：
要解决的矛盾：
正面 / 负面 / 承担者：
现在证据：
过去依据：
将来删除条件：
自由影响 / 安全代价：
如果不做，损失是什么：
```

## 9. 反教条条款

1. 本文自身也要通过形式主义审查：它必须改变决策与门禁，否则应删除；
2. 任何原则都不得被用来回避证据、推迟交付或压制反对意见；
3. 当哲学与可复现的测量结果冲突时，以测量结果为准，并通过 ADR 修订哲学；
4. 任何“绝对正确”的表述都必须降级为“当前和解”，并写明复审条件；
5. 0 信任包括对本文的不信任：读者应追问它的适用边界与失效条件。
6. 自由与安全条款同样受反教条约束：不得把 §10 变成新的教条，也不得用它压制证据。

## 10. 自由、洞穴与安全

### 10.1 自由不被定义

本项目不替用户定义善、道德或自由；谁把“自由”“道德”固化为产品目标并要求他人服从，
谁就在反对自由。工程上只能定义可执行的边界，不能定义人的目的：

- 默认值必须可见、可改、可撤销；
- 不得以“为你好”为默认，不得隐藏退出与导出；
- 不同生活方式不得被产品预设为高低等级。

### 10.2 最大的自由是离开

用户随时可以停止使用并带走全部数据。退出成本是自由的敌人：

- 本地优先、单文件数据库、完整导出/备份是自由的技术形式；
- 禁止私有格式锁定、隐藏导出、强制账户、强制联网与暗黑模式；
- 退出路径必须与进入路径同样可用，并进入验收（NFR-218）。

### 10.3 每个人都是山洞

任何模型、仪表盘与文档都只是局部视角；出山洞见到的仍是地球这个更大的山洞。

- 不得宣称“看见全部”或“解释世界”；
- 未知、盲区与不可观测项必须显式标 `unknown`/`[待验证]`；
- 不制造全知幻觉：指标是局部证据，不是世界本身。

### 10.4 证明世界，而非解释或改造

真正的哲学在于证明世界，而非解释世界，更不是改造世界。

- 优先可执行证明：测试、测量、复现命令、差分验证；
- 不用宏大叙事替代证据，不把“改造用户工作流”作为产品目标；
- 工具增强用户判断，不替代用户判断。

### 10.5 异化是与自我的和解

主体的异化不是与外物和解，而是与自我和解。

- 不做排行榜、连胜、羞耻驱动与行为操纵；
- 失败提示指向可执行下一步，不评价用户；
- 用户可以不使用某功能而不损失核心能力。

### 10.6 安全不是最佳实践

所谓“最佳安全实践”作为普遍真理是骗局，过去、现在、未来都一样。安全是特定威胁模型
下的和解，而不是合规标签：

- 每项安全措施必须写：威胁模型、攻击面、证据、代价（可用性/性能/隐私）、失效条件、复审触发；
- 禁止合规表演：不以“行业标准”“检查清单”代替威胁分析与可复现验证；
- 默认拒绝、最小权限、回环监听、`redacted`、凭据不落日志仍是当前和解，不是永恒教条；
  变更走 ADR（NFR-219）。
