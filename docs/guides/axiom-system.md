# 公理体系与充分性审计

**建立**：2026-11-17 | **性质**：规则体系的重构与审计方法，不新增硬边界，不作验收结论
（ADR-037） | **冲突判定**：与 `AGENTS.md`、`specs/`、ADR 冲突时以原文为准

本指南回答三个问题：项目现行规则能否写成一组可判定的公理；当前仓库满足哪些、违反哪些；
一份待办清单何时才算“足以收口”。它是 2026-11-17 两轮审计（`local/coherence-audit-2026-11-17.md`、
`local/axiom-sufficiency-audit-2026-11-17.md`）的方法沉淀；计算脚本作为批次证据保存在 `local/`，
不入库。

---

## 0. 任务认知卡（宪法原则 X）

- **方向**：把 AGENTS、spec、tasks/checklist、guides、ADR 与工具链视为形式理论 Γ，把仓库视为模型 M，
  对可判定片段逐条计算，对不可判定片段显式登记。
- **目标**：给出可引用的公理、推理规则与元定理；给出“门禁通过”与“规则成立”之间的推理边界；
  给出待办集充分性的判定方法。
- **判据**：每条公理有原文锚点；每条判定能落到现有脚本、契约测试或 CI 通道；无法判定的条目写明
  无程序或登记理由；计算比率可逐行复算。
- **非目标**：不宣称对程序语义的形式化验证（Rice 定理边界）；不替代用户批准与 CI 验收；
  不把自然语言规则整体形式化；不因本指南新增平台、安全或资源边界。
- **失效条件**：AGENTS／spec／ADR 的规则文本改写后，本指南的公理表须重跑映射；
  公理条数与粒度是本指南的选择，粒度变化改变比率，不改变“结构层可判定、证据层部分可判定”的结论。

## 1. 语言与本体

| 符号 | 所指 | 事实源 |
|---|---|---|
| `U` | 文件、crate、脚本、工作流、任务 `T`、检查点 `C`、需求 `R`、ADR、commit、CI run、artifact | 仓库与 CI |
| `Γ` | 规则文本的公理化闭包 | AGENTS、spec、checklist、guides、ADR |
| `M` | 审计模型：某时刻的提交树＋工作树＋CI 事实 | `git rev-parse HEAD` 与 `git status` |
| `c` | 断言 `(φ, scope, state, index)` | 证据态见 `evidence-states.md` |
| `D(γ)` | 判定程序：有限时间内给出真／假／无法判定 | 脚本、契约测试、CI job、探针 |

三条限定：

1. `source` 锚点是文本匹配，规则改写会让锚点失效并误报；失效按修锚点处理，不得放宽匹配。
2. `M` 是快照，不是永恒状态。报告必须写明 HEAD 与工作树是否干净，不得把工作树结论冒充提交树结论。
3. `M ⊨ γ` 只表示“程序在当前快照上判为满足”，不表示语义上执行正确；语义充分性恒为 `unknown`。

`scope` 与 `index` 目前不是结构字段，只以自由文本出现。这是本指南判定的两条主要缺口的来源
（A05、A06），也是建议优先补齐的字段。

## 3. 推理规则

- **R1（判定）**：`D(γ)=真` 且 `D` 在其声明域内健全 ⇒ `M ⊨ γ`，只对当前快照与该域成立。
- **R2（Hoare 对应）**：任务写 `{pre} 动作 {post}`；Check 是 `post` 的谓词；完成需
  `post ⇒ 所覆盖 FR`（D02）且 `¬Check ⇒ ¬FR`（D03）。
- **R3（追溯闭合）**：`∀r∈R ∃T,∃C` 只保证存在性，不保证蕴含。
- **R4（降级）**：出现更晚且作用域相容的反证时，旧断言必须降级或改判作用域，不能并存。
- **R5（登记）**：无判定程序时写入缺口登记，含责任人与退出条件；登记不得记为通过。
- **R6（充分）**：待办集 `P` 对义务集 `O` 充分 ⇔ 覆盖 ∧ 相容 ∧ 可行 ∧ 判据充分。
- **R7（外部性）**：CI 未实跑的结论记“未取得”，本地全绿不得替代（ADR-037）。

## 4. 元定理

- **T1（可判定片段）**：文件存在、计数、连续性、引用可解析与有限测试套件可判定；值语义只能建契约；
  结构不变量可程序化。由 G04，体系不能在自身内证明无假阴性，需要外部复算。
- **T2（全绿不蕴含全称）**：判定域窄于断言域时，门禁可以通过而全称断言仍假。
  实例：GUI 线程预算在 CI 运行器与高 DPI 本机给出互斥判定；FreeBSD 通道在两次运行中一绿一红。
- **T3（样本不对称）**：单样本只能证伪全称，不能证明全称。实例：主题循环探针一次为真，
  后续运行四主题为假；“跑绿一次”不构成对间歇崩溃的定位。
- **T4（追溯≠实现）**：三方追溯只判存在性。FR 的验收可以只由“未启用”类 Check 形式覆盖，
  门禁仍报无断链（FR-406）。
- **T5（待办充分性）**：R6 四项须同时成立。2026-11-17 计算中，仓库文档存在性覆盖 17/18，
  但严格充分（载体、责任人、退出条件、判定程序、判据充分）只有 2/18。
- **T6（登记制）**：语义类不可完全程序化，唯一诚实处置是登记＋抽样契约；登记不闭合时，
  门禁的“0 反例”只说明查询范围窄，不说明规则成立。

## 6. 充分性计算方法

对待办集 `P` 与义务集 `O`：

1. **覆盖**：`∀o∈O ∃p∈P`，`o` 在 `p` 的完成效果内；
2. **相容**：`p` 之间无互斥，且不违反当前成立的公理；
3. **可行**：每个 `p` 的前置条件可满足，依赖图无环，阻塞链有退出期限；
4. **判据充分**：承载 `p` 的 Check 通过能推出该义务，而不是只推出“未启用”或“已登记”。

四项分别计算并记录比率。只报“存在性覆盖”会把待办文本的规模误当作收口能力；只报“门禁全绿”
会把结构闭合误当作规则成立。

## 9. 已知限制

1. 只覆盖可判定片段；语义充分性不可判定，只登记并由用户确认。
2. 锚点是文本匹配，规则改写会误报；误报按修锚点处理。
3. 单样本与共享运行器的测量不能给出全称结论；性能与平台结论仍按 ADR-013、ADR-025、ADR-037 判定。
4. 本指南的 45 条是重构，不是原文；原文没有形式语义，重构的完备性本身不可判定。
5. 计算脚本保存在 `local/`，属批次证据，不入库；复算按第 5 节的程序索引执行。
