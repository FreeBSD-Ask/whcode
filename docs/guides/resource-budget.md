# 资源占用达标标准（铁律：不达标禁止落地）

**更新**：2026-10-22 | **依据**：spec.md NFR-201—210 候选预算、AGENTS.md §1.1 资源优先序、
NFR-215 有界容器纪律。D-06 预算未冻结——本文件把候选值**具体化为任务级可执行检查**，
作为落地门禁（不替代 D-06 冻结流程：预算正式冻结仍须跨平台基线与长时数据）。

## 1. 任务级达标标准（铁律）

任何新增/修改的任务代码必须同时满足以下内存与 CPU 检查，**不达标禁止落地**：

### 1.1 内存（RSS / 分配有界）

| # | 检查 | 标准 | 判定方式 |
|---|---|---|---|
| M1 | 测试进程峰值 RSS | ≤ 512 MB/进程 | 测量脚本（`script/measure_resources.py`）：`cargo test` 全套运行时逐进程采样 WorkingSet 峰值 |
| M2 | 组件级分配有界 | 单次操作的集合增长必须有上限（列表/缓存/快照） | 代码审查 + 有界测试（NFR-215 既有纪律：队列/缓冲/缓存/事件通道必须有界） |
| M3 | 长历史会话切换 RSS 增量 | ≤ 10 MB（NFR-203 候选；10 万事件、切换 20 次） | T054 有界加载测试 + 切换视图快照恒定大小（`SWITCH_TAIL_LIMIT=50`） |
| M4 | 挂起/空闲驻留 | 空闲会话卸载后仅保留元数据 + 游标（FR-614） | T131 驻留策略测试 |

### 1.2 CPU（无忙等 / 空闲零占用 / 分位数）

| # | 检查 | 标准 | 判定方式 |
|---|---|---|---|
| C1 | 禁止忙等（busy-wait） | 轮询循环必须带 sleep ≥ 10 ms；不得有自旋空转 | 代码审查（worker.rs 轮询 10ms ✓；TUI 事件循环 250ms 超时轮询 `poll_event` ✓——阻塞轮询 + 超时唤醒，非自旋） |
| C2 | 空闲期 CPU ≈ 0 | 空闲期零重绘（T129 计数器断言）；空闲心跳不触发计算 | T129 redraw_count 零重绘测试 ✓ + 重放证据（100 空闲步零重绘、无待绘制帧零探测） |
| C3 | TUI 空闲 CPU | ≤ 0.5% 单核（NFR-205 候选） | 渲染纪律（脏标记门控，未脏不绘制）+ 最小化探测成本纪律：**无待绘制帧＝零探测**；有负载时探测 5s→60s 指数退避（≈0.5% 单核上界，ADR-021 修订）——重放测试断言探测计数 ✓ |
| C4 | 会话切换响应 | ≤ 200 ms（NFR-207 候选，10 万事件） | T054 有界加载（尾部 50 条恒定）——测量脚本覆盖 |
| C5 | 任务概览查询 | p95 ≤ 50 ms（NFR-208 候选，1 万任务） | T055 `overview-perf-m2.json`（实测 p95 7.6 ms ✓） |
| C6 | 历史单页查询 | p95 ≤ 30 ms（NFR-209 候选） | 分页上限 1000（store 既有门禁） |
| C7 | TUI 帧预算（Check 83） | 帧渲染 p95 ≤ 16 ms（候选，未冻结）；帧成本由终端尺寸界定 | `artifacts/tui-frame-budget.json`（release 实测 p50 250 µs / p95 281 µs，10k 行快照 80×24；限行投影 `render_lines_limited`） |

### 1.3 判定与处置

- **门禁脚本**：`python script/measure_resources.py` 接入验证链（M1/C4 实测）；
- **实测超标**：任务回退重写——先测量定位（NFR-216 流程：测量→定位→建模→设计→
  实现→复测），不得以"后续优化"话术落地；
- **候选值修订**：实测数据支撑下可经 ADR 修订预算（D-06 冻结流程不变）；
- **测量纪律**（§5.2）：记录 OS/硬件/编译类型/工具链/DuckDB 版本/数据规模/采样窗口
  （report JSON 必含）。

## 1bis. 极限规模层（30—60GB 会话库，2026-10-22 修订）

**现实工作负载**：会话库可达 30—60GB（≈4 亿事件 @130B/事件）。测试无法在会话内
写 60GB 磁盘，但极限规模的可验证不变量是——

> **所有查询、翻页、清理、切换操作的内存占用必须与库大小无关（O(1)）**。

访问模式在 1M 事件（≈150MB 库文件）上与 4 亿事件**同构**（B+ 树索引深度仅差 1—2 层），
因此极限测试以 1M 事件夹具验证不变量，外部测量证明测试进程峰值 RSS 有界：

| # | 极限检查 | 标准 | 判定方式 |
|---|---|---|---|
| X1 | 极限夹具 | ≥ 1M 事件单会话（测试内批量写入） | `test_extreme_scale.rs` |
| X2 | 全序翻页 O(1) 内存 | 1000 页 × 1000 行遍历全程**不物化全表**（仅累计计数/求和/相邻比较） | 极限测试断言 + 外部 RSS 测量 |
| X3 | 大表聚合 | `count(*)`/`MAX(seq)` 走索引/元数据，秒级完成 | 极限测试时序断言 |
| X4 | 极限清理 | purge 预览计数 + 执行删除在 1M 行上完成且进程内存有界；**实测 125s @1M 行**（DuckDB MVCC 行删除 + 事务提交成本；删除吞吐候选 ≥ 8k 行/s）——批量/分区删除策略为后续优化候选（NFR-216 流程） | 极限测试（实测断言 ≤ 300s） |
| X5 | 极限切换 | 会话切换返回恒定 50 条尾部 + 游标（不随库大小增长） | 极限测试 |
| X6 | 极限进程内存 | 极限测试进程峰值 RSS ≤ 512 MB（1M 行夹具下；与行数无关的证明） | `script/measure_resources.py` |

**修订记录（2026-10-22）**：初版标准（100k 事件/10k 任务夹具）被用户判定**过于保守，
不符合项目目标**（会话库 30—60GB）——新增本极限层；既有 100k 测试降级为回归层，
极限测试（1M 事件）为落地门禁。

## 2. 静态红线（代码审查即拒绝，无需测量）

1. 无上界的 `Vec`/`HashMap`/`BTreeMap` 累积（导入文件、解码输入、缓存）；
2. 忙等循环（无 sleep 的 `loop` + `try_wait`/`try_recv`）；
3. 帧路径内的 JSON 反序列化或全量历史克隆（T083 结构测试 ✓）；
4. 每会话常驻线程或定时器（NFR-211）；
5. `mem::forget` / `Box::leak` 规避生命周期（clippy `mem_forget = "deny"` ✓）。

## 3. 测量环境记录

- OS：Windows 11 amd64；rustc 1.99.1 msvc；DuckDB 1.5.6（`memory_limit` 192MB）；
- 采样：PowerShell `Get-Process` 100ms 轮询（测量脚本）；CPU 时间为进程累计
  ProcessorTime；
- 测量均在本机（唯一验收平台），跨平台数据未取得——本标准为 Windows 验收门禁，
  不作跨平台承诺（ADR-013 收敛）。
