## 1. 适用范围与边界

- 适用对象：**里程碑级评审**——批次收口、新 ADR 采纳、发布（tag）前结论复核。
  不替代逐提交的 fmt／clippy／test／计数／追溯门禁：**门禁先行，评审收口**。
- 主体分工：可判定部分（计数、校验、扫描、链接图）一律程序化；评审只处理**不可判定部分**
  （取舍是否成立、正负和解是否被回避、证据是否被裁剪）。LLM 只能提交候选与建议，
  不得改 Check 勾选、证据态或任务状态（ADR-046 §2.6）。
- 产出是**发现与处置**，不是分数：本协议不产生任何数值评价（拒绝评分制，
  `docs/guides/evidence-states.md` §4）。

## 2. 三证据域独立与硬上限 3

一次评审的证据来自三个域，**各自独立取证、互不传递结论**：

| 域 | 取证对象 | 典型材料 | 禁止 |
|---|---|---|---|
| 运行域 | 会话与执行链的行为事实 | 事件表导出（`redacted` 切片）、turn／工具执行留痕、CI run 与 artifact | 读原始凭据、未脱敏载荷 |
| 仓库域 | 代码、测试与门禁产物 | `file:line` 级代码阅读、测试输出、门禁脚本输出 | 执行写操作、启动被测进程改变状态 |
| 治理域 | 决策与账本一致性 | ADR／spec／tasks／checklist 交叉比对、缺口登记 | 用“文档写了”代替“代码做了” |

1. 每域先独立完成取证并写下各自发现，之后才允许跨域讨论；
   不得让一个域的结论去筛另一个域的材料。
2. **硬上限 3**：一次评审最多三个证据域、最多三个委托对象（含代理）。
   需要更多视角时拆成多轮，不得本轮加塞第四域。上限的意义是让每域被完整读过，
   而不是被抽样。
3. 任何域“没找到证据”都是有效候选（先按信号链完备原则区分正确的空与错误的空），
   必须进入调和，不得被“其它域都很好”覆盖。

## 3. 调和纪律（先冻结，再支持）

违反任一条即本轮调和无效：

1. **保留全部候选**：三域每条候选都进入调和清单，先不筛。
2. **合并只认四同**：同 target、同观察后果、同 owner、同修复路线，四者全同才合并；
   其余保留为独立发现。
3. **弃选留痕**：不进入最终报告的候选必须写明理由（如“属其它批次”“与某条同四同已合并”）；
   禁止为报告整洁而丢弃合格发现。
4. **先冻结后支持**：发现清单与处置冻结之后，才允许补跑测试、补材料、补排版；
   冻结后不得反向修改发现内容，只能追加处置结果。

## 4. 质量门（八道，逐条可判定）

候选要成为报告中的发现，必须逐条过门；任何一道不过，降级为线索并写明差什么。
线索晋升须重过全部门，不存在降标准晋升。

| 门 | 判定问题 | 典型不过表现 |
|---|---|---|
| 证据资格 | 有 `file:line`、命令输出或 CI artifact 实指吗？ | “我感觉”“理论上” |
| 计数与缺席 | 搜索缺席是否区分了正确的空与错误的空？ | 把“没跑”当“没数据” |
| 理论风险 | 纯理论项是否只登记为线索？ | 把猜想写成结论 |
| 读者价值 | 修什么、谁承担、何时明确吗？ | 泛泛而谈、无人认领 |
| 事实一致 | 计数与结论出自同一证据包、同一窗口吗？ | 跨窗口拼数字 |
| 资产问责 | 引用清单／文档时核实它真的支持结论？ | “有条目”未对原文 |
| 隐私 | 正文不含凭据、会话标识、未脱敏载荷？ | 复制了日志里的密钥材料 |
| 可执行修复 | 修复动作落成命令或代码路径（且该路径已在目标中发现）？ | “建议加强” |

## 5. 发现四要件与处置

```text
target      指向：文件:行、命令、契约条目（可定位）
consequence 观察到的后果：现在的行为与判据的差异（不含推测）
owner       承担者：批次／工作单元（不指名个人，不作羞耻驱动）
fix         修复路线：命令或代码路径；不能立即修的写缺口登记位置
```

处置状态四选一：`fixed`（本次修）／`tracked`（转台账，写明位置）／
`wont-fix`（写明理由与复审条件）／`blocked`（写明阻塞点）。
发现台账结构化（`findings` 表，P2.2）落地前，四要件写在评审记录内，不落散落文档。

## 6. 失效条件与复审触发

1. 调和阶段出现“候选被静默丢弃”（清单查不到弃选理由）→ 本轮评审作废，重做调和；
2. 质量门通过率连续两轮 100% 且零降级 → 抽查是否存在门被跳过（门不是橡皮图章）；
3. 出现“以评审替代门禁”（评审通过而脚本红）→ 修订 §1 边界并回归 AGENTS.md §5；
4. `rg -n "硬上限|三证据域" docs/guides/milestone-review.md` 无命中（两文件口径分叉）→
   立即复审并指定唯一条文源；
5. BH 上游协议变更（`research/better-harness/README.md` 的 §B1—B3 引用路径失效或改名）→
   重读一手来源，判定三域与八门是否仍成立。
