# 设计原则与工程哲学

**日期**： 2026-10-21 | **依据**： Parnas 信息隐藏、SOLID、KISS/YAGNI、关注点分离、契约式设计、
Unix 哲学 | **强制级**： 每条原则必须能在本仓库找到**可执行落点**，否则视为口号

原则只有落到“哪条测试会失败、哪个 ADR 会阻止”才算生效。下表左列是原则，右列是本仓库的强制机制。

## 0. 核心哲学（总纲）

本文件列出的原则与工程约束不是“最佳实践”，而是当前条件下的和解。上位总纲见
`docs/guides/philosophy.md`：形式主义审查、正负和解、三重时间依据、物质—意识循环与
0 信任原则。任何原则若与可复现证据冲突，按总纲的 0 信任流程重新评估，而不是维护原则。

每条原则必须同时写明它的负面与失效条件；只写正面收益的原则视为未完成。

## 1. 信息隐藏（Parnas）

**原则**：模块封装“可能变化的决策”，接口不暴露内部细节。

**落点**：
- `whcode-domain` 是状态/事件/错误/门禁的唯一出处，其他 crate 不得复制枚举（重复即分叉）；
- `whcode-store` 独占 DuckDB 连接与 SQL，前端 crate 依赖图中不得出现它（`test_layering` 强制）；
- `pub` 面最小化：内部辅助函数保持私有，只导出契约需要的类型。

**违反示例**：把 `Connection` 暴露给 `whcode-app` 会让 SQL 细节泄漏到业务层。

## 2. 关注点分离（SoC）

**原则**：渲染、业务编排、持久化、进程控制各自独立。

**落点**：
- crate 分层 domain → app → 服务 → 适配器（`plan.md` §Project Structure）；
- 平台差异只允许出现在 `whcode-platform`，由 `test_layering` 的 10 类模式检测；
- TUI 渲染线程不执行网络 I/O 或阻塞查询（`whcode-tui/src/lib.rs` 文档约束）。

## 3. 单一职责与依赖倒置（SRP/DIP）

**落点**：四个前端（tui/cui/web/ssh）只依赖 `whcode-app` 的命令与快照；应用服务通过 trait
（如 `AuditSink`、`ExecRegistry`）依赖抽象而非实现。

**违反示例**：SSH 会话各自打开数据库写入（ADR-005 明确禁止）。

## 4. KISS / YAGNI

**落点**：
- 单一默认持久化后端（ADR-001）；未经 ADR 不得引入第二个；
- 可选运行时 `default = []`（FR-704）：未启用即不加载、不占端口、不注册工具；
- 不为“未来可能需要”预建抽象：先有基准与用例，再加缓存/分区/物化视图（FR-511）。

**违反示例**：提前引入异步运行时（M0 时 tokio 延后到 M2）；提前把 M1 的 14 表 schema 塞进 M0 冒烟。

## 5. 契约式设计（Design by Contract）

**落点**：
- 错误对象恒四字段 `code/message/retryable/details`（`contracts/cui-cli.md` §3，已有测试）；
- 所有 JSON 输出带 `schema_version`；事件 JSON 带 `schema_version`/`event_id`/`ts`；
- 上下文加载器返回 `items + next_cursor + consumed_budget + truncated_reason`（FR-105/505）；
- 有界队列对关键条目返回背压而非丢弃（`BoundedQueue`）。

**违反示例**：错误对象无 `details` 时省略整键（已修复）。

## 6. 失败显式化（Fail Fast, Fail Loud）

**落点**：
- 不确定的外部副作用标 `unknown`，禁止重放（ADR-007、FR-410）；
- 解析失败保留原文并报错，不静默丢弃（FR-309）；
- 交叉编译不等于运行验证（ADR-010）——未取得证据就写“阻塞”；
- 越界/非法配置在启动期 panic 或返回错误，不在运行期静默裁剪。

**违反示例**：TUI 在管道 stdin 下进入事件循环并永久挂起（已修复，Check 226）。

## 7. 证据优先（Evidence over Assertion）

**落点**：
- 性能数字必须带测量条件与分位数（§5.2）；
- `[待验证]` 项不得以推断关闭（research.md TBD-01—TBD-10）；
- 未复现的断言必须标注“未复现”并保留原始说法（ADR-012 的做法）。

**违反示例**：以“缓冲管理器用满 183.1 MiB”为由把夹具改成 384MB（ADR-012 已证伪）。

## 8. Unix 哲学（小工具、文本流、组合）

**落点**：
- CUI 输出 JSON/JSONL，可管道化（`events export --format jsonl`）；
- 稳定退出码 + `--json` 信封，脚本可直接消费；
- 单一职责的独立 crate，可按需组合。

## 9. 最小惊讶与一致性

**落点**：
- 状态名在代码/数据库/CUI JSON/Web 协议共用一套枚举（§3.1）；
- 事件 `kind` 采用任务书 §8.3 的 PascalCase，不得各端自造；
- 主题色值精确定义（#000000 / #FFFFFF），不出现“近黑”“浅白”这类模糊值。

## 10. 极简与资源纪律（本项目特有）

**落点**：
- 前端无框架、无打包器，JS ≤ 50 KB gzip（ADR-014、FR-618）；
- 最小化/不可见时停止一切 GUI 工作（FR-617）；
- 会话不叠加固定资源开销（FR-614）；
- 渲染只做事件驱动 + 脏标记重绘（FR-613）。

**违反示例**：为“好看”引入动画库或大图背景——与墨水屏/低内存目标直接冲突。

## 11. 原则复核方式

新增模块或重构时，在 PR 描述中回答：

1. 是否破坏既有依赖方向？（`test_layering` 会失败吗）
2. 是否引入了“可能变化的决策”却暴露了细节？
3. 是否为了未来需求而提前抽象？（YAGNI）
4. 失败路径是否显式、可重试语义是否正确？
5. 是否有测量/证据支持这次变更？
6. 这个设计是什么形式？它是否只是形式主义？不做的损失是什么？
7. 正面与负面各是什么？谁承担负面？失效条件是什么？
8. 过去、现在、将来的依据分别是什么？复审触发是什么？

## 12. 形式主义审查记录

新增模块、API、UI 元素、流程步骤或文档结构时，必须按 `docs/guides/philosophy.md` §8.1
填写：形式、矛盾、正面、负面、过去/现在/将来依据、0 信任校验、复审触发。
未填写者不得进入 G2 评审。

## 13. 性能与并发：设计先行

- 多线程/并发禁止原型先行；先有不变量、内存序、进展保证与验证计划（ADR-015）；
- 设计前至少研读 3 篇一手文献，逐篇写适用条件、与本案差异与反例；
- 内存/CPU 优化按“测量→定位→建模→设计→实现→复测→归档”执行；
- 汇编仅作为测量后的例外：独立隔离、安全包装、可回退、差分测试；
- 详见 `docs/guides/performance-and-concurrency.md`。

## 14. 自由、主体性与安全

- 不替用户定义善、道德或自由；默认值可见、可改、可撤销，禁止暗黑模式；
- 退出权是硬约束：完整导出、离线核心能力与退出路径必须与进入路径同样可用；
- 任何仪表盘/模型只提供局部证据；未知与盲区显式标注，不制造全知幻觉；
- 证明优先：测试、测量、复现命令与差分验证高于叙事；
- 不做排行榜、连胜、羞耻驱动与行为操纵，工具增强判断而非替代判断；
- 安全是威胁模型下的和解：写清攻击面、证据、代价与失效条件，禁止以“最佳实践”结项；
- 详见 `docs/guides/philosophy.md` §10（NFR-218/219）。

## 15. 一刻哲学的工程推论

| 规则 | 正面 | 负面/承担者 | 失效条件 | 落点 |
|---|---|---|---|---|
| 不伪造 | 结论可追溯，错误可复现 | 记录成本由作者承担；未知不能伪装成确定 | 出现可复现证据且来源可核验时，更新结论 | NFR-220、AGENTS 1.4 |
| 反进步叙事 | 不以主流与版本号代替证据 | 与“行业趋势”叙事冲突时需解释；作者承担举证成本 | 采用率与正确性被独立测量证明相关时，重新评估 | NFR-221 |
| 反苦难 | 错误信息可操作，维护可持续 | 短期交付变慢；不得用加班补设计缺口 | 用户研究证明某约束确有必要且无更温和替代时 | NFR-222、UI §11 |
| 自反文档 | 读者知道假设与时效 | 文档维护成本上升；过期文档必须下架 | 复审到期或前提变化时，重写或删除 | NFR-222、过程 G1/G2 |
| 和解优先 | 评审产出可执行共识 | 需要更多时间；不能以“和解”压制反对意见 | 分歧涉及安全/自由底线时，不得和解 | 过程 §4.2、PR 清单 |
| 去神圣化 | 以 commit、测量与取舍评价工作 | 不利于个人品牌叙事；作者承担被误解风险 | 证据显示某决策确需不可替代的专门能力时，记录具体能力而非神化个人 | AGENTS 1.4、模块设计 |

**共同失效条件**：若任一条被用作回避证据、压制反对意见或拒绝必要工作的借口，该条即失效，
按 `docs/guides/philosophy.md` §9 反教条条款处理。
