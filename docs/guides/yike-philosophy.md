## 2. 二十九章核心命题与工程翻译

| 章 | 核心命题（摘要） | 工程翻译 |
|---|---|---|
| 一 本体论 | 形式主义是世界的真实存在；人化即形式主义化 | 代码、接口、文档、指标都是形式；不要把它们当作“世界本身” |
| 二 历史认识论 | 一切真历史都是古代史；记忆是当下的重构 | 文档与复盘都是重构；保留多源叙述，不宣称“最终真相” |
| 三 进步史观 | 不存在进步，只有权力再分配 | 采用率、版本号、主流地位不等于正确或进步 |
| 四 循环与否定 | 分离聚合是规律；否定是必然的 | 架构分合、fork、重写都是循环；不要写线性进步史 |
| 五 偶然性 | 没有必然性，只有偶然性 | 决策是具体情境的产物；复盘不得编造“必然会发生” |
| 六 主体性与和解 | 和解优于斗争；与自己和解 | 评审目标是可执行共识，不是胜负；不把分歧道德化 |
| 七 文化 | 文化即形式主义；传统被重构 | 命名、礼仪、社区规范都是可改的形式，不是神圣传统 |
| 八 经济 | 商品是形式主义；劣币驱逐良币 | 市场成功不等于技术正确；不要以流行度优化架构 |
| 九 科学技术 | 科学是形式主义；测量合法性来自程序 | 性能/安全结论必须来自可复现程序与交叉验证 |

## 3. 对 WHCode 的直接约束

只采纳可执行的部分，落到以下规则：

1. **不伪造、未知显式（NFR-220）**：工具、模型与代理不得编造命令结果、文件内容、外部事实或史料；
   未知、失败、不可验证必须标 `unknown`/`[待验证]`；LLM 输出不得作为唯一证据。
2. **反进步叙事与采用率中立（NFR-221）**：不得以主流采用、星数、下载量、社区共识或版本号作为
   正确性/进步证据；技术演进不得写成必然进步史；性能与安全结论须来自可复现程序。
3. **用户友好、反苦难与文档时效（NFR-222）**：错误信息可操作、不责怪用户；不得以 RTFM、
   苦难、加班作为设计或贡献证据；文档与 ADR 必须标注假设、适用范围与复审日期。
4. **测量程序优先**：工具会撒谎，程序不会；基准必须记录环境、参数、分位数与交叉验证。
5. **自反文档**：每份 ADR/指南写明“本文是什么形式、解决什么矛盾、何时失效”。
6. **和解优先**：评审与冲突处理以可执行共识为目标；不把技术分歧上升为道德审判。
7. **去神圣化**：记录具体 commit、测量与取舍；不写“天才/大佬不可替代”的叙事。
8. **退出权**：用户随时可以停止使用并带走数据（NFR-218）；文档提供“从入门到跑路”的路径。

## 4. 明确不采纳的推论

以下推论常见于源文本语境，但**不**进入产品需求：

- 不把“人类文明无希望”用作降低质量、拒绝维护或消极交付的理由；
- 不把“教育不可能”用作不写文档、不做 onboarding 的借口；
- 不把“没有最佳实践”用作跳过证据与验证的理由；
- 不把“苦难不值得提倡”误解为拒绝必要的困难工作；它反对的是把苦难神圣化；
- 不把“一切皆形式主义”用作否认物质约束（内存、CPU、安全、平台）的理由；
- 不把源文本的政治、宗教、历史判断写进软件文案或默认价值观。

## 5. 四版前言的工程含义

| 前言 | 核心 | 工程含义 |
|---|---|---|
| 四版：和解与等待 | 和解取决于时间；替代品是幻觉 | 长期维护优先；不追“下一个大版本”的进步叙事 |

| 初版：局外人与好望角 | 局外人视角；存在即破烂 | 为外部用户与退出者设计；不假装权威 |
