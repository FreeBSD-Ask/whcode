# PR 清单（任务书 §15）

每个 PR 必须逐项核对；未实现事项必须明确标记并写明当前行为，不得依赖隐含默认值。

- [ ] 需求 ID 与实现范围明确。
- [ ] 正向测试与失败路径测试已更新。
- [ ] CUI/API 输出或事件 schema 若有变化，已做版本兼容审查。
- [ ] 三端能力矩阵已更新。
- [ ] 资源、权限、持久化和恢复影响已说明。
- [ ] 新的平台限制或依赖升级已更新兼容矩阵。
- [ ] 未实现事项被明确标记并写明当前行为，不得依赖隐含默认值。
- [ ] 形式主义审查：形式、矛盾、正面/负面/承担者、过去/现在/将来依据已填写（`docs/guides/philosophy.md` §8.1）。
- [ ] 0 信任复核：报错、文档与外部事实有独立复现或交叉验证，不以单一来源作结论。
- [ ] 当前和解：若引用“最佳实践”，已写明适用条件、本项目证据与失效条件。
- [ ] 物质—意识一致：文档、代码、产物与测量结果相互一致；不一致处以可复现事实为准并修正文档。
- [ ] 并发改动附设计档案、不变量/内存序/进展保证与验证计划（ADR-015）。
- [ ] 性能/并发改动附一手文献依据与同夹具前后对比（NFR-216/217）。
- [ ] 汇编改动有独立 ADR、隔离、安全包装、回退与差分测试（ADR-015）。
- [ ] 不伪造：工具/模型输出可追溯，未知显式标 `unknown`/`[待验证]`。
- [ ] 反进步叙事：未以采用率/星数/主流共识替代正确性证据。
- [ ] 用户友好：错误信息可操作、不责怪用户；文档含假设与复审日期。
- [ ] 证据层级：代码/commit/测试优先；AI 总结不作唯一证据。
- [ ] 三次复查：查证→交叉验证→判定；存疑标 `[待验证]`。
- [ ] 可逆性：可逆决策有快速验证；不可逆决策附设计与回退证据。
- [ ] 证据层级：代码/commit/测试优先；AI 总结不作唯一证据。
- [ ] 三次复查：查证→交叉验证→判定；存疑标 `[待验证]`。
- [ ] 可逆性：可逆决策有快速验证；不可逆决策附设计与回退证据。
- [ ] 自由与退出：完整导出、离线核心能力、退出路径可用；无私有格式锁定、强制账户/联网、暗黑模式。
- [ ] 主体性：无排行榜/连胜/羞耻/行为操纵；默认值可见、可改、可撤销。
- [ ] 安全：威胁模型、攻击面、证据、代价与失效条件齐备；不以“最佳实践/合规”替代。

补充约束（宪法与 spec 的对应条款）：

- 门禁类判定必须由程序实施，不得以提示词代替（FR-308、宪法原则 VII）。
- 外部副作用改动必须复核“意图—执行—登记”与 `unknown` 恢复路径（ADR-007、FR-410）。
- 性能相关改动必须附测量条件（OS/硬件/编译类型/工具链/依赖版本/参数/数据规模/采样窗口/脚本）
  并报告分位数（§5.2、NFR-201—210）。
- 证据要求：涉及 `[待验证]` 事项的 PR，必须以实测证据结项，不得以推断结论关闭
  （specs/001-whcode-harness/research.md TBD-01—TBD-10）。
