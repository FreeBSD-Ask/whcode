# 证据态命名与升级判据（Evidence States）

**建立**：2026-11-08 | **依据**：FR-761／ADR-060 项 H；语义来源
`research/better-harness/README.md`（BH `b605532`，`models/agent-work-loop.md` 证据五态与
分数天花板）；本仓落点为 `docs/adr/ADR-046-check-evidence-states.md`、
`.github/scripts/check_counts.py`（枚举校验）、`.github/scripts/traceability.py`（分布统计）。

## 1. 目的与边界

- 本文件只回答一件事：**一条 Check 的证据到什么程度**。它不评价功能质量、不评价实现难度、
  不替代“通过/不通过”判定（后者仍由 checkbox 与门禁脚本实施，ADR-046 §2.6）。
- 态是**登记语义**：写错态会污染统计与复审触发，因此改态权与勾选权同归复核人；
  LLM 只能提交建议，不得自行改态。
- 通过门禁只说明“格式与态级合规”，不说明“证据充分”。把门禁通过当成结论仍是 0 信任失守。

## 2. 七值映射表（可判定）

外部评审体系的五态与三不可判定态，在本仓已有七值枚举（ADR-046 §2.1），命名保持一致，
不新增同义词。判定时只回答表中“判定问题”一列，答“是”才可登记该态。

| 本仓标识 | 外部对应 | 判定问题（只答这一问） | 最低可复现证据 | 不构成证据的例子 |
|---|---|---|---|---|
| `present` | Present | 机制或判据是否已写入清单并有对应产物路径？ | 清单条目＋文件/命令存在 | 计划、口头承诺、“已经设计好” |
| `wired` | Wired | 是否存在可达的验证路径？ | 可执行命令或测试名（能跑，不要求已跑过） | 只有代码符号、无入口、命令跑不通 |
| `exercised` | Exercised | 验证是否真的执行并留痕？ | 命令＋运行结果＋日期（判据含失败路径时失败路径亦须跑过） | 只跑正向路径、断言空过、日志被截断 |
| `outcome-supported` | Outcome-supported | 是否有**可比**的后续结果支持效果声明？ | 远端 CI run 编号或 artifact、长跑记录、同夹具前后对比 | 单次样本、跨环境拼接、静态推断 |
| `missing` | Missing | 判据是否确认未满足或未实施？ | 缺口登记：原因＋复现命令＋阻塞点 | “没空做”“以后再补” |
| `unobserved` | Unobserved | 是否在观察边界外且当前无法判定？ | 边界说明（缺环境/缺凭据/平台不可用）＋复现所需条件 | 用 `unobserved` 规避 `missing` 的追责 |
| `not-applicable` | Not applicable | 是否经检视证明该 Check 不适用于本项目形态？ | 检视依据（为何不适用，指向具体边界或 ADR） | 未检视就标 N/A |

## 3. 升级判据（必须有可复现证据）

1. **证据形态决定态级**，不由叙述决定。Check 行内的取证叙事必须给出命令、CI run 编号或
   artifact 路径之一；只写“已实现”“已测试”不构成升级。
2. **逐条升级**：`present → wired → exercised → outcome-supported` 可以跳级（例如一次 CI
   运行同时证明可达与执行），但每次跳级都要在行内写清证据来源与日期。
3. **失败路径**：判据文本含失败路径（拒绝、超时、回退、越权）时，失败路径未执行不得升
   `exercised`；只跑成功路径属“部分执行”，按 `wired` 登记并写缺口。
4. **可比性**：升 `outcome-supported` 要求同一夹具或同一判据下的可比较结果；换了测量口径、
   换了平台或换了上游版本的“结果更好”不算支持，降回 `exercised` 并注明不可比原因。
5. **降级**：出现下列任一情形，降到实际成立的最高态，并在行内保留降级理由与日期——
   复现失败、CI 转红、判据或门禁口径变更、上游依赖大版本升级、事实与文档不一致。
   降级不删除既有取证叙事（历史不改写，以可复现事实为准）。

## 4. 明确拒绝评分制

- BH 的“分数天花板”表（`Missing/Unobserved/N/A→59`、`Present→74`、`Wired→84`、
  `Exercised→94`、`Outcome-supported→100`）**不采纳**，理由如下：
  1. 把证据形态压成单一数值产生假精度：同一分数掩盖不同 Check 的后果差异；
  2. 分数会诱导“为提分补证据”，把证据登记变成行为操纵，违背主体性原则（AGENTS.md §1.3）；
  3. 本仓门禁只需要“是否达到某态”这一布尔判定，不需要排序或加权。
- 因此：checklist、报告、仪表盘与任何前端界面**不得**展示 Check 分数或“证据分”；
  外部评审若要求分数，只能作为外部映射单独换算，不进入本仓判定与统计。

## 5. 门禁落点

| 门禁 | 作用 | 是否阻断 |
|---|---|---|
| `.github/scripts/check_counts.py` | 态值必须在七值枚举内；`[x]` 的态不得低于 `exercised` | 阻断 |
| `.github/scripts/traceability.py` | 输出态分布，供批次复盘 | 不阻断 |
| 季度抽样（ADR-046 §5.3） | 抽 10 条 `exercised` 人工核对叙事与态是否一致 | 一致性 < 90% 触发退出条件评估 |

## 6. 失效条件与复审触发

- `rg -n "EVIDENCE_STATES" .github/scripts/check_counts.py` 的枚举与本文件 §2 不一致 →
  立即复审（两处必须同源同义）。
- BH 模型升级（`research/better-harness/README.md` 的 `models/agent-work-loop.md` 路径失效
  或态定义改名）→ 重读一手来源，判定七值映射是否仍成立。
- 季度抽样一致性 < 90%，或 `outcome-supported` 占比连续两个批次下降 →
  触发 ADR-046 退出条件评估（退回二值＋日期制须另立 ADR）。
- 若有人提议引入分数或加权排名 → 先立 ADR 并在此写明代价、承担者与失效条件，
  不得以“外部体系如此”直接照搬。
